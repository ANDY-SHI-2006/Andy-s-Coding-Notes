# 5. 综合实战：简易网盘系统

本章把前面四章的知识整合成一个完整项目：基于 TCP 的简易网盘系统。用户注册登录后，可以查看、上传、下载自己网盘目录中的文件。项目用到第 2 章的 socket API、第 3 章的长度前缀协议，以及面向对象的代码组织方式。

## 5.1 项目设计

### 5.1.1 功能需求

**客户端：**

- `reg`：注册，注册成功后服务端为该用户创建一个专属网盘目录
- `login`：登录，之后的网盘操作都要求先登录
- `ls`：查看网盘目录下的文件（可指定一级子目录）
- `upload`：上传本地文件到网盘（已存在则覆盖）
- `download`：从网盘下载文件到本地
- `exit`：退出

**服务端：**

- 支持注册与登录，账号数据保存在 `db/` 目录（每个用户一个 JSON 文件）
- 支持查看、上传、下载，文件保存在 `files/<用户名>/` 目录
- 支持多个客户端同时使用

### 5.1.2 目录结构

```
netdisk/
├── server/                  # 服务端
│   ├── main.py              # 启动入口
│   ├── config/setting.py    # IP、端口、数据目录
│   ├── core/server.py       # socket 监听与连接管理
│   ├── core/handler.py      # 业务逻辑：注册、登录、ls、上传、下载
│   ├── utils/protocol.py    # 通信协议：消息与文件的收发
│   ├── db/                  # 运行时生成：用户账号数据
│   └── files/               # 运行时生成：用户网盘文件
└── client/                  # 客户端
    ├── main.py              # 启动入口
    ├── config/setting.py    # 服务端地址、下载目录
    ├── core/client.py       # 建立连接
    ├── core/handler.py      # 交互菜单与命令解析
    ├── utils/protocol.py    # 与服务端相同的协议实现
    └── downloads/           # 运行时生成：下载的文件
```

`db/` 和 `files/` 由服务端启动时自动创建，`downloads/` 由客户端首次下载时创建，都不需要手动准备。

完整可运行项目：[服务端](../examples/zh/netdisk/server/main.py) · [客户端](../examples/zh/netdisk/client/main.py)（分别在 `server/` 和 `client/` 目录下运行 `python main.py`）

### 5.1.3 通信协议设计

协议直接复用第 3 章的**长度前缀方案**（`struct` 的 `!I` 格式，4 字节网络字节序长度头部 + 循环精确接收），并做两条约定：

1. **控制消息用 JSON**：客户端发送 `{"cmd": "login", "username": "...", "password": "..."}`，服务端回复 `{"ok": true, "msg": "..."}`。相比用空格分隔的字符串，JSON 不怕文件名里带空格，字段含义也一目了然。
2. **文件传输两步走**：以 `upload` 为例，客户端先发 `upload` 命令（JSON），服务端确认目录就绪后回复 `READY`，客户端再发送文件内容（4 字节文件大小 + 分块数据）。

## 5.2 公共协议模块

`utils/protocol.py` 在客户端和服务端中完全相同，是整个项目的地基（完整代码：[utils/protocol.py](../examples/zh/netdisk/server/utils/protocol.py)，客户端的同名文件内容一致）：

```python
# utils/protocol.py
import os
import struct

HEADER_FORMAT = '!I'  # 网络字节序的无符号 4 字节整数（见第 3 章）
HEADER_SIZE = struct.calcsize(HEADER_FORMAT)
CHUNK_SIZE = 4096


def _recv_exactly(sock, size):
    """循环读取，直到读满 size 个字节；对方断开连接时返回 None。"""
    chunks = bytearray()
    while len(chunks) < size:
        chunk = sock.recv(size - len(chunks))
        if not chunk:
            return None
        chunks.extend(chunk)
    return bytes(chunks)


def send_msg(sock, message):
    """发送文本消息，自动加上 4 字节长度头部。"""
    data = message.encode('utf-8')
    sock.sendall(struct.pack(HEADER_FORMAT, len(data)))
    sock.sendall(data)


def recv_msg(sock):
    """接收文本消息；对方断开连接时返回 None。"""
    header = _recv_exactly(sock, HEADER_SIZE)
    if header is None:
        return None
    length = struct.unpack(HEADER_FORMAT, header)[0]
    data = _recv_exactly(sock, length)
    if data is None:
        return None
    return data.decode('utf-8')


def send_file(sock, file_path):
    """先发送 4 字节文件大小，再分块发送文件内容。"""
    size = os.path.getsize(file_path)
    sock.sendall(struct.pack(HEADER_FORMAT, size))
    with open(file_path, 'rb') as f:
        while True:
            chunk = f.read(CHUNK_SIZE)
            if not chunk:
                break
            sock.sendall(chunk)


def recv_file(sock, file_path):
    """先接收 4 字节文件大小，再分块接收并写入 file_path。成功返回 True。"""
    header = _recv_exactly(sock, HEADER_SIZE)
    if header is None:
        return False
    size = struct.unpack(HEADER_FORMAT, header)[0]
    received = 0
    with open(file_path, 'wb') as f:
        while received < size:
            chunk = sock.recv(min(CHUNK_SIZE, size - received))
            if not chunk:
                return False
            f.write(chunk)
            received += len(chunk)
    return True
```

`send_file` / `recv_file` 与消息收发同理：先传 4 字节文件大小，再按 `CHUNK_SIZE` 分块传输——这正是 3.1 节"先读头部、再精确读取正文"模式的应用。

## 5.3 服务端实现

### 5.3.1 监听与多客户端

服务端的主循环很简短：每接受一个连接就交给一个 `ClientHandler`，并为其启动一个线程，这样多个客户端可以同时使用网盘。

```python
# core/server.py
import os
import socket
import threading

from config.setting import DB_DIR, FILES_DIR, IP, PORT
from core.handler import ClientHandler


class Server:
    def __init__(self):
        # 启动时确保数据目录存在
        os.makedirs(DB_DIR, exist_ok=True)
        os.makedirs(FILES_DIR, exist_ok=True)

    def run(self):
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
        sock.bind((IP, PORT))
        sock.listen(5)
        print(f'网盘服务端已启动: {IP}:{PORT}')
        while True:
            conn, addr = sock.accept()
            print(f'新连接: {addr}')
            # 为每个连接启动一个线程，多个客户端可以同时使用网盘
            handler = ClientHandler(conn, addr)
            threading.Thread(target=handler.run, daemon=True).start()
```

完整代码：[core/server.py](../examples/zh/netdisk/server/core/server.py)

> 文件传输是"命令 + 多步接收"的有状态过程，放在 3.3 的 `select` 单线程模型里，一个客户端传输大文件时会卡住其他所有人。每连接一个线程是这里最简单直接的并发方案；更大规模的生产系统会使用线程池或 `asyncio`。

### 5.3.2 命令分发与账号管理

`ClientHandler.run` 循环接收 JSON 命令并分发到对应方法；注册把账号写入 `db/<用户名>.json` 并初始化网盘目录，登录校验密码后记录当前用户：

```python
# core/handler.py（节选）
class ClientHandler:
    """处理单个客户端连接：注册、登录、查看、上传、下载。"""

    def __init__(self, conn, addr):
        self.conn = conn
        self.addr = addr
        self.username = None  # 登录后记录用户名

    def run(self):
        try:
            while True:
                raw = protocol.recv_msg(self.conn)
                if raw is None:
                    break  # 客户端断开连接
                request = json.loads(raw)
                handler = {
                    'reg': self.reg,
                    'login': self.login,
                    'ls': self.ls,
                    'upload': self.upload,
                    'download': self.download,
                }.get(request.get('cmd'))
                if handler is None:
                    self._reply(False, f"未知命令: {request.get('cmd')}")
                    continue
                handler(request)
        finally:
            self.conn.close()

    def reg(self, request):
        username = request['username']
        db_path = self._user_db_path(username)
        if os.path.exists(db_path):
            self._reply(False, f'用户 {username} 已存在')
            return
        with open(db_path, 'w', encoding='utf-8') as f:
            json.dump({'username': username, 'password': request['password']},
                      f, ensure_ascii=False)
        # 注册成功后在 files 下为该用户初始化网盘目录
        os.makedirs(os.path.join(FILES_DIR, username), exist_ok=True)
        self._reply(True, f'{username} 注册成功')
```

完整代码：[core/handler.py](../examples/zh/netdisk/server/core/handler.py)

用字典 `{'reg': self.reg, ...}` 做命令分发，比一长串 `if/elif` 更易扩展：新增命令时只需加一个方法和一行字典条目。

`exit` 不在分发表中：它由客户端本地处理（直接关闭连接并退出），服务端通过 `recv_msg` 返回 `None` 感知断开。

### 5.3.3 上传与下载

上传和下载都是"先确认、后传文件"的两步流程。以上传为例：

```python
# core/handler.py（节选）
    def upload(self, request):
        if not self._check_login():
            return
        filename = os.path.basename(request['filename'])
        target_dir = self._user_files_dir()
        subdir = request.get('subdir')
        if subdir:
            target_dir = os.path.join(target_dir, subdir)
            os.makedirs(target_dir, exist_ok=True)
        self._reply(True, 'READY')  # 目录已准备好，通知客户端开始传文件
        ok = protocol.recv_file(self.conn, os.path.join(target_dir, filename))
        print(f"上传{'成功' if ok else '失败'}: {self.username}/{filename}")
```

## 5.4 客户端实现

客户端负责打印菜单、解析输入、发送命令。每个命令方法都遵循同一模式：校验参数 → `_request` 发 JSON 并收回响应 → 按 `ok` 字段决定后续动作：

```python
# core/handler.py（节选）
    def upload(self, *args):
        if len(args) not in (1, 2):
            print('格式: upload <本地路径> [网盘子目录]')
            return
        local_path = args[0]
        if not os.path.isfile(local_path):
            print('本地文件不存在')
            return
        request = {'cmd': 'upload', 'filename': os.path.basename(local_path)}
        if len(args) == 2:
            request['subdir'] = args[1]
        resp = self._request(request)
        if not resp['ok']:
            print(resp['msg'])
            return
        protocol.send_file(self.sock, local_path)  # 服务端就绪后发送文件内容
        print('上传完成')

    def _request(self, payload):
        """发送一个 JSON 命令，并返回解析后的 JSON 响应。"""
        protocol.send_msg(self.sock, json.dumps(payload, ensure_ascii=False))
        return json.loads(protocol.recv_msg(self.sock))
```

## 5.6 局限

这个实现以教学清晰为目标，距离真实网盘还有不少距离：

- **密码明文存储**：真实系统应存储哈希（如 `hashlib.pbkdf2_hmac`）而非明文。
- **传输无校验**：可以为文件增加 MD5/SHA 校验，确认传输完整。
- **大文件与断点续传**：目前文件大小用 4 字节表示（上限约 4 GB），且中断后只能重传。
- **路径安全**：`ls` 的子目录参数没有防御 `..`，严格场景应校验路径不越出用户目录。
> **小结**：这个项目没有引入任何新知识，它的价值在于组合——socket 连接、长度前缀协议、JSON 消息、文件 IO、面向对象分发，每一部分都来自前面的章节。能独立看懂并复现这个项目，本课程的目标就达到了。
