## 1. 网络架构

### 1.1 C/S：客户端 / 服务器

C/S（Client / Server）架构由本地客户端和服务器共同提供服务。客户端负责界面、部分业务逻辑和本地资源，服务器负责集中式数据与服务。

常见场景包括桌面软件、游戏和银行客户端。它通常可以提供更丰富的本地体验，但需要维护客户端版本，并处理多操作系统兼容性。安全性也不能简单归因于“数据在本地”，实际取决于认证、授权、加密和终端防护等设计。

### 1.2 B/S：浏览器 / 服务器

B/S（Browser / Server）架构通过浏览器访问服务器提供的 Web 应用，通常不需要安装专用客户端。

它便于发布和更新，跨平台成本较低，但会依赖网络、浏览器能力和服务器性能。现代 Web 应用也可以通过缓存、WebAssembly、Service Worker 等技术改善离线能力和交互体验。

### 1.3 C/S 与 B/S 对比

| 维度 | C/S | B/S |
| --- | --- | --- |
| 使用方式 | 通常需要安装客户端 | 通过浏览器访问 |
| 更新方式 | 客户端和服务器可能都要更新 | 主要更新服务器端 |
| 性能 | 可以充分利用本地资源 | 受浏览器、网络和服务器影响 |
| 跨平台 | 需要维护多个客户端 | 浏览器兼容性更重要 |
| 典型场景 | 桌面软件、游戏、专业客户端 | 网站、管理后台、在线服务 |

### 1.4 对 DevOps 的意义

架构类型会影响部署、监控和故障排查方式：

- B/S 应用通常关注 HTTP 响应时间、状态码、TLS、反向代理和负载均衡。
- C/S 应用还要关注客户端版本、连接稳定性、延迟、丢包和升级机制。
- 两类应用都需要身份认证、访问控制、日志、指标和链路追踪。

## 2. 网络通信的三个核心要素

一次网络通信通常可以从三个问题开始分析：

1. **IP 地址**：数据要到哪台主机或网络接口？
2. **端口号**：目标主机上的哪个进程或服务？
3. **协议**：数据按照什么格式和规则交换？

这三个要素常组合为 `IP:port` 和协议，例如 `192.168.1.10:443/TCP`。

### 2.1 IP 地址

IP 地址用于网络层寻址。公网地址需要在互联网范围内具有可路由性，私有地址可以在不同局域网中重复使用；因此“唯一标识设备”需要结合地址作用域理解。

IPv4 使用 32 位地址，通常写成点分十进制，例如 `192.168.1.34`；IPv6 使用 128 位地址，通常写成冒号分隔的十六进制组。

### 2.2 端口号

端口号用于区分同一主机上的网络服务，范围为 `0-65535`。端口的占用通常按协议区分，因此同一端口号可以同时被 TCP 和 UDP 服务使用。

| 范围 | 名称 | 说明 |
| --- | --- | --- |
| `0-1023` | 知名端口 | 常见系统服务使用 |
| `1024-49151` | 注册端口 | 应用或厂商注册使用 |
| `49152-65535` | 动态/私有端口 | 常用作客户端临时端口 |

常见端口包括：`22/SSH`、`53/DNS`、`80/HTTP`、`443/HTTPS`、`3306/MySQL`、`5432/PostgreSQL`、`6379/Redis` 和 `27017/MongoDB`。

### 2.3 协议

协议规定消息格式、交换顺序、错误处理和状态变化。HTTP、DNS、TCP、UDP、IP 都是协议，但它们位于不同的网络层次，承担不同职责。
