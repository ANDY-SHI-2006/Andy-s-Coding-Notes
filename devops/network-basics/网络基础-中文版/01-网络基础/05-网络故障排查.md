# 网络故障排查

[上一篇：HTTP 与 HTTPS](04-HTTP与HTTPS.md) | [返回章节目录](README.md)

## 1. 推荐排查顺序

按“本机配置 → 本地网关 → DNS → 目标端口 → 应用层响应 → 路径与抓包”的顺序逐步缩小范围。每一步都记录命令、时间、目标和结果，避免只凭感觉判断。

## 2. 连通性与路径

```bash
ping -n 4 example.com       # Windows
ping -c 4 example.com       # Linux/macOS
tracert example.com         # Windows
traceroute example.com      # Linux/macOS
```

`ping` 失败不一定代表服务不可用，因为目标可能禁用了 ICMP。路径中的 `*` 也可能只是路由器不返回探测报文。

## 3. DNS 验证

```bash
nslookup example.com
nslookup -type=mx example.com
dig example.com
dig @8.8.8.8 example.com
```

对比本地 DNS、指定 DNS 和不同网络环境的结果，重点观察记录类型、TTL、权威响应和解析地址是否符合预期。

## 4. 端口与连接

```bash
ss -tuln                 # Linux
netstat -ano             # Windows
netstat -an              # macOS/Linux 通用选项之一
lsof -i :8080            # macOS/Linux
```

先确认服务是否监听正确地址和端口，再确认防火墙、安全组、网络策略和负载均衡器是否允许流量通过。

## 5. HTTP 测试

```bash
curl -I https://example.com
curl -v https://example.com
curl -L https://example.com
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name":"alice"}'
```

`curl -v` 可观察 DNS、TCP、TLS、请求头和响应头。排查 HTTPS 时，还要检查证书、SNI、代理和主机名。

## 6. 抓包

Wireshark 适合图形化分析；`tcpdump` 适合服务器现场采集：

```bash
sudo tcpdump -i eth0 port 53
sudo tcpdump -i eth0 -w capture.pcap
```

抓包可能包含密码、令牌和个人数据，只能在获得授权的网络中进行，并使用过滤器限制范围。
