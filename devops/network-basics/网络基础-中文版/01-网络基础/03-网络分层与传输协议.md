## 1. OSI 与 TCP/IP 模型

OSI 是用于教学和分析的七层模型；TCP/IP 是互联网工程中更常用的分层方式。不同教材对层名称略有差异，重点是理解每层的职责和封装关系。

| OSI | TCP/IP 常见映射 | 示例 |
| --- | --- | --- |
| 应用、表示、会话层 | 应用层 | HTTP、DNS、SMTP |
| 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网际层 | IP、ICMP |
| 数据链路、物理层 | 网络接口层 | Ethernet、Wi-Fi |

发送时数据从上层向下层封装，接收时逐层解封装。ARP 通常被放在网络接口层附近讨论，但它跨越网络层和链路层的边界。

| 层次 | 常见设备或组件 | 常见排障线索 |
| --- | --- | --- |
| 应用层 | Web 服务器、反向代理 | 状态码、请求日志、应用延迟 |
| 传输层 | 负载均衡器、防火墙 | 监听端口、握手、重传 |
| 网络层 | 路由器、云路由表 | 地址、路由、丢包、TTL |
| 网络接口层 | 交换机、网卡、无线 AP | 链路状态、VLAN、MAC |

## 2. TCP 与 UDP

| 特性 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 提供确认、重传和有序交付 | 不保证送达、顺序或重传 |
| 开销 | 较高 | 较低 |
| 常见场景 | Web、文件传输、数据库连接 | DNS、实时媒体、部分游戏和物联网 |

UDP 并不限制数据只能很小，应用仍需考虑 MTU、分片和丢包；TCP 也不保证应用层消息边界，应用需要自行定义消息格式。

TCP 还提供流量控制和拥塞控制：接收窗口限制发送方不要超过接收能力，拥塞窗口帮助发送方根据网络状况调整发送速率。它们共同影响吞吐量，但不能消除应用层超时和重试设计的需要。

## 3. TCP 数据与异常状态

TCP 把应用数据视为连续字节流，不保留 `send()` 或 `write()` 的调用边界。应用通常使用长度前缀、分隔符或固定长度协议定义消息边界。

`RST` 表示连接被立即复位，常见原因包括目标端口没有监听、进程主动拒绝或中间设备丢弃状态。优雅关闭后，主动关闭的一方可能进入 `TIME_WAIT`，以确保旧报文不会误影响后续连接。

## 4. TCP 连接建立与关闭

### 4.1 三次握手

1. 客户端发送 `SYN`，声明初始序列号。
2. 服务器返回 `SYN + ACK`，确认客户端并声明自己的序列号。
3. 客户端返回 `ACK`，连接进入可传输状态。

### 4.2 连接关闭

TCP 是全双工协议，两个方向可以独立关闭。常见的优雅关闭过程会交换 `FIN` 和 `ACK`，因此通常称为“四次挥手”；实际报文可能因延迟确认、同时关闭或复位而有所不同。

## 5. 实操题

1. 使用抓包工具观察一次 TCP 三次握手，并标出 `SYN`、`ACK` 和序列号。
2. 启动一个未监听的端口，分别用 `curl` 或 `Test-NetConnection` 观察连接失败表现。
3. 设计一个带长度前缀的消息格式，说明它如何解决 TCP 粘包和拆包问题。
