# 3 视图与请求

在 Django 的 MTV 架构中，**视图**是决定用户看到什么、收到什么的层。视图接收一个 `HttpRequest` 对象，并必须返回一个 `HttpResponse`（或其子类）作为响应。

```
浏览器 -> URL 路由 -> 中间件 -> 视图 -> 模板渲染 -> 中间件 -> 浏览器
```

> **规则：** 视图函数的第一个参数始终是 `HttpRequest` 对象，且必须返回一个 `HttpResponse`（或其子类）。

---

## 3.1 响应类型

Django 提供了多种返回响应的方式。根据你需要返回的内容来选择。

| 类型 | 典型状态码 | 主要参数 | 使用场景 |
|------|---------------|-----------------|-------------|
| `HttpResponse` | 200 | `content, content_type, status, headers` | 返回原始字符串/HTML 或简单文件 |
| `render()` | 200 | `request, template_name, context, content_type, status` | 将模板渲染为 HTML |
| `JsonResponse` | 200 | `data, safe, encoder, status` | 前后端分离、AJAX |
| `redirect()` | 302/301 | `to, *args, permanent=False, **kwargs` | URL 重定向 |

### 3.1.1 HttpResponse

基础类——"一切都能通过它返回"。

| 参数 | 用途 |
|-----------|---------|
| `content`（bytes/str） | 响应体。`str` 在发送前会使用 `charset` 进行编码。 |
| `content_type` | 默认 `"text/html; charset=utf-8"`；返回 JSON 时设为 `'application/json'`。 |
| `status` | HTTP 状态码，默认 `200`。 |
| `headers` | 额外的响应头，以 dict 形式传入（很少用到）。 |

```python
from django.http import HttpResponse

def test(request):
    return HttpResponse("Hello from the view!")
```

### 3.1.2 render

用上下文渲染模板。它是服务端渲染页面最常用的响应类型。

| 参数 | 用途 |
|-----------|---------|
| `request` | 必需——让模板可以访问 `request` 以及上下文处理器变量，例如 `messages`。 |
| `template_name` | 字符串或列表；传列表时，Django 会依次尝试直到某个模板存在。 |
| `context` | 字典；在模板中用 `{{ key }}` 访问。 |
| `content_type` | 默认 `text/html; charset=utf-8`。 |
| `status` | 默认 200；自定义错误页时可设为 404/500。 |

```python
def index(request):
    a, b = 1, 2
    # locals() 返回当前作用域中所有变量的字典，
    # 让你可以把视图变量直接传给模板
    return render(request, 'index.html', locals())
```

### 3.1.3 JsonResponse

继承自 `HttpResponse`，会自动设置 `Content-Type: application/json`。序列化内部使用 `json.dumps`。

| 参数 | 用途 |
|-----------|---------|
| `data` | 要序列化为 JSON 的数据 |
| `safe` | 是否只允许 `dict`（默认 `True`） |

> **注意：** `safe` 默认为 `True`——只允许字典。传入 `list`/`tuple` 需要设置 `safe=False`，否则 Django 会抛出 `TypeError`。

```python
from django.http import JsonResponse

def api_data(request):
    return JsonResponse({'status': 'success', 'message': 'ok'})

def api_list(request):
    return JsonResponse([1, 2, 3], safe=False)   # 列表需要 safe=False
```

### 3.1.4 redirect

返回一个到其他 URL 的 HTTP 重定向。

```python
from django.shortcuts import redirect

# 1. 外部 URL（必须是完整 URL）
return redirect('https://www.example.com')

# 2. 服务器路由
return redirect('app01/index')

# 3. 具名 URL
# path('index/', views.index, name='home')
return redirect('home')
```

## 3.2 访问请求数据

### 3.2.1 HttpRequest 对象

`HttpRequest` 封装了传入请求的全部信息。

| 属性 | 说明 |
|-----------|-------------|
| `request.method` | HTTP 方法（`GET`、`POST`、`PUT`、...） |
| `request.GET` | 查询字符串参数 |
| `request.POST` | 通过 POST 提交的表单数据 |
| `request.META` | 请求头 |
| `request.path` | URL 的路径部分 |
| `request.COOKIES` | 随请求发送的所有 cookie |

```python
def login(request):
    if request.method == 'POST':
        return HttpResponse('This is a POST request with data')
    else:
        return render(request, 'login.html')
```

### 3.2.2 GET 与 POST

| | GET | POST |
|--|-----|------|
| 数据如何传输 | 通过 URL：`?key1=value1&key2=value2` | 通过请求体 |
| 大小 | 受限（URL 长度） | 无实际限制 |
| 安全性 | 数据在 URL 中可见——避免敏感数据 | 更安全；数据不在 URL 中 |
| 典型用途 | 获取/读取数据、渲染页面、链接 | 提交会改变服务器状态的数据 |

常见的 POST 场景：登录、注册、评论、购买、文件上传。

### 3.2.3 get() 与 getlist()

`request.POST` 和 `request.GET` 是 `QueryDict` 对象——一种一个键可以对应多个值的字典。

```python
username = request.POST.get('username')          # 单个值
password = request.POST.get('password')

# 当一个键有多个值时（例如复选框），使用 getlist()
hobby = request.POST.getlist('hobby')            # 返回列表
```

### 3.2.4 多选（复选框）

`register.html`：

```html
<form action="" method="post">
    <p>Username: <input type="text" name="username"></p>
    <p>Password: <input type="password" name="password"></p>
    <p>Gender:
        <input type="radio" name="gender" value="0">Male
        <input type="radio" name="gender" value="1">Female
    </p>
    <p>Hobbies:
        <input type="checkbox" name="hobby" value="0">Singing
        <input type="checkbox" name="hobby" value="1">Football
        <input type="checkbox" name="hobby" value="2">Basketball
    </p>
    <p><input type="submit" value="Register"></p>
</form>
```

`views.py`：

```python
def register(request):
    if request.method == 'GET':
        # GET 专注于获取数据并展示模板
        return render(request, 'register.html')
    else:
        # POST 专注于处理数据（增/改/删）
        username = request.POST.get('username')
        password = request.POST.get('password')
        gender = request.POST.get('gender')
        hobby = request.POST.getlist('hobby')   # 多选 -> 列表
        print(username, password, gender, hobby)
        return HttpResponse('Registration successful')
```

## 3.3 文件上传

### 3.3.1 启用文件上传

默认的 `<form>` 编码只发送纯文本。要上传文件，需设置 `enctype="multipart/form-data"`：

```html
<form action="/app01/addInfo/" method="post" enctype="multipart/form-data">
    <input type="file" name="file">
</form>
```

在服务端，通过 `request.FILES` 访问文件（而不是 `request.POST`）：

```python
upload_file = request.FILES.get('file')
```

### 3.3.2 文件元信息

```python
file_name = upload_file.name             # 原始文件名
content_type = upload_file.content_type  # MIME 类型
file_size = upload_file.size             # 大小（字节）
```

### 3.3.3 小文件与大文件

```python
# 小文件：read() 一次性把所有内容加载到内存
file_content = upload_file.read()
with open(upload_file.name, 'wb') as f:
    f.write(file_content)

# 大文件：chunks() 是一个生成器，逐块读取
data = upload_file.chunks()
with open(upload_file.name, 'wb') as f:
    for chunk in data:
        f.write(chunk)
```

> **注意：** `read()` 会把整个文件加载到内存；`chunks()` 则分块流式读取。处理大文件时始终优先使用 `chunks()`，以免耗尽内存。

### 3.3.4 校验文件类型

```python
head = request.FILES.get('head')
file_name = head.name
file_ext = file_name.split('.')[-1]
if file_ext in ['jpg', 'png', 'gif', 'jpeg', 'webp']:
    data = head.chunks()
    with open(file_name, 'wb') as f:
        for chunk in data:
            f.write(chunk)
else:
    return HttpResponse('Invalid file type')
```

## 3.4 FBV 与 CBV

### 3.4.1 基于函数的视图（FBV）

以普通函数形式编写、按请求方法分支的视图。

```python
def login(request):
    if request.method == 'POST':
        return HttpResponse('Logged in')
    return render(request, 'login.html')
```

### 3.4.2 基于类的视图（CBV）

以类形式编写、把每个 HTTP 方法分发到各自方法的视图。CBV 继承自 Django 内置的视图类（`View`、`TemplateView`、`ListView`、`DetailView`、...）。

在 URLconf 中，唯一的区别是调用 `.as_view()`：

```python
# FBV
path('login/', views.login)
# CBV
path('login/', views.Login.as_view())
```

```python
from django.views import View

# 1. 类名以大写开头
# 2. 必须继承自 View
class Login(View):
    def get(self, request):
        print('Handled GET request')
        return render(request, 'login.html')

    def post(self, request):
        print('Handled POST request')
        return HttpResponse('Logged in')
```

### 3.4.3 如何选择

| FBV | CBV |
|-----|-----|
| 简单、控制流清晰明确 | 更结构化、可读性更好 |
| 按 `request.method` 分支 | 每个 HTTP 动词对应一个方法 |
| 复用较难 | 高度可复用——只需继承类即可 |

> **注意：** CBV 更易复用：如果其他地方需要某个 CBV 的逻辑，只需继承该类即可。

---

## 3.5 最佳实践

| 建议 | 避免 |
|----|-------|
| 对 GET/POST 混合视图按 `request.method` 分支 | 在一个视图中混合读取和写入 |
| 对多值键使用 `getlist()` | 对复选框/多选值使用 `get()` |
| 上传使用 `request.FILES` + `enctype="multipart/form-data"` | 从 `request.POST` 读取文件 |
| 大文件使用 `chunks()` | 大文件使用 `read()` |
| 对可复用的 CRUD 逻辑优先使用 CBV | 为相同模式编写重复的 FBV |

**记忆口诀**
- **视图** = "`request` 进 -> `HttpResponse` 出"；从 `render`/`JsonResponse`/`redirect` 中选择响应；通过 `request.GET/POST/FILES` 读取数据；以 FBV（函数）或 CBV（带 `.as_view()` 的类）来组织。
