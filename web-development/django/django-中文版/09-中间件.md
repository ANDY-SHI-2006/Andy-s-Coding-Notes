# 9 中间件

中间件是一条由钩子组成的管道：请求到达之后、视图执行之前运行一次；视图返回之后、响应到达浏览器之前再运行一次。

```
浏览器
  |
HttpRequest
  |
中间件 (process_request, process_view)
  |
视图函数
  |
HttpResponse
  |
中间件 (process_response)
  |
浏览器
```

中间件的核心作用：

1. 在请求到达视图**之前**执行逻辑（身份校验、权限校验、请求日志）。
2. 在响应到达客户端**之前**执行逻辑（格式包装等）。

---

## 9.1 内置中间件

Django 自带若干默认在 `MIDDLEWARE` 中启用的中间件类：

```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',          # 安全功能：HTTPS、HttpOnly
    'django.contrib.sessions.middleware.SessionMiddleware',   # 会话 / 状态保持
    'django.middleware.common.CommonMiddleware',              # 自动补全末尾斜杠、URL 规范化
    'django.middleware.csrf.CsrfViewMiddleware',              # CSRF 防护
    'django.contrib.auth.middleware.AuthenticationMiddleware',# 认证系统
    'django.contrib.messages.middleware.MessageMiddleware',   # 闪现消息
    'django.middleware.clickjacking.XFrameOptionsMiddleware', # 防止 iframe 嵌入
]
```

---

## 9.2 编写自定义中间件

1. 在应用内创建一个 `my_middleware` 文件夹。
2. 在其中创建一个模块（例如 `my_mid.py`）。
3. 导入并继承 `MiddlewareMixin`，然后定义你的类。
4. 重写钩子方法（例如 `process_request`、`process_response`）。
5. 在 `settings.py` 中注册中间件。

```python
# app01/my_middleware/my_mid.py
from django.utils.deprecation import MiddlewareMixin

class MyMiddleware(MiddlewareMixin):
    pass
```

你可以重写以下五个钩子：

| 钩子 | 重要程度 | 运行时机 |
|------|-----------|--------------|
| `process_request` | 必须掌握 | 视图之前 |
| `process_response` | 必须掌握 | 视图之后 |
| `process_view` | 理解即可 | `process_request` 之后、视图之前 |
| `process_template_response` | 理解即可 | 视图返回模板响应之后 |
| `process_exception` | 理解即可 | 视图抛出异常时 |

## 9.3 process_request 与 process_response

```python
def process_request(self, request):
    """
    参数：
        request：HttpRequest 对象（与 views.py 收到的同一个）
    返回值：
        1. None          -> 继续执行下一个中间件 / 视图
        2. HttpResponse  -> 短路；立即返回该响应
    """
    print('Before the view: pre-processing')


def process_response(self, request, response):
    """
    参数：
        request：HttpRequest 对象
        response：HttpResponse 对象
    返回值：
        HttpResponse 对象
    """
    print('After the view: post-processing', request, response)
    return response
```

> **关键规则：** `process_request` 返回 `None` 时，请求会继续流向视图；返回 `HttpResponse` 时会拦截请求，并直接返回该响应。

### 示例：在 process_request 中做参数校验

```python
def process_request(self, request):
    # 反爬校验：GET 请求必须携带 csrfmiddlewaretoken
    if request.method == 'GET':
        token = request.GET.get('csrfmiddlewaretoken')
        if not token:
            # 直接返回 HttpResponse 进行拦截
            return HttpResponse("403 CSRF Forbidden", status=403)
    # None 表示正常流程，继续执行视图
    return None
```

## 9.4 多个中间件的执行顺序

```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',   # {% csrf_token %}
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
    'app01.my_middleware.my_mid.MyMiddleware1',
    'app01.my_middleware.my_mid.MyMiddleware2',
]
```

- `process_request`：按**从上到下**的顺序依次经过每个中间件。
- `process_response`：按**从下到上**的顺序依次经过每个中间件。

```
request  -> M1.process_request -> M2.process_request -> ... -> view
response <- M1.process_response <- M2.process_response <- ... <- view
```

## 9.5 其他钩子（理解即可）

```python
def process_view(self, request, view_func, view_args, view_kwargs):
    """
    view_func  ：即将执行的视图函数对象
    view_args  ：视图的位置参数
    view_kwargs：视图的关键字参数
    """
    print("Before the view: MyMid1.process_view ran")

def process_template_response(self, request, response):
    print("After template response: MyMid1.process_template_response ran")
    return response

def process_exception(self, request, exception):
    print("After exception: MyMid1.process_exception ran")
    return HttpResponse("An exception occurred")
```

## 9.6 CSRF 防护

CSRF（跨站请求伪造）的工作原理如下：

1. 攻击者搭建一个与真实站点一模一样的**钓鱼网站**。
2. 受害者误以为是真实站点，在钓鱼网站上执行了某个操作（例如转账）。

启用 CSRF 后，只有携带正确 `{% csrf_token %}` 的请求才能通过校验；其他站点即使也在表单中加入了 `{% csrf_token %}`，也无法调用该接口（因为它们的 token 不是服务器生成的）。

```html
<form method="post">
    {% csrf_token %}
    ...
</form>
```

---

## 9.7 最佳实践

| 建议 | 避免 |
|----|-------|
| 在 `process_request` 中返回 `None` 以继续流程 | 除非打算短路，否则返回响应 |
| 保持中间件职责单一（认证、日志、响应头） | 把视图专属的业务逻辑放进中间件 |
| 给每个 POST 表单都加上 `{% csrf_token %}` | 没有充分理由就关闭 CSRF |
| 记住请求自上而下、响应自下而上执行 | 假设两者按相同顺序执行 |

**记忆口诀**
- **中间件** = "请求 → `process_request`（自上而下）→ 视图 → `process_response`（自下而上）→ 响应"；返回 `None` 放行，返回 `HttpResponse` 拦截。
