# 14 操作训练与蓝图

本章先用一个"电影投票 + 评论"的综合案例串联前面学过的模型、视图、模板与 Session 知识，然后引入中大型项目必备的结构化管理工具——蓝图（Blueprint）。

## 14.1 训练用例：电影投票与评论

### 14.1.1 需求模型建立及准备

项目需求：简易版"电影投票 + 评论"应用。项目第一步是确定数据库模型（字段、约束）：

- 电影模型 `Movie`：电影 id、电影名称 name、演员 cast、票数 votes
- 评论模型 `Message`：评论 id、评论内容 content、评论时间 time

开发环境搭建与模型定义：

### 14.1.3 编写视图及模板渲染

首页视图 `index` 同时承担两种职责：GET 请求时查询所有电影和评论并渲染模板；POST 请求时接收表单提交的评论并入库，然后重定向回首页：

```python
@app.route('/', methods=['GET', 'POST'])
def index():
    if request.method == 'GET':
        # 获取所有的电影数据
        movie_all = Movie.query.all()
        # 获取所有的评论数据
        msg = Message.query.all()
        return render_template("vote.html", movie_all=movie_all, msg=msg)
    elif request.method == 'POST':
        # 获取表单提交过来的评论数据
        content = request.form.get('content')
        msg = Message(content=content)
        db.session.add(msg)
        db.session.commit()
        return redirect(url_for('index'))
```

模板 `vote.html`：遍历电影列表展示名称、演员和票数，下方是评论表单和评论列表：

### 14.1.4 防刷票机制（Session）

投票规则：没有投票就不能看到票数，且一个人一天只能投一票。通过 session 完成这一机制：投票时验证是否存在 session 标记，投票成功后加上 session 标记，标记过期时间为 1 天：

```python
# 防止刷票：没有投票就不能看到票数 + 一天只能投一票
# 通过session完成这一机制：在投票时（验证是否存在session标记），投票成功加上session标记，session标记过期时间：1天
@app.route('/vote')
def vote():
    if not session.get('is_vote'):
        # 投票：给谁投票 --> 电影id --> 查询参数传参
        m_id = request.args.get("movie_id")
        # 通过id获取电影信息
        m = Movie.query.get(m_id)
        # 票数累加
        m.votes += 1
        # 提交数据变动
        db.session.add(m)
        db.session.commit()

        # 设置session投票标记
        session.permanent = True
        app.permanent_session_lifetime = timedelta(days=1)

        session["is_vote"] = 'vote'
    return redirect(url_for('index'))
```

要点：

- 给谁投票通过查询参数传参：`/vote?movie_id={{ m.id }}`，视图中用 `request.args.get("movie_id")` 获取。
- `session.permanent = True` 配合 `app.permanent_session_lifetime = timedelta(days=1)`，让 session 标记 1 天后过期，从而实现"一天一票"。
- 模板中用 `{% if session.get('is_vote') %}` 判断是否已投票：未投票的用户看到的是红色提示文字，看不到真实票数。

## 14.2 蓝图（Blueprint）

### 14.2.1 为什么需要蓝图

思考：在中大型项目中通常包含用户模块、权限模块（身份验证、安全校验）、文件管理等。结构化管理后，单个模块内部可能包含：用户模型、用户功能封装工具、用户的视图……此时视图的路由注册就成了问题——当视图函数非常多的时候，路由管理必须遵循"高内聚、低耦合"的编程原则。

Flask 给出的解决方案是蓝图：

```python
from flask import Blueprint
```

### 14.2.2 蓝图的使用步骤

蓝图的实现分三步：先生成蓝图对象，然后通过蓝图对象注册视图函数，最后将蓝图对象汇集注册到 Flask 应用实例对象。

第一步、第二步在独立的模块文件中完成（如 `apps/file.py`）：

```python
from flask import Blueprint

# 1.生成蓝图对象        蓝图名称        当前模块
app_file = Blueprint('app_file', __name__)


# 2.通过蓝图对象注册视图路由
@app_file.route('/file', methods=['GET'])
def file():
    return 'file'
```

第三步在主程序入口中完成：

```python
from flask import Flask
from apps.file import app_file
from apps.index import app_index

app = Flask(__name__,
            template_folder='templates')

# 3.注册将蓝图对象汇集  注册到 flask应用实例对象
app.register_blueprint(app_file)
app.register_blueprint(app_index)
# 通过 flask应用实例对象 中的 register_blueprint方法注册 蓝图对象

if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

注册后打印 `app.url_map`，可以看到蓝图中的路由已经出现在路由表中：

```text
Map([<Rule '/static/<filename>' (GET, OPTIONS, HEAD) -> static>,
 <Rule '/file' (GET, OPTIONS, HEAD) -> app_file.file>])
```

### 14.2.3 url_prefix 与端点 endpoint

注册蓝图时可以传入 `url_prefix`，给蓝图内所有路由统一加上 URL 前缀：

```python
app.register_blueprint(app_file, url_prefix='/af')
```

此时蓝图内部路由 `@app_file.route('/file', methods=['GET'])` 生成的最终路由为 `/af/file`：

```text
<Rule '/af/file' (OPTIONS, HEAD, GET) -> app_file.file>
```

路由信息中的端点 endpoint 为 `app_file.file`，由两部分组成：

- `app_file`：蓝图名称
- `file`：视图端点名称，默认就是视图函数名

### 14.2.4 蓝图注册的内部过程

`@蓝图对象.route` 装饰视图函数时，并没有在应用对象中注册路由——没有改变 `app.url_map`，而是向蓝图实例对象的 `deferred_functions` 列表添加一段路由信息函数：

```text
name = 'app_file'                    # 蓝图名称
deferred_functions = [函数1, 函数2]   # 路由信息函数列表
```

当调用 `应用实例对象.register_blueprint(蓝图对象)` 时：

1. 遍历 `deferred_functions`，取出路由信息函数；
2. 调用路由信息函数，内部通过 `add_url_rule` 结合蓝图提供的 `url_prefix` 和蓝图内部路由，生成最终路由并写入 `app.url_map`。

一个注册多个蓝图的完整入口示例：

```python
from flask import Flask
from apps.index import app_index
from apps.file import app_file
from apps.user import app_user
from apps.users.demo import app_study

app = Flask(__name__,
            template_folder='templates',
            static_folder='static',
            static_url_path='/static')

# 注册---将蓝图对象汇集注册到flask应用实例对象
app.register_blueprint(app_file, url_prefix='/app_file')
app.register_blueprint(app_index)
app.register_blueprint(app_user)
app.register_blueprint(app_study)

if __name__ == '__main__':
    print(app.url_map)
    app.run(debug=True)
```

对应的路由表：

```text
Map([<Rule '/static/<filename>' (HEAD, OPTIONS, GET) -> static>,
<Rule '/app_file/file' (HEAD, OPTIONS, GET) -> app_file.file>,
<Rule '/index' (HEAD, OPTIONS, GET) -> app_index.file>,
<Rule '/user' (HEAD, OPTIONS, GET) -> app_user.file>,
<Rule '/study_static/<filename>' (HEAD, OPTIONS, GET) -> app_study.static>,
<Rule '/study' (HEAD, OPTIONS, GET) -> app_study.file>])
```

### 14.2.5 蓝图的静态资源与模板

蓝图对象也可以指定自己独立的模板目录和静态资源目录：

```python
from flask import Blueprint, render_template

# 生成蓝图对象
app_study = Blueprint('app_study', __name__,
                      template_folder='study_templates',
                      static_folder='study_static',
                      static_url_path='/study_static')
# static_url_path 默认为 /+static_folder值

"""
找模版的顺序---> 主模版目录（应用对象中注册的template_folder）...
"""

@app_study.route('/study', methods=['GET'])
def file():
    return render_template('demo.html')
```

![[ch14-01.png]]

如上图所示，注册后路由表中会同时出现主应用的 `/static/<filename>` 和蓝图的 `/study_static/<filename>` 两条静态资源路由。

注意事项：

- 请求静态资源时会先匹配主路由的静态资源，匹配不到就直接报错 404。
- 如果子路由（蓝图）的静态资源路径与主路由静态资源路径一样，将访问不到子路由的静态资源。

## 14.3 课后作业

### 14.3.1 作业：项目结构拆分

需求：将一个 Flask 项目拆分为独立模块——

- `config.py`：配置文件
- `models.py`：数据库模型（User、Book 一对多）
- `blueprints/`：存放用户、图书两个蓝图
- `templates/`：前端页面
- `app.py`：程序入口，统一注册蓝图、初始化数据库

两张表一对多：用户（User）— 图书（Book）。每个蓝图实现：新增、展示、删除。

项目结构：

```text
flask_split/
├── app.py                 # 程序入口
├── config.py              # 配置项
├── models.py              # 数据库模型
├── blueprints/
│   ├── __init__.py
│   ├── user.py            # 用户蓝图
│   └── book.py            # 图书蓝图
└── templates/
    ├── base.html          # 公共导航模板
    ├── user.html
    └── book.html
```
