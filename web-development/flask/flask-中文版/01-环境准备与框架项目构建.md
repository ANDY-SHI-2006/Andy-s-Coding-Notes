# 1 环境准备与框架项目构建

本章是 Flask 课程的入门章节，主要内容包括：搭建项目虚拟环境、认识 Flask 框架及其与 Django 的区别、创建第一个 Flask 工程、Flask 的初始化参数与资源配置、项目配置的构建与读取，以及 `app.run()` 启动参数。

## 1.1 项目虚拟环境

开发 Python 项目时，不同项目依赖的模块及版本各不相同。为每个项目创建独立的虚拟环境，可以避免依赖冲突。使用 `virtualenv` 配合管理工具 `virtualenvwrapper` 来创建和管理虚拟环境。

安装虚拟环境相关包：

```bash
pip install virtualenv  # 虚拟环境包
# pip install virtualenv -i https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple  # 可使用国内镜像加速

pip install virtualenvwrapper-win  # 管理工具包，Windows 平台
# Linux/Mac ---> pip install virtualenvwrapper
```

安装完成后，需要指定虚拟环境的管理目录：在**系统环境变量**中添加一个变量，变量名必须是 `WORKON_HOME`，值为存放虚拟环境的目录路径。

常用命令：

```bash
# 创建虚拟环境（名称不能是中文，命名规则与 Python 变量名一致）
mkvirtualenv demo  # 创建一个名为 demo 的环境
# mkvirtualenv 环境名称

# 退出虚拟环境
deactivate

# 删除虚拟环境
rmvirtualenv 环境名称
```

> 建议虚拟环境的名称与项目名称保持一致。后续会创建很多项目，不同项目使用的模块不同，环境名与项目名一致便于快速匹配环境。

## 1.2 Flask 简介

### 1.2.1 什么是 Flask

Flask 诞生于 2010 年，是 Armin Ronacher 用 Python 语言基于 Werkzeug 工具箱编写的轻量级 Web 开发框架，又称为"微框架"。

"微"意味着 Flask 只保持核心简单——Flask 本身相当于一个内核，其他几乎所有功能（如邮件扩展 Flask-Mail、用户认证 Flask-Login）都需要通过第三方扩展来实现。Flask 没有默认使用的数据库，可以选择 MySQL，也可以使用 NoSQL。其 WSGI 工具箱采用 Werkzeug（路由模块），模板引擎使用 Jinja2。

Flask 的设计思想是：每个人开发的 Web 应用都不一样，用到的技术点也不一样，如果框架全部事先设计好反而会束缚开发者。因此 Flask 只提供最核心的路由分发，需要什么功能就自己集成进来，给开发者最大的自由性——这也是 Flask 受欢迎的原因之一，它是 Python 众多 Web 框架中最灵活的框架。

Flask 中文版文档：https://flask.net.cn/

### 1.2.2 Flask 与 Django 的对比

Django 和 Flask 都是 Python 的 Web 框架：

- **Django —— 重量级（功能齐全）**：提供一站式解决方案，集成了 MVT（Model-View-Template）和 ORM，以及后台管理（admin）。用一个形象的例子：Django 就像一个精装修的房子，什么家具（功能）都有，直接拎包入住。

![[ch01-01.png]]

Django 提供了：

> - `django-admin`：快速创建项目工程目录
> - `manage.py`：管理项目工程
> - ORM 模型（数据库抽象层）
> - admin 后台管理站点
> - 缓存机制、文件存储系统、用户认证系统

- **Flask —— 轻量级（只有最核心的框架基本模块）**：Flask 的两个主要核心应用是 Werkzeug 和模板引擎 Jinja2。Django 的后台管理、表单、ORM 等都有现成的可以直接使用，而 Flask 都没有提供，需要使用第三方扩展包。Flask 就好比待装修的房子：

## 1.3 创建 Flask 工程

创建 Flask 项目没有命令快捷方式，只需要在项目文件夹下创建一个普通的 py 文件，导入 Flask 类并实例化一个 Flask 应用程序即可。

先安装 Flask 框架：

```bash
pip install flask
```

### 1.3.1 第一个 Flask 程序

```python
from flask import Flask

# 实例化 Flask 应用对象
# 需要传入必须参数：__name__ ---> 当前模块（此文件）的对象数据
app = Flask(__name__)


# 构建函数视图并注册路由
@app.route('/')
def hello_world():
    return "Hello World!"


# 如果 __name__ == '__main__' 代表当前文件
# （不是被其他地方导入，而是代码所处的文件本身被直接运行）
if __name__ == '__main__':
    app.run()
```

### 1.3.2 路由与视图函数

- **路由（Route）**：绑定浏览器访问地址（URL）和后端处理函数。用装饰器 `@app.route("访问路径")` 声明，例如 `@app.route("/index")` 代表浏览器访问 `http://127.0.0.1:5000/index` 时触发对应函数。
- **视图函数（视图）**：被路由装饰器包裹的普通函数就是视图，负责接收请求、处理逻辑、返回内容给浏览器，必须有返回值（字符串、HTML、JSON 等）。

核心区别：路由只管"地址匹配"，规定哪个网址找谁；视图只管"业务处理 + 响应"，干活并返回数据。

### 1.3.3 运行方式与 debug 模式

运行 Flask 项目的两种方式：

- 通过 PyCharm 的运行命令运行 Flask 项目
- 通过 `python app.py` 命令行方式运行

开发阶段应打开 debug 调试模式（代码修改后自动重启、出错可看到错误堆栈）：

```python
if __name__ == '__main__':
    # app.run()
    # debug 运行 --- 开发阶段使用 debug 调试模式
    app.run(debug=True)
```

## 1.4 初始化参数——资源配置

实例化 Flask 对象时，除了必须参数 `import_name`（即传入的 `__name__`），还可以配置静态文件和模板相关的参数：

- `import_name`：导包的目录，Flask 以此作为整个项目的参考根路径，寻找静态文件目录和模板目录
- `static_url_path`：访问静态文件的 url 前缀，默认是 `/static`
- `static_folder`：静态文件目录名，默认 `'static'`
- `template_folder`：模板文件目录名，默认 `'templates'`

实例化 Flask 对象之后，静态文件和模板默认在第一个参数（`__name__`）指定的模块所在的目录下查找：

![[ch01-03.png]]

```python
from flask import Flask

# 实例化 Flask 应用对象
# 需要传入必须参数：__name__ ---> 当前模块（此文件）的对象数据
# import_name：导包的目录 --- 以此作为整个项目的参考根路径
# static_url_path：访问静态文件的 url 前缀
# static_folder：静态资源目录
# template_folder：模板目录
app = Flask(__name__,
            static_url_path='/static',
            static_folder='static',
            template_folder='templates'
            )
```

在 `static` 目录下放一张图片 `01.jpg`，启动服务后就可以通过静态文件路径访问到：`http://127.0.0.1:5000/static/01.jpg`。

配合 `template_folder`，视图函数中可以使用 `render_template` 渲染模板目录下的 HTML 文件：

```python
from flask import Flask, render_template

# 实例化 Flask 应用对象
app = Flask(__name__,
            template_folder='templates'
            )


# 构建函数视图并注册路由
@app.route('/')
def hello_world():
    return render_template('index.html')


# 如果 __name__ == '__main__' 代表当前文件
# （不是被其他地方导入，而是代码所处的文件本身被直接运行）
if __name__ == '__main__':
    # debug 运行 --- 开发阶段使用 debug 调试模式
    app.run(debug=True)
```

## 1.5 配置构建

Django 项目中有一个 `settings.py` 配置文件，但 Flask 中没有，需要自己定义。

> **注意：配置键必须全部大写。**

常见的两种配置方式：

### 1.5.1 从配置文件中读取配置

```python
# 文件类型：.cfg 或 .py，配置文件中只保存配置信息
app.config.from_pyfile('文件名')
```

例如创建一个 `config.py`（或 `config.cfg`）文件保存配置信息（如 `DEBUG = True`）：

![[ch01-04.png]]

```python
from flask import Flask

# 实例化 Flask 应用对象
app = Flask(__name__)

# 读取配置文件，加载配置信息
app.config.from_pyfile('config.py')
```

注意：如果注册多个配置文件，后注册的同名配置会覆盖前面的配置，一般一个工程只使用一个配置文件。

### 1.5.2 从类中读取配置信息

```python
app.config.from_object(类名)
```

Flask 默认运行在线上模式，出错时看不到错误堆栈信息。为了方便调试，开发阶段一般会将调试打开：Django 中默认开启调试 `DEBUG = True`，Flask 中同样只需要在配置中写入 `DEBUG = True` 即可。

```python
from flask import Flask

# 实例化 Flask 应用对象
app = Flask(__name__)

# 读取配置文件，加载配置信息
# app.config.from_pyfile('config.py')


class Config():
    DEBUG = True


# 从类中加载配置
app.config.from_object(Config)


# 构建函数视图并注册路由
@app.route('/')
def hello_world():
    return "Hello World!"


if __name__ == '__main__':
    app.run()
    # debug 运行 --- 开发阶段使用 debug 调试模式
    # app.run(debug=True)
```

## 1.6 读取配置参数

**第一种方式**：在能访问到 `app` 对象的文件中，可直接使用 `app.config.get` 方式获取配置参数。

```python
app.config.get('配置名')
```

**第二种方式**：从 flask 中导入 `current_app`，它在整个 Flask 项目中都可以使用，实际上就是 `app` 对象的一个别名。

```python
current_app.config.get('配置名')
```

完整示例：

```python
from flask import Flask, current_app

# 实例化 Flask 应用对象
app = Flask(__name__)


class Config():
    DEBUG = True
    A = 2
    B = 5


# 从类中加载配置
app.config.from_object(Config)


# 构建函数视图并注册路由
@app.route('/')
def hello_world():
    a = app.config.get('A')                # 方式一：直接通过 app 对象读取
    b = current_app.config.get('B')        # 方式二：通过 current_app 读取
    return str(a + b)


if __name__ == '__main__':
    app.run()
```

启动后访问 `http://127.0.0.1:5000/`，视图返回 `7`（即配置项 A + B 的结果）：

## 1.7 app.run() 参数与源码

`app.run()` 的方法签名（源码）如下：

```python
def run(
    self,
    host: str | None = None,      # 主机
    port: int | None = None,      # 端口
    debug: bool | None = None,    # 调试
    load_dotenv: bool = True,
    **options: t.Any,
) -> None:
```

从源码可以看出，`run` 方法实际上是启动一个 Werkzeug 工具箱提供的简易服务器。常用参数说明：

- `host`：服务器主机地址，默认使用本机地址 `'127.0.0.1'`；假如设置 `'0.0.0.0'`，则可以监听本机所有 IP 地址
- `port`：端口号，默认 `5000`
- `debug`：调试开关，参数是 bool 值，表示是否开启调试，`True` 开启调试，默认 `False`
- `load_dotenv`：控制是否从 `.env` 文件加载环境变量

示例：

```python
from flask import Flask

# 实例化 Flask 应用对象
app = Flask(__name__)


# 构建函数视图并注册路由
@app.route('/')
def hello_world():
    return "Hello World!"


if __name__ == '__main__':
    # debug 运行 --- 开发阶段使用 debug 调试模式
    app.run(debug=True, port=8888, host='0.0.0.0')
    # 启动后输出：
    #  * Running on http://127.0.0.1:8888
    #  * Running on http://<本机IP>:8888
```
