# 9 模板与模型

本章分两部分：前半部分讲解 Jinja2 模板的复用机制——模板继承（extends/block）与模板包含（include），以及模板中可直接使用的 Flask 特殊变量（config、request、session、url_for、get_flashed_messages）；后半部分进入模型（Model）主题，介绍 Flask-SQLAlchemy 的安装、数据库连接的 URI 配置、模型类的定义与数据表的创建，以及一对多关系模型。

## 9.1 模板——继承

当多个页面拥有相同的骨架（头部、导航、底部等）时，可以把公共部分抽取为**父模板（基模板）**，各页面作为**子模板**继承它，只覆盖有差异的部分。

### 9.1.1 extends 继承父模板

子模板第一行使用 `extends` 声明要继承的父模板：

```html
{% extends 'demo/demo.html' %}
{% extends 'user_base.html' %}
```

要点：

- `extends` 指定的模板在 `templates` 目录里查找，可以带子目录路径（如 `demo/demo.html`）；
- 模板目录由创建应用时的 `template_folder` 参数指定，默认为 `templates`。

配套的视图代码：

```python
from flask import Flask, render_template

app = Flask(__name__,
            template_folder='templates')


@app.route('/')
def index():
    return render_template('user_base.html')


@app.route('/user')
def user():
    return render_template('user.html')


if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

### 9.1.2 block 与 super()

父模板用 `{% block 名称 %}...{% endblock %}` 圈出允许子模板覆盖的区域；子模板用同名的 `block` 覆盖对应区域：

```html
{% block 名称 %}
    子内容模版
    {{ super() }}    将block原内容继承进来
{% endblock %}
```

- 子模板中定义同名 `block` 即**覆盖**父模板中该 block 的内容；
- 在子模板的 block 里调用 `{{ super() }}`，可以把父模板该 block 的**原内容继承进来**（在原有内容基础上追加，而不是完全替换）。

父模板 `user_base.html`：

```html
<title>{% block title %} 林晨曦 {% endblock %} · 个人介绍</title>
```

子模板 `user.html`：

```html
{% extends 'user_base.html' %}

{% block title %}
    张三
{% endblock %}

{% block about %}
    <h2>关于你自己的信息</h2>
    {{ super() }}
{% endblock %}
```

渲染结果中，`title` block 被替换为「张三」，`about` block 则在父模板原有内容前追加了 `<h2>` 标题。

## 9.2 模板——包含

`include` 把另一个模板的内容**原样引入到当前位置**，适合复用页头、页脚、卡片等局部片段：

```html
{% include 'body/header.html' %}
```

- `include` 引入指定的模板到该位置——是**当前模板包含** include 指定的模板（与 extends 的继承方向相反）；
- 加上 `ignore missing` 后，被引入的模板不存在时不报错、直接忽略。

示例：

```html
<body>
  <div class="profile-card">

      {% include 'body/header.html' %}

      {% include 'body/about.html' %}

      {% include 'body/contact.html' %}

      {% include 'body/contact123.html' ignore missing %}
  </div>
</body>
```

其中 `contact123.html` 不存在，但因为加了 `ignore missing`，页面照常渲染。

## 9.3 模板——Flask 特殊变量

Flask 向模板上下文默认注入了一批特殊变量和方法，无需视图函数显式传参即可在模板中直接使用：

- `config` —— Flask 中的 config 对象，即 `app.config`；
- `request` —— 当前请求的请求对象；
- `session` —— 当前请求的 session 对象；
- `url_for` 方法 —— 反解析，通过 endpoint 端点（与视图函数名字一致）生成 URL；
- `get_flashed_messages` 方法 —— 消息队列获取方法；在视图中可以通过 `flash()` 函数向消息队列传入数据。

典型用法示例（模板中直接读取配置项、请求信息并做 URL 反解析）：

```html
<h2>{{ config.WEB_TITLE }}</h2>
<p>请求路径：{{ request.path }}</p>
<p>请求方式：{{ request.method }}</p>
<a href="{{ url_for('admin') }}" class="btn">进入管理员后台</a>
```

### 9.3.1 flash 消息队列

`flash()` 用于在视图中向消息队列放入一次性消息，模板中通过 `get_flashed_messages()` 取出展示（常用于「操作成功/失败」提示）：

- 视图中使用 `flash()` 前需要 `from flask import flash`；
- **注意配置 SECRET_KEY**：`app.config['SECRET_KEY']`，因为 flash 消息队列基于 session 机制。

```python
from flask import Flask, render_template, flash

app = Flask(__name__,
            template_folder='templates')
app.config['SECRET_KEY'] = 'qwjehfgbiodsvwidhr93fu5u43i9hg9uerhw'

# flash消息队列基于session机制 ---》 需要配置SECRET_KEY


@app.route('/')
def index():
    flash('python1')
    flash('python2')
    flash('python3')

    return render_template('user.html')


if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

多次调用 `flash()` 会按顺序放入多条消息，模板中的 `get_flashed_messages()` 一次性取出全部消息（取出后即从队列中移除）。

## 9.5 设置与连接

### 9.5.1 URI、URL 与 URN

- **URI（统一资源标识符）**：用于标识某一互联网资源名称的字符串。它可以是一个地址，也可以是一个纯标识符，不一定包含访问方式。
- **URL（统一资源定位符）**：URI 的一种特殊形式，不仅标识资源，还提供了获取该资源的具体位置和访问方法。
- **URN（统一资源名称）**：另一种 URI，用于唯一标识资源，但不提供访问方式——它像"身份证号"，能唯一标识对象，但不告诉你如何找到它。

三者的关系：

- 所有 URL 都是 URI，但并非所有 URI 都是 URL；
- URI 关注"谁"，URL 关注"谁 + 在哪里 + 怎么找"；
- URI 是资源的统一标识方式，包含 URL 和 URN 两大类；URL 是 URI 的子集，必须包含访问协议和路径。

示例：

- URI：`mailto:help@example.com`（标识邮箱地址）
- URL：`https://example.com/index.html`（标识并定位网页）
- URN：`urn:isbn:0451450523`（标识书籍 ISBN）

### 9.5.2 常用数据库的连接 URI

| 数据库 | URI |
| --- | --- |
| MySQL | `mysql://username:password@hostname/database` |
| Postgresql | `postgresql://username:password@hostname/database` |
| SQLite (Unix) | `sqlite://python/data/database` |
| SQLite (Windows) | `sqlite://c:/db/data/database` |
| Oracle | `oracle://scott:tiger@127.0.0.1:1521/sidname` |

字段说明：

- `username`：登录数据库的用户名
- `password`：登录数据库的密码
- `hostname`：服务器主机 ip，可以是本地主机（localhost）也可以是远程服务器
- `database`：表示要使用的数据库

### 9.5.3 连接配置步骤

连接数据库的完整步骤（以 MySQL 为例）：

1. 确认连接的目标数据库存在——不存在则先创建：`create database demo default charset utf8;`
2. 导包：`from flask_sqlalchemy import SQLAlchemy`
3. 设置连接配置 `SQLALCHEMY_DATABASE_URI`，格式为 `'数据库服务://用户名:密码@数据库host:数据库端口/数据库名称'`
4. 创建数据库对象 `db = SQLAlchemy(app)`

完整代码：

```python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__,
            template_folder='templates')

# 'sqlite:///test.db'
app.config['SQLALCHEMY_DATABASE_URI'] = 'mysql://root:qwe123@127.0.0.1:3306/demo'

# 4.创建数据库对象
db = SQLAlchemy(app)  # SQLAlchemy实例关联flask应用对象，同时加载配置数据
ctx = app.app_context()  # 获取flask应用上下文
ctx.push()  # 将应用上下文推入栈中（激活上下文）


@app.route('/')
def index():
    return 'Hello World!'


if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

### 9.5.4 Flask-SQLAlchemy 常用配置参数

| 配置参数名 | 参数解释 |
| --- | --- |
| SQLALCHEMY_NATIVE_UNICODE | 可以用于显式地禁用支持原生的 unicode。这是某些数据库适配器必须的（像在 Ubuntu 某些版本上的 PostgreSQL），当使用不合适的指定无编码的数据库默认值时。 |
| SQLALCHEMY_POOL_SIZE | 数据库连接池的大小。默认是数据库引擎的默认值（通常是 5）。 |
| SQLALCHEMY_POOL_TIMEOUT | 指定数据库连接池的超时时间。默认是 10。 |
| SQLALCHEMY_POOL_RECYCLE | 自动回收连接的秒数。这对 MySQL 是必须的，默认情况下 MySQL 会自动移除闲置 8 小时或者以上的连接。需要注意地是如果使用 MySQL 的话，Flask-SQLAlchemy 会自动地设置这个值为 2 小时。 |
| SQLALCHEMY_MAX_OVERFLOW | 控制在连接池达到最大值后可以创建的连接数。当这些额外的连接回收到连接池后将会被断开和抛弃。 |
| SQLALCHEMY_TRACK_MODIFICATIONS | 如果设置成 True（默认情况），Flask-SQLAlchemy 将会追踪对象的修改并且发送信号。这需要额外的内存，如果不必要的可以禁用它。 |
| SQLALCHEMY_COMMIT_ON_TEARDOWN | 每次请求结束后会自动提交数据库中的改动。 |
| SQLALCHEMY_DATABASE_URI | 用于连接数据库的核心 URI，指定数据库类型、账号、密码、地址、端口、库名等基础连接信息，是 Flask-SQLAlchemy 的必填基础配置。 |
| SQLALCHEMY_BINDS | 用于绑定多个数据库，支持在一个 Flask 应用中同时连接和操作多个不同的数据库，适配多库业务场景。 |
| SQLALCHEMY_ECHO | 控制是否打印 SQLAlchemy 执行的 SQL 语句，设置为 True 时会在控制台输出所有执行的 SQL，方便开发调试，生产环境建议关闭。 |
| SQLALCHEMY_ENGINE_OPTIONS | 用于传递给 SQLAlchemy 引擎的额外选项，可配置引擎级别的高级参数，比如连接池的补充配置、数据库驱动的特殊适配参数等。 |
| SQLALCHEMY_ISOLATION_LEVEL | 设置数据库事务的隔离级别，可根据业务需求配置读未提交、读已提交、可重复读、串行化等隔离级别，控制事务的并发访问行为。 |
| SQLALCHEMY_POOL_PRE_PING | 控制是否在获取数据库连接前先发送 ping 请求检查连接有效性，设置为 True 可避免拿到已失效的连接，提升数据库连接的稳定性。 |
| SQLALCHEMY_SESSION_OPTIONS | 用于传递给 SQLAlchemy 会话的额外选项，可配置会话级别的参数，比如事务的自动刷新规则、查询的默认执行行为等。 |

## 9.6 定义模型与创建数据表

建立一张表，就是建立一个**模型类**——类继承 `db.Model`（ORM 实例对象），类属性对应表的字段，通过 `db.Column()` 构建字段的数据类型与限制条件：

```python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config['SQLALCHEMY_DATABASE_URI'] = 'mysql://root:123456@127.0.0.1:3306/test0616'

# 创建数据库对象
db = SQLAlchemy(app)  # SQLAlchemy实例关联flask应用对象，同时加载配置数据
ctx = app.app_context()  # 获取flask应用上下文
ctx.push()  # 将应用上下文推入栈中（激活上下文）


# 建立一张表---》建立一个模型类 ---》类
class User(db.Model):  # 继承db对象（orm实例对象）
    # 建立主键（唯一，自增长）
    # db.Column():构建字段数据类型，限制条件
    id = db.Column(db.Integer, primary_key=True)

    # 用户名---》字符串20字节   唯一  非空
    username = db.Column(db.String(20), unique=True, nullable=False)

    # 年龄 ---》 整数  默认值：18
    age = db.Column(db.Integer, default=18)


@app.route('/', methods=['GET', 'POST'])
def index():
    return 'index'


if __name__ == '__main__':
    print(app.url_map)
    db.create_all()  # 建立所有的表
    app.run(debug=True)
```

- `db.create_all()`：根据所有模型类建立对应的表；
- `db.drop_all()`：根据模型删除所有的表。

运行后在 MySQL 中验证（`show create table` 可以看到主键、唯一索引等约束已生效）：

```shell

mysql> show tables;
```

### 9.6.2 SQLAlchemy 常用约束条件

| 约束名 | 核心说明 | SQLAlchemy 代码示例 | 补充说明 / 数据库效果 |
| --- | --- | --- | --- |
| primary_key | 主键约束，唯一标识表中每一行数据，不可重复、不可为空 | `id = db.Column(db.Integer, primary_key=True)` | 主键列默认会自动创建主键索引，是表的必备核心字段，通常与自增约束配合使用 |
| unique | 唯一约束，该列所有值不可重复，仅允许存在 1 个 NULL 值 | `username = db.Column(db.String(20), unique=True)` | 适用于用户名、手机号、身份证号等不能重复的业务字段，会自动创建唯一索引 |
| index | 普通索引约束，为该列创建索引，大幅提升查询效率 | `phone = db.Column(db.String(11), index=True)` | 经常作为查询条件、排序条件的列建议添加索引，比如商品分类 ID、用户手机号等 |
| nullable | 空值约束，控制该列是否允许存储空值 | 不允许为空：`name = db.Column(db.String(50), nullable=False)`；允许为空：`remark = db.Column(db.Text, nullable=True)` | 业务必填项必须设为 `False`，非必填项可设为 `True`，该约束默认值为 `True` |
| default | Python 级默认值，插入数据时若不指定该列，自动使用设置的默认值 | 固定值：`status = db.Column(db.SmallInteger, default=1)`；动态值：`create_time = db.Column(db.DateTime, default=datetime.now)` | 动态值传入函数时**不要加 `()`**，否则会在模型加载时就执行，仅适用于 Python 代码操作的场景 |
| autoincrement | 自增约束，整数列自动按规则递增，通常与主键配合 | `id = db.Column(db.Integer, primary_key=True, autoincrement=True)` | MySQL 的 INT 主键默认会开启自增，显式声明更清晰，适用于 ID、序号等需要自动递增的字段 |
| foreign_key | 外键约束，建立两张表的关联关系，保证数据一致性 | `user_id = db.Column(db.Integer, db.ForeignKey('user.id'), nullable=False)` | 格式为 `db.ForeignKey('表名.列名')`，通常与 `relationship` 配合实现 ORM 关联查询，是多表关联的核心约束 |
| server_default | 数据库级默认值，在数据库层面设置默认值，与代码语言无关 | `update_time = db.Column(db.DateTime, server_default=db.func.now())` | 通过 `db.func` 调用数据库原生函数（如 `now()`、`current_timestamp`），默认值由数据库自己维护，跨语言操作也能生效 |
| onupdate | 更新自动赋值约束，数据行更新时自动给该列刷新值 | `update_time = db.Column(db.DateTime, onupdate=datetime.now, default=datetime.now)` | 每次更新数据时，该列会自动刷新为当前时间，无需手动赋值，非常适合做「数据最后更新时间」字段 |
| comment | 字段注释约束，给列添加业务注释，同步到数据库表结构 | `status = db.Column(db.SmallInteger, default=1, comment='用户状态：1-正常，0-禁用')` | 注释会直接写入数据库的表结构，大幅提升后续维护的可读性，是规范开发的必备约束 |
| CheckConstraint | 检查约束，自定义校验规则，保证列的值符合指定条件 | `age = db.Column(db.SmallInteger, db.CheckConstraint('age >= 0 AND age <= 150'))` | 可限制数值范围、字符串格式等，MySQL 8.0+ 原生支持检查约束，能从数据库层面拦截非法数据 |
| UniqueConstraint | 联合唯一约束，多个列组合起来不可重复 | 在模型类中添加：`__table_args__ = (db.UniqueConstraint('user_id', 'goods_id', name='uk_user_goods'),)` | 适用于多字段联合去重的场景，比如用户收藏表，同一个用户不能收藏同一个商品两次，会自动创建联合唯一索引 |

## 9.7 关系模型——一对多

一对多关系的建模思路：

- 一的一方是**主表**（father），多的一方是**子表**（son）；
- **外键建在子表上**（son），外键关联的是主表的主键；
- ORM 操作数据库时：数据库中的一行数据对应一个数据对象（属性就是字段）；
- ORM 查询一对多时：son 数据通过 `father_id` 找到 father 数据；从 father 反查 son 数据，需要在主表上构建一个**关系反查字段**——该字段不会在数据库里存在，只在 Python ORM 操作中使用。

```python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config['SQLALCHEMY_DATABASE_URI'] = 'mysql://root:123456@127.0.0.1:3306/test0616'

# 创建数据库对象
db = SQLAlchemy(app)  # SQLAlchemy实例关联flask应用对象，同时加载配置数据
ctx = app.app_context()  # 获取flask应用上下文
ctx.push()  # 将应用上下文推入栈中（激活上下文）


class Father(db.Model):
    # 自定义表名称
    __tablename__ = 'fathertable'

    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(50), nullable=False)


class Son(db.Model):
    __tablename__ = 'sontable'

    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(50), nullable=False)

    # 外键字段 ---》db.ForeignKey 构建外键关联 ---》主表的主键
    # --->father.id ---> father是表的名称
    father_id = db.Column(db.Integer, db.ForeignKey('fathertable.id'))


@app.route('/', methods=['GET', 'POST'])
def index():
    return 'index'


if __name__ == '__main__':
    print(app.url_map)
    db.create_all()  # 建立所有的表

    # db.drop_all()  # 删除所有的表 ---根据模型去删
    app.run(debug=True)
```

要点：

- 模型类默认以类名的小写作为表名，可通过 `__tablename__` 自定义表名称；
- `db.ForeignKey('fathertable.id')` 的参数格式是 `'表名.列名'`，关联主表的主键。

## 9.8 课后作业

使用 Flask + Flask-SQLAlchemy 设计一对多两张数据表：

- 主表（一）：用户表 `User`
- 从表（多）：文章表 `Article`
- 关系：一个用户可以发布多篇文章，一篇文章只属于一个作者（用户）

字段设计要求：

`User` 用户表：

- `id`：主键
- `username`：用户名，长度 20 以内，非空，唯一
- `nickname`：昵称，长度 30，非空
- `status`：账号状态，数字，默认 1（正常）

`Article` 文章表：

- `id`：主键
- `title`：文章标题，长度 100，非空
- `content`：文章内容，长文本，非空
- `publish`：是否发布，布尔，默认 False
- `user_id`：外键，关联用户 id，允许为空
