# 10 事件循环与执行模型

JavaScript 在单线程中运行，却能处理定时器、网络请求和用户交互，而不会冻结页面。事件循环正是实现这一点的机制。理解事件循环有助于你编写非阻塞代码、避免 UI 冻结，并理清 `setTimeout`、`Promise.then` 和 `async/await` 的执行顺序。

---

## 10.1 为什么 JavaScript 是单线程的

### 10.1.1 “单线程”是什么意思

线程（thread）是程序能够执行的最小指令序列。JavaScript 只使用一个线程来运行你的代码：主线程（main thread）。这意味着同一时刻只能执行一条语句。

| 术语 | 含义 |
|------|------|
| **单线程（Single-threaded）** | 同一时刻只在主线程上执行一个任务 |
| **同步（Synchronous）** | 代码逐行运行，等待每条语句执行完毕 |
| **异步（Asynchronous）** | 耗时操作被推迟；主线程继续执行其他工作 |

> **重要提示：** 单线程并不意味着慢。浏览器在后台会使用其他线程处理网络、定时器和渲染，但你的 JavaScript 代码本身只在一个线程上运行。

### 10.1.2 为什么这样设计？

单线程模型让 DOM 保持安全且可预测。如果两个脚本能同时修改同一个元素，竞态条件（race condition）就会频繁出现。

单线程模型的优点：
- DOM 上无需锁，也不会死锁
- 大多数脚本的心理模型更简单
- 事件循环能干净地协调异步工作

代价是任何长时间运行的同步任务都会阻塞其他一切：UI 更新、动画和事件处理程序都得等待。

## 10.2 同步代码与阻塞

### 10.2.1 主线程负责所有可见工作

解析 HTML、运行 JavaScript、处理点击和重绘屏幕都共享主线程。当 JavaScript 忙碌时，浏览器无法重绘或响应输入。

### 10.2.2 阻塞示例：长循环会冻结页面

点击下面的按钮不会有任何反应，直到循环结束，因为主线程正被占用。

```html
<button id="work">Start long task</button>
<button id="greet">Say hello</button>
<p id="status">Ready</p>

<script>
    document.getElementById("work").addEventListener("click", () => {
        document.getElementById("status").textContent = "Working...";

        const start = Date.now();
        while (Date.now() - start < 3000) {
            // 阻塞主线程 3 秒
        }

        document.getElementById("status").textContent = "Done";
    });

    document.getElementById("greet").addEventListener("click", () => {
        console.log("Hello!");   // 直到循环结束才会执行
    });
</script>
```

关键要点：
- 循环运行期间，浏览器无法更新 `textContent`。
- 第二个按钮的点击处理程序会延迟到主线程空闲时才执行。
- 长时间任务应拆分成小块，或移出主线程。

> **最佳实践：** 将同步工作控制在 50 毫秒以内。对于更重的任务，使用 `setTimeout`/`requestIdleCallback` 让出主线程，或把任务移到 Web Worker 中执行。

## 10.3 调用栈与执行上下文

### 10.3.1 调用栈

调用栈（call stack）是一种数据结构，用于跟踪当前正在运行的函数。函数被调用时会被压入栈中；返回时则从栈中弹出。

```javascript
function first() {
    second();
    console.log("first");
}

function second() {
    third();
    console.log("second");
}

function third() {
    console.log("third");
}

first();   // third, second, first
```

栈的变化过程：
1. `first()` 入栈，调用 `second()`
2. `second()` 入栈，调用 `third()`
3. `third()` 入栈，输出 `"third"`，然后出栈
4. `second()` 输出 `"second"`，然后出栈
5. `first()` 输出 `"first"`，然后出栈

### 10.3.2 执行上下文

每次函数调用都会创建一个执行上下文（execution context），其中包含：
- 自己的 `this` 绑定
- 局部变量和参数
- 对外部作用域的引用（作用域链）

当前正在执行的上下文始终位于调用栈的顶部。

### 10.3.3 栈溢出

栈的大小是有限的。没有正确退出条件的递归函数可能耗尽栈空间。

```javascript
function crash() {
    crash();   // 没有基本情况
}

// crash();   // RangeError：超出最大调用栈大小
```

> **提示：** 现代浏览器中不宜广泛依赖尾调用优化（tail-call optimization）。对于深层重复，优先使用迭代循环；或者增大递归调用之间的延迟，用 `setTimeout` 清空栈。

## 10.4 事件循环与任务队列

### 10.4.1 宏任务

宏任务（macrotasks）是排队的任务单元，在调用栈为空且浏览器完成必要的渲染后执行。

| 来源 | 示例 |
|--------|---------|
| `setTimeout` | `setTimeout(fn, 1000)` |
| `setInterval` | `setInterval(fn, 1000)` |
| I/O 回调 | 文件读取、网络响应（在 Node.js 中） |
| UI 渲染 | 重绘和布局任务 |
| `queueMacrotask` | 不是标准 API；概念上等同于 `setTimeout(fn, 0)` |

### 10.4.2 微任务

微任务（microtasks）是更小、优先级更高的任务，在当前脚本结束后、下一个宏任务之前立即执行。

| 来源 | 示例 |
|--------|---------|
| `Promise.then` / `catch` / `finally` | `fetch(url).then(fn)` |
| `queueMicrotask` | `queueMicrotask(fn)` |
| `async/await` 的续体 | `await` 表达式之后的代码 |

### 10.4.3 执行顺序规则

1. 运行当前同步代码，直到调用栈为空。
2. 逐一处理微任务队列中的**所有**微任务。
3. 如有需要，渲染页面。
4. 从任务队列中取出**最早**的宏任务并执行。
5. 从第 2 步开始重复。

也就是说：**栈空 → 清空微任务 → 执行下一个宏任务**。

```javascript
console.log("1");                     // 同步

setTimeout(() => console.log("2"), 0); // 宏任务

Promise.resolve().then(() => {        // 微任务
    console.log("3");
});

console.log("4");                     // 同步

// 输出：1, 4, 3, 2
```

> **记住：** 即使延迟为 `0`，`setTimeout` 也会在所有微任务和任何渲染之后执行。

### 10.4.4 事件循环流程图

```
+---------------------+
|    同步代码          |  <-- 先运行，填满调用栈
|   （压栈/弹栈）      |
+----------+----------+
           |
           v
+----------+----------+
|     微任务队列       |  <-- 在下一个宏任务之前
|  Promise.then /     |      完全清空
|  queueMicrotask     |
+----------+----------+
           |
           v
+----------+----------+
|     宏任务队列       |  <-- 一次执行一个
|  setTimeout /       |
|  setInterval / IO   |
+----------+----------+
           |
           v
+----------+----------+
|    渲染 / 绘制       |  <-- 浏览器更新屏幕
+---------------------+
           |
           +----> 回到微任务检查
```

用中文概括：
1. 执行 JavaScript，直到栈为空。
2. 清空所有待处理的微任务。
3. 渲染页面。
4. 执行下一个宏任务。
5. 从头开始。

## 10.5 为什么 setTimeout 不是精确的定时器

### 10.5.1 最小延迟，而非保证延迟

`setTimeout(fn, 1000)` 要求浏览器至少在 1000 毫秒后将 `fn` 加入宏任务队列。实际执行时间取决于主线程上还有其他什么任务。

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Timer fired");
}, 100);

const start = Date.now();
while (Date.now() - start < 500) {
    // 阻塞 500 毫秒
}

console.log("End");

// 可能输出：Start, End, Timer fired
```

定时器回调大约等待了 500 毫秒，而不是 100 毫秒，因为主线程正忙。

### 10.5.2 后台标签页中的最小延迟

浏览器会对非活动标签页中的定时器进行节流，以节省电量。后台标签页中延迟很短的 `setTimeout` 可能会被推迟到 1 秒甚至更久。

| 场景 | 行为 |
|-----------|----------|
| 活动标签页，主线程空闲 | 延迟接近设定值 |
| 主线程繁忙 | 延迟比设定值更长 |
| 嵌套 `setTimeout`（5 层以上） | 某些浏览器会把最小延迟限制为 4 毫秒 |
| 后台标签页 | 定时器可能被节流至约 1 秒 |

> **最佳实践：** 把 `setTimeout` 用于任务调度，而非实时音频、动画或精确测量。对于动画，优先使用 `requestAnimationFrame`。

## 10.6 async/await 与事件循环

### 10.6.1 async 函数返回 Promise

`async` 函数总是返回一个 Promise。当你在其中 `await` 一个值时，函数会暂停，函数的剩余部分被安排为一个微任务。

```javascript
async function demo() {
    console.log("A");
    await Promise.resolve();   // 在此处暂停
    console.log("B");          // 作为微任务运行
}

console.log("Start");
demo();
console.log("End");

// 输出：Start, A, End, B
```

### 10.6.2 await 在循环中的位置

`await` 是 `.then()` 的语法糖。`await` 之后的代码会变成一个微任务续体。

```javascript
async function fetchUser(id) {
    const response = await fetch(`/api/users/${id}`); // 让出主线程
    const user = await response.json();               // 再次让出
    return user;
}
```

网络请求在另一个线程上发送时，主线程保持空闲。当响应返回时，`await` 之后的续体被作为微任务排队，并在任何待处理宏任务之前执行。

> **重要提示：** `await` 只会暂停所在的 `async` 函数。它不会阻塞其他脚本、事件处理程序或浏览器的渲染循环。

## 10.7 常见错误与最佳实践

| 应该 | 不应该 |
|----|-------|
| 把长时间同步工作拆成更小的块 | 在主线程上直接运行重型循环 |
| 在 `async` 函数中使用 `await` 以提高可读性 | 认为 `setTimeout(fn, 0)` 会在当前行之后立即执行 |
| 优先使用 `queueMicrotask` 在下次渲染前调度清理工作 | 依赖定时器延迟实现精确计时 |
| 使用 `requestAnimationFrame` 进行视觉更新 | 使用 `setInterval` 实现逐帧动画 |
| 保持 `.then()` 链扁平并处理错误 | 创建深度嵌套的 Promise 链 |

**记忆口诀**
- **事件循环** = “栈空先微任务，再执行下一个宏任务”
- **setTimeout** = “调度延迟，并非保证延迟”
- **async/await** = “看起来像同步，实际作为微任务续体运行”
