# 1 认识微信小程序

本章介绍微信小程序的基本概念、发展历史、与传统 APP 的区别，以及开发前的准备工作：注册小程序账号、安装微信开发者工具并创建第一个项目。

## 1.1 小程序基本介绍

### 1.1.1 小程序是什么

微信小程序，简称小程序，英文名 Mini Program。对于开发者而言，小程序开发门槛相对较低，难度不及 APP，能够满足简单的基础应用，适合生活服务类线下商铺以及非刚需低频应用的转换。

![[ch01-01.png]]

手机上安装的软件 APP 大致可以分为四类：

- **原生 APP（Native App）**：针对特定操作系统开发，如 iOS（Objective-C）、Android（Java、Kotlin）、Windows Phone（C#）。
- **Web App**：用 H5 + CSS + JavaScript 开发，再打包成相应的 APP，比如 Android 的 `xxx.apk`。
- **Hybrid App（混合 APP）**：原生 + Web 混合开发。
- **Light App（轻应用）**：寄生于一个超级 APP 内部，微信小程序就是基于微信 APP 的轻应用。

### 1.1.2 小程序发展历史

小程序发展历史 Timeline（2016–2024）：

| 时间 | 阶段 | 说明 |
| ---- | ---- | ---- |
| 2016 年 | 萌芽阶段 | 项目立项，从"应用号"改名"小程序"，仅开放少数开发者内测，处于技术打磨阶段 |
| 2017 年 | 诞生起步 | 1 月 9 日正式上线，实现基础访问、分享、扫码功能，逐步开放个人与企业开发权限 |
| 2018 年 | 功能补齐 | 新增直播、消息推送、完整电商链路，从工具类转向商业服务类应用 |
| 2019 年 | 商业成型 | 开放广告变现、搜索流量，模板化开发普及，小程序正式走向商业化盈利 |
| 2020 年 | 全民爆发 | 受疫情影响，生活服务、线上服务类小程序飞速发展，用户量达到顶峰 |
| 2021–2022 年 | 生态深耕 | 打通微信全生态流量，主攻本地实体行业，成为实体店线上经营核心工具 |
| 2023 至今 | 智能进化 | 融入人工智能技术，轻量化、高效率、免安装成为小程序最大核心优势 |

### 1.1.3 小程序与传统 APP 的区别

| 特性维度 | 小程序 | 传统 APP |
| -------- | ------ | -------- |
| 安装方式 | 无需安装，即用即走 | 需从应用商店下载安装 |
| 独立性 | 依赖超级 App（如微信） | 独立应用，不依赖任何平台 |
| 开发成本 | 低（一套代码，多端运行） | 高（需分别开发 iOS 和安卓版） |
| 功能能力 | 受限，依赖平台开放接口 | 强大，可调用系统全部功能 |
| 性能体验 | 接近原生，但略有差距 | 最佳，流畅度高 |
| 推广方式 | 社交分享、扫码、搜索 | 应用商店、广告投放 |
| 适用场景 | 轻量级、工具型、低频次、需要快速传播的业务 | 高频次、重交互、功能复杂、追求极致体验的业务 |

**小程序**是一种无需下载安装、依托于超级 App（如微信、支付宝）即可使用的应用。

- 优势：
  - **即用即走，无需安装**：用户无需从应用商店下载，扫一扫或搜一下即可打开，使用门槛极低。
  - **开发成本低，周期短**：使用统一的 Web 技术栈（如 JS、CSS），一套代码可跨平台运行，大大降低了开发和维护成本。
  - **依托平台，易于推广**：背靠微信等拥有巨大流量的平台，可以方便地通过分享、社交链、公众号等方式进行裂变式传播。
  - **无需考虑设备适配**：运行环境由宿主 App（如微信）提供，开发者无需过多关心不同手机操作系统的兼容性问题。
- 局限性：
  - **功能受限，依赖平台**：必须依赖于宿主 App（如微信），不能独立运行。其功能调用受限于平台提供的 API，无法实现所有原生功能。
  - **体验相对较弱**：在性能、动画流畅度和操作体验上，通常不如原生 APP。
  - **平台规则限制**：需要遵守平台的审核、运营规范和政策，自主性较低。

**传统 APP** 是指需要通过应用商店（如 App Store、安卓市场）下载并安装到手机操作系统上的原生应用程序。

- 优势：
  - **功能强大且完整**：可以调用手机的所有硬件和系统 API（如 GPS、蓝牙、摄像头），能够实现最复杂、最极致的功能。
  - **性能卓越，体验流畅**：直接运行于操作系统之上，在响应速度、动画效果和交互体验上最佳。
  - **独立性强**：不依赖任何第三方平台，可以独立运营和品牌塑造。
  - **可离线运行**：核心功能和内容可以打包在 App 内，实现更好的离线使用体验。
- 局限性：
  - **开发成本高，周期长**：需要为 iOS 和安卓分别开发，人力、时间和资金投入大。
  - **推广安装门槛高**：需要用户主动去应用商店搜索、下载、安装，获客成本和用户流失率较高。
  - **需要维护和更新**：应用上架需经过平台审核，版本更新需要用户手动下载，维护复杂。

### 1.1.4 怎么理解小程序

小程序本质上是一种"镶嵌"在超级 APP（如微信、支付宝）内部的轻量级应用程序。它实现了用户"触手可及"的梦想，无需下载安装，只需扫一扫或搜一下即可打开使用，同时也体现了"用完即走"的理念。

1. **不是 HTML5**：虽然用了类似的技术，但体验更好。它不能简单地被看作一个手机网页，它拥有独立的运行环境，体验更接近原生 APP，比网页更流畅、更稳定。
2. **即用即走，随手可得**：这是核心特征。无需下载安装，扫个码或搜一下就能立即使用，用完就关，不占手机内存，像使用一个工具一样方便。
3. **基于微信客户端，一次开发，多端兼容**：它依赖微信这个"母体"，不能独立存在。但好处是，你只需要开发一次，就能在几乎所有安装了微信的手机上正常运行，自动兼容不同操作系统（iOS/Android），大大节省了开发成本。
4. **优美的操作体验**：小程序的设计规范和运行机制保证了其操作流畅度、动画效果和整体用户体验，都远超普通网页，非常接近原生 APP 的感觉。

### 1.1.6 需要的技术储备

开发小程序需要三项基础技术：

1. **WXSS —— 负责"好看"**：就是 CSS，控制页面样式（颜色、布局、字体等）。
2. **WXML —— 负责"骨架"**：类似 HTML 的标签语言，搭建页面结构和内容。
3. **JavaScript —— 负责"能动"**：处理所有业务逻辑，比如点击事件、数据获取、页面交互。

### 1.1.7 小程序的框架结构

小程序的运行框架可以分为三层：

- **视图层**：由 WXML、WXSS、JS、JSON 构成，负责页面结构与样式的渲染。
- **控制逻辑层**：由控制代码和 API 接口构成，通过"响应的数据绑定"和"事件"与视图层双向通信。
- **操作系统层**：提供网络通讯、录音功能、数据缓存、系统信息等底层能力。

![[ch01-04.png]]

从整体架构看，用户端包括小程序前端与微信客户端；小程序前端架构由 WXML、WXSS、JavaScript、自定义组件构成，通过微信能力（微信 API、开放能力、原生组件）连接后端服务（业务服务器、数据库、缓存、文件存储）与第三方服务（云开发：内容安全、实时音视频、地图服务），并配套 CI/CD、监控告警、日志分析、性能优化等运维部署能力。

## 1.2 账号和设置

小程序是微信提供的一种服务，官方明确给出了使用小程序的接入流程：

1. **注册**：在微信公众平台注册小程序，完成注册后可以同步进行信息完善和开发。
2. **小程序信息完善**：填写小程序基本信息，包括名称、头像、介绍及服务范围等。
3. **开发小程序**：完成小程序开发者绑定、开发信息配置后，开发者可下载开发者工具、参考开发文档进行小程序的开发和调试。
4. **提交审核和发布**：完成小程序开发后，提交代码至微信团队审核，审核通过后即可发布（公测期间不能发布）。

![[ch01-05.png]]

### 1.2.1 注册

**进入注册页面**：官方文档 <https://mp.weixin.qq.com/cgi-bin/wx?token=&lang=zh_CN>，点击"前往注册"。

**填写注册信息**，注意：

1. 一个邮箱只能申请一个小程序账号。
2. 注册了公众号的邮箱不能再申请小程序。
3. 邮箱填写后点击"激活邮箱"，跳转网页后登录自己的邮箱。
4. 邮箱将收到验证码，填写完成后设置密码（字母、数字或者英文符号，最短 8 位，区分大小写）。
5. 密码设置后勾选协议前面的 ☐，然后点击注册。

**信息登记**：主体类型选择"个人"（个人类型暂不支持微信认证、微信支付及高级接口能力），然后填写主体信息：

- 身份证姓名：信息审核成功后身份证姓名不可修改。
- 身份证号码：一个身份证号码只能注册 5 个小程序。
- 管理员手机号码：使用与微信号绑定的同一手机号，一个手机号码只能注册 5 个小程序。
- 短信验证码：填写手机短信收到的 6 位验证码。
- 管理员身份验证：微信扫码完成身份验证，该微信号将作为小程序的管理员。

确认提交的主体信息（主体名称、主体类型）后点击"确定"，提示"信息提交成功"后即可点击"前往小程序"进入微信公众平台使用相关功能。

### 1.2.2 登录

**进入官网登录页面**：网址 <https://mp.weixin.qq.com>，扫码登录或者账号密码登录均可。

登录后可能会被要求进行二次扫码验证登录，直接使用绑定的微信扫码登录即可。二次验证成功后，进入小程序管理后台。

**先完善个人信息**，在"小程序发布流程"中依次完成：

- **小程序信息**：补充小程序的基本信息，如名称、图标、描述等。账号名称长度为 4–30 个字符（一个中文字等于 2 个字符）；头像图片格式必须为 png、bmp、jpeg、jpg、gif，不可大于 2M，建议使用 png 格式图片，建议尺寸为 144px × 144px；小程序介绍需不含国家相关法律法规禁止内容。
- **小程序类目**：补充小程序的服务类目，设置主营类目。
- **小程序备案**：补充小程序的备案信息（需先填写小程序信息和类目）。
- **微信认证**：完成微信认证后，账号可获得"被搜索"和"被分享"能力；未完成微信认证不影响后续版本发布。

### 1.2.3 获取 AppID

小程序开发需要依赖于小程序的 AppID。在小程序管理后台依次进入 **开发与服务 → 开发管理 → 开发设置**，即可在"开发者 ID"中查看当前小程序的 **AppID（小程序 ID）**，开发小程序时需要用到；同一页面还可以生成 **AppSecret（小程序密钥）**。

### 1.2.4 版本管理

在 **管理 → 版本管理** 中可以查看小程序的三类版本：

- **线上版本**：已发布、面向全部用户的版本。
- **审核版本**：已提交微信团队审核、待发布上线的版本。
- **开发版本**：开发者工具上传、尚在开发调试中的版本。

### 1.2.5 成员管理

小程序成员管理包括对小程序项目成员及体验成员的管理。

- **项目成员**：表示参与小程序开发、运营的成员，可登录小程序管理后台，包括运营者、开发者及数据分析者。管理员可在"成员管理"中添加、删除项目成员，并设置项目成员的角色。
- **体验成员**：表示参与小程序内测体验的成员，可使用体验版小程序，但不属于项目成员。管理员及项目成员均可添加、删除体验成员。

## 1.3 开发工具和模拟器

为了帮助开发者简单和高效地开发和调试微信小程序，腾讯在原有的公众号网页调试工具的基础上，推出了全新的微信开发者工具，集成了公众号网页调试和小程序调试两种开发模式。

### 1.3.1 下载安装官方开发工具（必要）

下载地址：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>

下载页面提供三个版本：

- **稳定版 Stable Build**：测试版缺陷收敛后转为稳定版，日常使用推荐此版本。
- **预发布版 RC Build**：预发布版，包含大的特性，通过内部测试，稳定性尚可。
- **开发版 Nightly Build**：日常构建版本，用于尽快修复缺陷和敏捷上线小的特性，开发自测验证，稳定性欠佳。

根据自己的操作系统（Windows 64、Windows 32、macOS x64、macOS ARM64）下载相应版本的软件，下载后双击运行安装，一路下一步即可。

安装注意事项：

- 不要把开发工具安装在 C 盘——微信小程序开发工具运行起来很占电脑性能，学习阶段还好，后面项目比较大时影响明显。
- 下载安装包时注意选择对应的版本；安装之前先把电脑上的各种"xx 管家"类软件退出，否则会影响开发工具的安装。
- 电脑权限不够时，记得使用管理员身份运行安装程序。

### 1.3.2 工具进入

打开微信开发者工具后，用之前绑定的微信扫码登录，登录后将会正式进入开发管理面板。面板左侧可以切换不同的项目类型：**小程序、小游戏、多端应用、代码片段、公众号网页、其他**，点击"+"即可新建项目。

## 1.4 项目创建

在开发管理面板中选择"小程序"，点击"+"进入"创建小程序"界面，使用之前绑定的微信号扫码后即可填写项目信息：

- **项目名称**：可以是中文，例如 `demo`。
- **目录**：项目存放的目录，例如 `D:\wechatProject`。
- **AppID**：小程序 ID，即在 1.2.3 节获取的 AppID；没有的话也可以注册或使用测试号。
- **后端服务**：可选择"微信云开发"或"不使用云服务"（默认模板不适用云开发）。
- **开发模式**：选择"小程序"。
- **模板选择 / 语言**：选择用于交互的开发语言和模板，例如官方"JS-基础模版"（语言为 JavaScript）。

填写完成后点击"创建"，即可生成第一个小程序项目，在模拟器中预览效果。
