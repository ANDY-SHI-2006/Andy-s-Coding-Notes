# 14 账号管理

本章实现 Flask 后台管理系统的「账号管理」模块：账号列表、账号详情、新增与编辑账号、删除与恢复账号（软删除），以及当前登录用户的个人资料修改与密码修改。账号数据对应 `User` 模型，视图集中在 `web/views/account/Account.py`，模板在 `web/templates/account/` 目录下。

## 14.1 注册账号管理蓝图

在入口文件 `www.py` 中注册账号管理视图的蓝图，URL 前缀为 `/account`：

```python
from web.views.account.Account import route_account
app.register_blueprint(route_account, url_prefix="/account")
```

`Account.py` 中创建蓝图，并引入统一的渲染函数 `ops_render`（替换原生的 `render_template`）和 `User` 模型：

```python
# -*- coding: utf-8 -*-
from flask import Blueprint, render_template
from common.libs.render_helper import ops_render
from web.models.user import User

route_account = Blueprint('account_page', __name__)

@route_account.route("/index")
def index():
    return ops_render("account/index.html")

@route_account.route("/info")
def info():
    return ops_render("account/info.html")

@route_account.route("/set")
def set():
    return ops_render("account/set.html")
```

## 14.4 新增与编辑账号

新增和编辑共用 `/account/set` 这一个视图与模板，通过**请求是否携带账号 id** 来区分两种操作。

### 14.4.1 GET 请求：渲染表单

新增不需要渲染数据；编辑需要查询用户原数据并填充到表单：

```python
@route_account.route("/set", methods=["GET", "POST"])
def set():
    if request.method == "GET":
        context = {}
        req = request.args
        uid = int(req.get("id", 0))
        info = None
        if uid:
            info = User.query.filter_by(uid=uid).first()
        context["info"] = info
        return ops_render("account/set.html", context)
```

### 14.4.3 POST 请求：获取参数并校验

获取表单提交的各项参数，并构建统一格式的响应对象：

```python
    elif request.method == "POST":
        req = request.values
        nickname = req["nickname"] if "nickname" in req else ""
        mobile = req["mobile"] if "mobile" in req else ""
        email = req["email"] if "email" in req else ""
        login_name = req["login_name"] if "login_name" in req else ""
        login_pwd = req["login_pwd"] if "login_pwd" in req else ""
        id = req["id"] if "id" in req else 0

        resp = {"code": 200, "msg": "操作成功", "data": {}}
```

**校验登录名是否被注册**。注意过滤条件 `User.uid != id` 的巧妙之处：

- 编辑时登录名没有更改：`User.login_name == login_name` 成立，但 `User.uid != id` 不成立，不会误判；
- 编辑时登录名改成了别人已用的：两个条件都成立，拦截；
- 新增时（`id` 为 0）登录名已被注册：两个条件都成立，拦截。

```python
        # 验证登录名是否被注册（在添加账号时，User.uid != id 才会成立）
        has_in = User.query.filter(User.login_name == login_name, User.uid != id).first()
        if has_in:
            resp["code"] = -1
            resp["msg"] = "该登录名已经存在，请换一个试一试"
            return jsonify(resp)
```

### 14.4.4 区分编辑与新增，构建用户数据

能按 id 查到用户就是编辑请求，否则是新增请求。**admin 账号（uid 为 1）不允许修改**；新增时需要生成加盐数据 `login_salt` 和创建时间：

```python
        # 编辑 or 添加账号？
        user_info = User.query.filter_by(uid=id).first()
        if user_info:  # 能拿到就是编辑请求
            # 如果是 admin 账号，不允许修改
            if user_info and user_info.uid == 1:
                resp["code"] = -1
                resp["msg"] = "该用户是admin账号，不允许修改编辑"
                return jsonify(resp)
            model_user = user_info
        else:  # 拿不到就是新增账号请求
            model_user = User()  # 新建一个 User 实例
            # from common.libs.UserService import UserService
            model_user.login_salt = UserService.genSalt(16)  # 自动产生一个加盐数据
            # import datetime
            model_user.created_time = datetime.datetime.now()
```

其中 `genSalt()` 方法定义在 `common/libs/UserService.py` 中，用于生成指定长度的随机加盐字符串：

```python
@staticmethod
def genSalt(length=16):
    """生成 加盐码"""
    selectString = string.ascii_letters + string.digits  # 所有的数字和字母
    # 随机生成 16 个数字或者字母的组合
    key_list = [random.choice(selectString) for i in range(length)]
    return "".join(key_list)
```

### 14.4.5 更新数据到数据库

无论新增还是编辑，最后统一赋值并提交。密码字段结合前端的占位符比较：只有提交的密码不是 `******` 时才视为修改了密码，重新生成加盐密码保存：

```python
        model_user.nickname = nickname
        model_user.mobile = mobile
        model_user.email = email
        model_user.login_name = login_name
        if login_pwd != '******':
            # 表示修改了密码，重新生成密码保存（要结合前端的密码默认值比较）
            model_user.login_pwd = UserService.genPwd(login_pwd, model_user.login_salt)
        model_user.updated_time = datetime.datetime.now()
        # from application import db
        db.session.add(model_user)
        db.session.commit()
        return jsonify(resp)
```

## 14.5 删除与恢复账号（软删除）

删除与恢复共用一个 `/ops` 接口，通过参数 `act` 区分操作类型（`remove` / `recover`）。采用**软删除**：不真正删除记录，只修改 `status` 字段（1 正常、0 已删除）。

### 14.5.1 前端传递 id

列表页删除/恢复链接通过 `data` 属性把账号 id 传给 js：

```html
<a class="m-l remove" href="javascript:void(0);" data="{{ item.uid }}">
    <i class="fa fa-trash fa-lg"></i>
</a>
```

并在 `index.html` 底部关联 `{% block js %}` 中的 `/js/account/index.js`，由它发送 ajax 请求。

### 14.5.2 后端 ops 视图

在 `Account.py` 中添加 `ops` 视图方法（只接受 POST），依次校验：操作类型是否合法、是否选择了账号、账号是否存在、是否为 admin 账号：

```python
@route_account.route("/ops", methods=["POST"])
def ops():
    if request.method == "POST":
        resp = {"code": 200, "msg": "操作成功", "data": {}}
        req = request.values

        act = req["act"] if "act" in req else ""
        id = req["id"] if "id" in req else 0
        print('获取到的数据:', act, id)

        if act not in ["remove", "recover"]:
            resp["code"] = -1
            resp["msg"] = "操作有误"
            return jsonify(resp)
        if not id:
            resp["code"] = -1
            resp["msg"] = "请选择要操作的账号"
            return jsonify(resp)
        user_info = User.query.filter_by(uid=id).first()
        if not user_info:
            resp["code"] = -1
            resp["msg"] = "指定账号不存在"
            return jsonify(resp)
        if user_info and user_info.uid == 1:
            resp["code"] = -1
            resp["msg"] = "该用户是admin账号，不允许修改编辑"
            return jsonify(resp)
```

### 14.5.3 软删除操作

根据 `act` 修改 `status` 字段并提交：

```python
        if act == "remove":
            user_info.status = 0  # 删除状态
        elif act == "recover":  # 变成不删除状态
            user_info.status = 1
        user_info.updated_time = datetime.datetime.now()
        db.session.add(user_info)
        db.session.commit()
        return jsonify(resp)
```

## 14.6 个人资料修改与修改密码

除了管理员对账号的统一管理，当前登录用户还可以在「个人中心」修改自己的资料和密码。这部分视图在 `web/views/user/User.py` 中（蓝图前缀 `/user`），操作对象是当前登录用户 `g.user`。

### 14.6.1 修改用户信息

`/user/edit` 视图：POST 时校验昵称和邮箱，**数据有变化时才操作数据库**；保存成功后需要**重新生成登录 cookie**，因为 cookie 中存储的用户编码与昵称、邮箱相关：

```python
@route_user.route("/edit", methods=["GET", "POST"])
def edit():
    if request.method == "POST":
        # 1、构建响应对象
        resp = {"code": 200, "msg": "操作成功", "data": {}}

        # 2、获取提交数据 --- nickname、email
        nickname = request.values.get("nickname", None)
        email = request.values.get("email", None)

        if not nickname or len(nickname) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入要修改的用户名"
            return jsonify(resp)
        if not email or len(email) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入要修改的邮箱"
            return jsonify(resp)

        # 数据有变化的情况才进行数据的操作
        user_info = g.user
        if user_info.nickname == nickname and user_info.email == email:
            resp["code"] = -1
            resp["msg"] = "数据一样，无需修改"
            return jsonify(resp)

        user_info.nickname = nickname
        user_info.email = email

        db.session.add(user_info)
        db.session.commit()

        # 携带 cookie
        res_jsonobj = jsonify(resp)

        # cookie 登录信息存储
        res_jsonobj.set_cookie(current_app.config.get("AUTH_COOKIE_NAME"),
                               f'{UserService.genUserCode(user_info)}#{user_info.uid}',
                               max_age=86400)

        return res_jsonobj

    elif request.method == "GET":
        return render_template("user/edit.html")
```

### 14.6.2 修改密码

`/user/reset-pwd` 视图：要求输入原密码和新密码；用 `UserService.genPwd()` 把用户输入的原密码加盐后**与数据库中的密码对比**，验证通过才允许修改。cookie 信息是否需要更新，取决于设置 cookie 时存放的数据内容：

```python
@route_user.route("/reset-pwd", methods=["POST", "GET"])
def resetPwd():
    """
    这里 cookie 信息是否需要修改取决于你设置 cookie 信息的时候存放的数据是什么
    """
    if request.method == "POST":
        # 1、构建响应对象
        resp = {"code": 200, "msg": "操作成功", "data": {}}

        old_pwd = request.values.get("old_password", None)
        new_pwd = request.values.get("new_password", None)

        if (not old_pwd) or len(old_pwd) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入原密码"
            return jsonify(resp)

        if (not new_pwd) or len(new_pwd) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入不少于6位的新密码"
            return jsonify(resp)

        if old_pwd == new_pwd:
            resp["code"] = -1
            resp["msg"] = "跟原密码相同，请重新输入"
            return jsonify(resp)

        user_info = g.user
        # 用户输入的原密码，与数据库里面的原密码进行对比
        gen_pwd = UserService.genPwd(old_pwd, user_info.login_salt)

        if user_info.login_pwd != gen_pwd:
            resp["code"] = -1
            resp["msg"] = "原密码错误"
            return jsonify(resp)

        # 通过验证，修改密码
        user_info.login_pwd = UserService.genPwd(new_pwd, user_info.login_salt)
        db.session.add(user_info)
        db.session.commit()
        return jsonify(resp)
    elif request.method == "GET":
        return render_template("user/reset_pwd.html")
```
