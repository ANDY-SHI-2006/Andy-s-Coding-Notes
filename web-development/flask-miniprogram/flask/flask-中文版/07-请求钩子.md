# 7 请求钩子

## 7.1 请求钩子概述

一次完整的请求流程是：

```
用户 --- 请求 --- flask应用 --- 响应

flask应用内部：  请求 ---> 视图 ---> 响应
```

请求钩子（Request Hooks）就是在"请求 → 视图 → 响应"这条链路上插入的处理函数，可以在进入视图之前、视图处理完成之后、请求结束时执行一些通用逻辑（如权限校验、日志记录、资源释放等）。

Flask 提供三个常用的请求钩子：

| 钩子 | 触发时机 |
| ---- | -------- |
| `app.before_request` | 进入视图之前 |
| `app.after_request` | 视图处理完成之后 |
| `app.teardown_request` | 请求结束时触发（视图异常也会触发） |

## 7.2 三个请求钩子的用法

- `before_request`：不接收参数，在视图函数执行前运行。
- `after_request`：接收视图返回的响应对象，处理后**必须返回响应对象**。
- `teardown_request`：接收异常对象，即使没有异常抛出也会触发（此时异常对象为 `None`）。

```python
from flask import Flask

app = Flask(__name__,
            template_folder='templates')


@app.before_request
def before_request():
    print('before_request 执行')


@app.after_request
def after_request(response):  # 接收响应对象
    print('after_request 执行')
    return response  # 返回响应对象


@app.teardown_request
def teardown_request_(exception):  # 接收异常对象
    print('teardown_request 触发: ', exception)
    return exception  # 返回数据对象


@app.route('/index')
def index():
    return '异常'


if __name__ == '__main__':
    print('路由---:', app.url_map)

    app.run(debug=True)
```

### 7.2.1 视图抛出异常时的执行情况

当视图函数中抛出异常时（例如 `a = 1/0`），`after_request` 不会执行，但 `teardown_request` 仍然会触发，并能接收到异常对象：

```python
@app.route('/index')
def index():
    print('index')
    a = 1/0  # 抛出 ZeroDivisionError
    return "请求钩子"
```

访问 `/index` 后，控制台会打印 `teardown_request 触发: ` 及对应的异常信息。利用这一特性，可以在 `teardown_request` 中做统一的异常日志记录和资源清理。

## 7.3 钩子函数与视图函数之间的数据传递

钩子函数和视图函数之间需要传递数据时，可以使用 Flask 的 `g` 对象作为全局变量。`g` 对象作用于整个应用，每个请求进来时都会重新构建一次（先置空），因此可以在 `before_request` 中写入数据，在视图函数中读取：

```python
from flask import Flask, g

app = Flask(__name__,
            template_folder='templates')


@app.before_request
def before_request():
    g.s = 'g对象传递的参数'


@app.route('/index')
def index():
    print(g.s)         # g对象传递的参数
    # print(g.get('s'))  # 也可以用 get 方式读取
    return "请求钩子"


if __name__ == '__main__':
    print('路由---:', app.url_map)

    app.run(debug=True)
```

> `g` 对象属于 Flask 上下文的一部分，关于应用上下文与请求上下文的详细介绍见第 8 章。

## 7.4 补充：Session 构建 Redis 存储

默认情况下 Flask 的 session 数据存储在客户端 Cookie 中。借助 `Flask-Session` 扩展，可以把 session 数据转存到 Redis 服务器：

- Flask 使用 Redis：`redis`（Redis 驱动模块）
- 构建 Redis 的 session 存储：`Flask-Session`

安装依赖：

```bash
pip install Flask-Session redis -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

### 7.4.1 常用配置项

- `SECRET_KEY`：用于签名 Session ID 的密钥（必须设置）。
- `SESSION_TYPE`：指定使用哪种后端，这里设为 `'redis'`。
- `SESSION_PERMANENT`：是否设置永久会话（默认 `True`）。
- `PERMANENT_SESSION_LIFETIME`：会话有效期（`timedelta` 对象，默认 31 天）。
- `SESSION_USE_SIGNER`：是否对 Cookie 中的 Session ID 进行签名（推荐 `True`）。
- `SESSION_KEY_PREFIX`：Redis 中 Key 的前缀（默认 `'session:'`）。
- `SESSION_REDIS`：指定 Redis 连接实例（可以是连接对象或连接 URL）。

### 7.4.2 完整示例

```python
import os
from datetime import timedelta
from flask import Flask, make_response, request, session
import redis
from flask_session import Session

app = Flask(__name__,
            template_folder='templates')

# 1. 加密密钥 --- SECRET_KEY
app.config['SECRET_KEY'] = 'f*&……*（）#￥%%&iehrjgjakjsdbveiwjfdgfi(*(&*^%$^&YR&*^YH&'
app.config["SESSION_TYPE"] = 'redis'
app.config["SESSION_REDIS"] = redis.from_url('redis://127.0.0.1:6379')
app.config["SESSION_PERMANENT"] = False
app.config["SESSION_USE_SIGNER"] = True

# 初始化 Session
Session(app)


@app.route('/index')
def index():
    session['name'] = 'abai'
    return "session"


if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息

    app.run(debug=True)
```

## 7.5 补充：Cookie 过期时间 expires

设置 Cookie 过期时间有两种方式：`max_age` 和 `expires`，其中 **`max_age` 更推荐**，因为它精确到秒。

```python
import os
from datetime import timedelta, datetime
from flask import Flask, make_response, request, session

app = Flask(__name__,
            template_folder='templates')


@app.route('/index')
def index():
    # max_age ---- 秒
    response = make_response('cookie过期时间')

    # expires ---> datetime对象
    # expires = datetime.now() + timedelta(hours=1)
    expires = datetime.utcnow() + timedelta(hours=1)
    response.set_cookie('username', 'admin', expires=expires)

    return response


if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息

    app.run(debug=True)
```

### 7.5.1 expires 的时区问题

`expires` 接收的是 `datetime` 对象。相关时间运算：

```
>>> from datetime import timedelta, datetime

>>> datetime.now()
datetime.datetime(2026, 3, 7, 20, 31, 39, 895878)

>>> timedelta(hours=1)
datetime.timedelta(seconds=3600)

>>> datetime.now() + timedelta(hours=1)
datetime.datetime(2026, 3, 7, 21, 32, 23, 62567)
```

如果使用 `datetime.now()`（本地时间）设置过期时间，浏览器站点信息中显示的时间会与你预期的不一致——浏览器把你的时间看成 UTC 标准时间，再按本地时区换算。例如：

- 已创建：2026年3月7日 20:30:01，预期 1 小时后到期，即 21:30:01；
- 实际显示到期：2026年3月8日 05:30:01，与正确结果相差 8 个小时。

原因是中国时区为 UTC+8，与国际标准时间相差 8 个小时。因此使用 `expires` 时应使用 `datetime.utcnow()` 计算过期时间，避免时区偏差。

## 7.6 补充：set_cookie 参数

`set_cookie` 除了 `key`、`value`、`max_age`/`expires` 外，还有几个常用的限制参数：

```python
import os
from datetime import timedelta, datetime
from flask import Flask, make_response, request, session

app = Flask(__name__,
            template_folder='templates')


@app.route('/index')
def index():
    # max_age ---- 秒
    response = make_response('cookie过期时间')
    response.set_cookie('username', 'admin',
                        max_age=60*60,
                        domain='127.0.0.1'
                        # domain='.baidu.com'   # 只对设置的主机名有效
                        # domain='baidu.com'
                        # path='/index'  # 路由path的前缀限制
                        # path='/'       # 路由path的前缀限制 -- 默认 / ---> 根路径
                        # httponly=True  # 禁止js访问
                        # secure=True    # 仅限https
                        )
    return response


if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息

    app.run(debug=True)
```

参数说明：

| 参数 | 作用 |
| ---- | ---- |
| `max_age` | 过期时间，单位为秒（推荐） |
| `domain` | 限制 Cookie 生效的域名 |
| `path` | 路由 path 的前缀限制，默认 `/`（根路径） |
| `httponly` | 设为 `True` 时禁止 JS 访问该 Cookie |
| `secure` | 设为 `True` 时仅限 HTTPS 请求携带该 Cookie |

关于 `domain`：设置为 `baidu.com`（或 `.baidu.com`）时，一级域名匹配所有子域：

```
baidu.com     一级匹配所有子域
---> www.baidu.com
---> baike.baidu.com
```
