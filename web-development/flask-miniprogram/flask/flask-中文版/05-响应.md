# 5 响应

本章介绍 Flask 中构造响应的常见方式：模板响应（手动构建与 `render_template`）、异常响应（`abort` 与 `errorhandler`）、重定向响应（`redirect` 与 `url_for`），以及基于生成器的流式响应。

## 5.1 模板响应

返回一个 HTML 模板有两种方案：

- 方案一：手动构建（`make_response` + `open` 读取文件 + `re.sub` 注入数据）
- 方案二：使用 Flask 内置的 `render_template`

### 5.1.1 手动构建模板响应

先准备一个模板文件 `templates/demo.html`：

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>测试模版</title>
</head>
<body>
<h1>你好 ---- {{ name }}</h1>

</body>
</html>
```

手动构建的思路：用 `make_response()` 构建响应对象，用 `open` 读取模板文件内容，再用正则表达式把模板中的占位符替换为实际数据，最后把处理后的内容赋给响应体返回：

```python
from flask import Flask, render_template, make_response
import re

app = Flask(__name__, template_folder='templates')

"""
响应模版：
---- 方案一：手动构建
---- 方案二：render_template
"""

@app.route('/demo', methods=['GET', 'POST'])
def demo():
    name = 'abai'
    # 方案一：手动构建
    # --------- make_response 构建响应对象
    respose = make_response()
    # --------- 自定义响应体  open 打开文件（位置，模式，编码）read 读取
    data = open('./templates/demo.html', 'r', encoding='utf-8').read()

    # 模版数据注入
    """
    import re

    re.sub ---> 根据正则表达式 匹配 目标字符串中的子串，并根据指定内容（字符串/函数返回值）替换这些子串

    sub(pattern, repl, string, count=0, flags=0):
        pattern: 正则表达式模式，用于匹配需要替换的子串
        repl:   替换内容 --- 字符串/函数返回值
        string:  待处理的原始字符串
        count: 最多替换次数 ---- 默认值0  替换所有匹配项
        flags: 正则表达式标志
            ----  re.IGNORECASE 忽略大小写
            ----  re.DOTALL 匹配换行
    """
    # pattern 参数需要跟模版页面里面的字符串一模一样
    data = re.sub('{{ name }}', name, data)

    respose.data = data
    return respose

if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

要点：`re.sub(pattern, repl, string)` 按正则表达式匹配模板字符串中的子串并替换；`pattern` 必须与模板页面里的占位符写法完全一致（包括空格）。

### 5.1.2 使用 render_template

`render_template` 是 Flask 内置的模板渲染方式，只需传入模板名和要注入的变量，无需手动读文件、做正则替换：

```python
from flask import Flask, render_template

app = Flask(__name__, template_folder='templates')

@app.route('/demo', methods=['GET', 'POST'])
def demo():
    name = 'abai'
    # return render_template('demo.html')
    # return render_template('demo.html', name=name)
    age_size = 18
    return render_template('demo.html', name=name, age=age_size)

if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

模板中通过 `{{ name }}`、`{{ age }}` 这样的占位符接收变量。显然，`render_template` 比手动构建简洁得多，是实际开发的标准做法。

## 5.2 响应——异常

### 5.2.1 abort 函数

`abort` 函数用于放弃请求并返回错误代码（响应状态码）。调用 `abort` 后视图立即终止执行，其后的代码不再运行：

```python
from flask import Flask, abort

app = Flask(__name__, template_folder='templates')

"""
abort函数：放弃请求并返回错误代码（响应状态码）
"""

@app.route('/demo', methods=['GET', 'POST'])
def demo():
    # 终止视图执行，并返回HTTP状态
    abort(404)
    # abort(404, '错误信息404')
    return "hello"

if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

### 5.2.2 自定义错误处理视图（errorhandler）

`errorhandler` 装饰器接收一个 HTTP 状态码作为参数，用于自定义该状态码对应的错误处理视图。它不仅作用于 `abort` 函数抛出的错误，也作用于 Flask 应用自身产生的对应错误码（例如访问不存在的路由触发的 404）：

```python
@app.errorhandler(404)
def not_found(error):  # 错误信息对象
    return f'访问地址不存在 {error}'
```

注意：`errorhandler` 不能接受自定义的非法错误码，否则会抛出 `ValueError`：

```python
# ValueError: '4000000' is not a recognized HTTP error code.
# Use a subclass of HTTPException with that code instead.
# @app.errorhandler(4000000)
# def not_found(error):  # 错误信息对象
#     return f'访问地址不存在 {error}'
```

## 5.3 响应——重定向

使用 `redirect` 进行重定向，通常配合 `url_for` 使用：`url_for` 根据视图函数名反解析出真实路由地址，再由 `redirect` 重定向到该地址，避免在代码中硬编码 URL：

```python
from flask import Flask, redirect, url_for

app = Flask(__name__, template_folder='templates')

"""
redirect: 重定向
"""

@app.route('/demo', methods=['GET', 'POST'])
def demo():
    print("登录中")
    # return redirect('/index')
    # 反解析 ----》 真实路由 ---》 重定向
    return redirect(url_for('index'))

@app.route('/index')
def index():
    return "index --- 登录完成"

if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

## 5.4 流式响应

流式响应（Streaming Response）不是一次性返回全部数据，而是分批逐步发送。典型应用场景：

- 实时数据推送
- 大文件传输
- 长时间运行的任务进度更新

### 5.4.1 生成器基础

流式响应依赖 Python 的生成器（Generator）。生成器是一种特殊的迭代器，用于按需（惰性求值）生成数据，而不是一次性将所有结果加载到内存中。它依赖 `yield` 关键字实现函数的“暂停与恢复”，非常适合处理大数据或无限序列。

与普通函数不同，生成器函数在调用时不会立即执行，而是返回一个生成器对象；每次调用 `next()` 或在 `for` 循环中迭代时，才会从上次暂停的位置继续执行，直到遇到下一个 `yield` 或结束：

```python
>>> ga = generate()
>>> ga
<generator object generate at 0x000001C7E07B0040>
>>> next(ga)
0
>>> next(ga)
1
...
>>> next(ga)
9
>>> next(ga)
Traceback (most recent call last):
  File "<input>", line 1, in <module>
StopIteration     ----> 生成器结束
```

### 5.4.2 基础流式响应

把生成器传给 `Response`，Flask 就会以流式方式逐条发送数据。可以用 `response.is_streamed` 验证它是流式响应：

```python
from flask import Flask, redirect, url_for, Response
import time

app = Flask(__name__, template_folder='templates')

@app.route('/index')
def index():
    # 生成器  闭包
    def generate():
        for i in range(10):
            yield f"数据: {i} <br>"
            time.sleep(1)

    response = Response(generate(), mimetype='text/html')
    print(response.is_streamed)  # is_streamed True ---> 流式响应
    return response

if __name__ == '__main__':
    print(app.url_map)  # 查看路由信息
    app.run(debug=True)
```

浏览器访问 `/index` 时，会看到数据每隔 1 秒逐条出现，而不是等待 10 秒后一次性显示。

### 5.4.3 JSON 流式响应

生成器也可以逐条产出 JSON 数据，将 `mimetype` 设为 `application/json`：

```python
import json

@app.route('/index')
def index():
    def generate_json():
        for i in range(10):
            data = {
                "id": i,
                "message": f"消息 {i}",
                "timestamp": time.time()
            }
            yield json.dumps(data)
            time.sleep(1)

    return Response(generate_json(), mimetype='application/json')
```

### 5.4.4 SSE 事件流

SSE（Server-Sent Events，服务器发送事件）是浏览器端接收事件流的标准方式。生成器按 SSE 格式（每行以 `data: ` 开头）产出数据，响应的 `mimetype` 设为 `text/event-stream`：

```python
@app.route('/index')
def index():
    # sse 事件流 ----》 sse格式 ---》 浏览器事件
    def event_stream():
        for i in range(10):
            yield f'data: 事件 {i} \n'
            time.sleep(1)

    # text/event-stream ---> sse
    return Response(
        event_stream(),
        mimetype='text/event-stream',
        headers={
            'Cache-Control': 'no-cache',   # no-cache 禁用缓存
            "Connection": "keep-alive",     # keep-alive 保持连接
            # "X-Accel-Buffering": "no",    # 禁用 nginx 缓冲
        }
    )
```

### 5.4.5 流式响应相关的响应头

`Cache-Control` 常见取值：

- `max-age=`：设置缓存的最大存储时间（以秒为单位）。在此时间内，缓存被视为有效。示例：`Cache-Control: max-age=3600` 表示缓存有效期为 1 小时。
- `no-cache`：要求缓存必须在使用前向服务器验证资源的有效性。即使缓存存在，也需要重新验证。示例：`Cache-Control: no-cache`。
- `no-store`：完全禁止缓存，客户端和代理服务器都不存储请求或响应的任何内容。示例：`Cache-Control: no-store`。
- `public`：允许任何缓存（包括代理服务器）存储响应内容。示例：`Cache-Control: public, max-age=86400`。
- `private`：仅允许单个用户的本地缓存存储内容，代理服务器不能缓存。示例：`Cache-Control: private, max-age=3600`。
- `must-revalidate`：一旦缓存过期，必须向服务器重新验证资源的有效性。示例：`Cache-Control: must-revalidate`。
- `immutable`：表示响应内容不会随时间改变，客户端无需重新验证，即使用户刷新页面。示例：`Cache-Control: immutable`。
- `stale-while-revalidate=`：允许客户端在后台异步验证的同时使用过期的缓存。示例：`Cache-Control: stale-while-revalidate=60`。
- `stale-if-error=`：在服务器出错时，允许客户端使用过期的缓存。示例：`Cache-Control: stale-if-error=120`。

`Connection` 常见取值：

- `Connection: keep-alive`：`keep-alive` 表示保持长连接，允许多个请求复用同一个 TCP 连接。它的优点包括减少连接建立和断开的开销、降低网络延迟以及提高系统性能。在 HTTP/1.1 中，长连接是默认开启的，客户端和服务器无需额外配置即可支持。
- `Connection: close`：`close` 表示短连接，即每次请求完成后立即关闭连接。在 HTTP/1.0 中，这是默认行为。
