# 13 登录管理

本章为点餐小程序的 Flask 后台管理系统实现完整的登录体系：创建数据库与 `user` 表、用工具自动生成模型类、实现登录接口与加盐加密校验、前端 ajax 异步登录、将登录态写入 Cookie、通过拦截器（`before_request`）统一验证登录、登出，以及登录后的个人信息维护（展示、编辑、修改密码）。

## 13.2 登录接口实现

### 13.2.1 用户名密码非空校验

修改 `web/views/user/User.py`，让 `login` 视图同时支持 GET 与 POST：GET 返回登录页模板，POST 返回 JSON 结果。统一约定响应结构 `{"code": 200, "msg": "...", "data": {}}`，`code` 为 `-1` 表示失败：

```python
@route_user.route("/login", methods=['GET', 'POST'])
def login():
    if request.method == "POST":
        resp = {"code": 200, "msg": "登录成功", "data": {}}
        req = request.values
        login_name = req["login_name"] if "login_name" in req else ""
        login_pwd = req["login_pwd"] if "login_pwd" in req else ""
        if (not login_name) or len(login_name) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入正确的登录用户名"
            return jsonify(resp)
        if (not login_pwd) or len(login_pwd) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入正确的密码"
            return jsonify(resp)

    return render_template("user/login.html")
```

### 13.2.2 密码加密机制：UserService

数据库中不存明文密码。加密与校验约定如下：

- **注册（写入）流程**：先生成用户独有的随机密钥 `login_salt`，再用该盐加密密码，最后把加密后的密码与盐一起入库；
- **登录（认证）流程**：先取出该用户的盐，用同样的机制加密用户输入的密码，再与数据库中存储的密文比较。

在 `common/libs` 目录中创建 `UserService.py`，封装加密逻辑（base64 编码是为了避免密码中的特殊符号影响拼接）：

```python
import base64
import hashlib


class UserService():
    @staticmethod
    def genPwd(pwd, salt):
        # base64加密：密码字符串中可能包含特殊符号
        pwd_base64 = base64.encodebytes(pwd.encode("utf-8"))
        str = f"{pwd_base64}-{salt}"  # 先进行简单的拼接
        # md5加密
        m = hashlib.md5()  # 生成md5实例
        m.update(str.encode("utf-8"))  # 添加加密数据
        return m.hexdigest()  # 获取加密数据
```

### 13.2.3 对接数据库校验登录

在 `login` 视图中追加数据库校验逻辑：按登录名查询用户，查不到或密码校验不通过都返回统一的失败提示：

```python
        # 使用模型验证用户名和密码
        user_info = User.query.filter_by(login_name=login_name).first()
        if not user_info:  # 数据库查不到
            resp["code"] = -1
            resp["msg"] = "请输入正确的用户名或密码"
            return jsonify(resp)

        salt = user_info.login_salt  # 获取加密盐
        gen_pwd = UserService.genPwd(login_pwd, salt)  # 跟注册时相同的加密机制
        if user_info.login_pwd != gen_pwd:
            resp["code"] = -1
            resp["msg"] = "请输入正确的用户名或密码"
            return jsonify(resp)

        # 登录成功
        resp['data']['username'] = login_name
        resp['data']['password'] = login_pwd
        return jsonify(resp)
```

文件头部需要引入模型和服务类：

```python
from web.models.user import User
from common.libs.UserService import UserService
```

## 13.3 前端 ajax 异步登录

登录页不用表单同步提交，改为 ajax 异步请求，步骤如下：

1. 在 `login.html` 中引入登录脚本：

```html
{% block js %}
    <script src="{{ buildStaticUrl('/js/user/login.js') }}"></script>
{% endblock %}
```

2. 把 `login.html` 中的 `form` 标签改为 `div`，按钮类型改为 `button`（避免触发表单默认提交）；
3. 分析 `login.js` 源码，在相应页面标签上添加它依赖的类属性：外层容器加 `.login_wrap`，登录按钮加 `.do-login`。

`login.js` 会在点击 `.do-login` 时读取 `.login_wrap` 内的用户名和密码，做前端非空校验后以 POST 方式异步提交到 `/user/login`，并根据返回的 `code` 弹出提示或跳转。浏览器中用初始账户登录成功后，会弹出"登录成功"提示。

## 13.4 登录状态写入 Cookie

### 13.4.1 配置 Cookie 名称

在配置文件（如 `config/local_setting.py`）中添加：

```python
AUTH_COOKIE_NAME = "mooc_food"
```

### 13.4.2 生成加密的 Cookie 值

Cookie 不能明文存放用户信息，约定值为 `加密串#uid`。在 `UserService.py` 中添加生成加密串的方法——把用户的关键字段拼接后做 md5：

```python
    @staticmethod
    def genAuthCode(user_info):
        """根据用户实例对象生成密钥"""
        str = f"{user_info.uid}-{user_info.login_name}-{user_info.login_pwd}-{user_info.login_salt}"
        m = hashlib.md5()
        m.update(str.encode("utf-8"))
        return m.hexdigest()
```

由于加密串中包含 `login_pwd` 和 `login_salt`，用户修改密码后旧 Cookie 会自动失效，必须重新登录。

### 13.4.3 登录成功时写入 Cookie

直接 `return jsonify(resp)` 无法携带 Cookie，需要改用 `make_response` 构造响应对象再调用 `set_cookie`。同时通过 `max_age` 设置 Cookie 有效期为 7 天：

```python
        # return jsonify(resp)  # 无法携带cookie
        response = make_response(json.dumps(resp))
        # 携带cookie
        cookie_str = UserService.genAuthCode(user_info) + "#" + str(user_info.uid)
        response.set_cookie(current_app.config.get("AUTH_COOKIE_NAME"),
                            cookie_str, max_age=7*24*60*60)
        return response
```

登录成功后，在浏览器中可以看到名为 `mooc_food` 的 Cookie，内容形如 `23cd4d3a12f57ce7944b1f1bfda6010b#1`，即 `md5加密串#用户uid`。

## 13.5 通过拦截器验证是否登录

### 13.5.1 创建拦截器与 check_login

在 `web` 目录下添加 `interceptors` 包，新建 `AuthInterceptor.py`。`check_login()` 负责从 Cookie 中还原并校验登录用户，任何一步不合法都返回 `False`：

```python
from flask import request, current_app, redirect, url_for, g
from application import app
from web.models.user import User
from common.libs.UserService import UserService
import re


def check_login():
    """判断用户是否登录"""
    cookie = request.cookies
    auth_key = app.config["AUTH_COOKIE_NAME"]
    auth_cookie = cookie.get(auth_key) if auth_key in cookie else None
    # 例如：23cd4d3a12f57ce7944b1f1bfda6010b#1
    if not auth_cookie:
        return False

    auth_info = auth_cookie.split("#")
    if len(auth_info) != 2:
        return False

    try:
        userinfo = User.query.filter_by(uid=auth_info[1]).first()
    except:
        return False

    if userinfo is None:
        return False

    # 判断秘钥：用数据库中的用户信息重新生成加密串，与cookie中的对比
    auth_code = UserService.genAuthCode(userinfo)
    if auth_info[0] != auth_code:
        return False

    return userinfo
```

### 13.5.2 before_request 拦截器与白名单

用 Flask 的 `@app.before_request` 钩子实现拦截：先校验登录并把用户存入 `g` 对象，再判断请求路径是否在白名单中，不在白名单且未登录则重定向到登录页：

```python
@app.before_request
def before_request():
    """拦截器"""
    path = request.path
    user_info = check_login()  # 登录校验

    if user_info:
        g.current_user = user_info

    # 获取并构建所有的忽略url列表
    ignore_urls = current_app.config["IGNORE_URLS"]
    ignore_check_login_url = current_app.config["IGNORE_CHECK_LOGIN_URLS"]
    ignore_merge = ignore_urls + ignore_check_login_url

    pattern = re.compile("|".join(ignore_merge))
    if pattern.match(path):
        return None  # return None不做拦截

    if not user_info:  # 没有登录
        return redirect(url_for('user_page.login'))

    return None  # return None不做拦截
```

在配置文件中添加免认证的白名单路由：

```python
# 忽略url
IGNORE_URLS = [
    "^/user/login"
]
# 忽略检查登录 URL
IGNORE_CHECK_LOGIN_URLS = [
    "^/static",
    "^/favicon.icon",
]
```

白名单用 `|` 拼成一个正则并预编译。这里用 `match()` 而不是 `search()`，二者区别：

- `match()`：只从字符串**开头**匹配，`re.compile("^/static/").match("/static/css/style.css")` 成功，匹配 `"/api/static/test"` 失败；
- `search()`：在**整个字符串**中搜索，`search("/api/static/test")` 也能命中 `/static/`，会造成误放行。

用 `match()` 配合 `^` 开头锚点，才能确保只放行真正以白名单前缀开头的路径。另外 `re.compile()` 把正则预编译成模式对象，避免每次匹配时重新编译，提升性能。

### 13.5.4 扩展：在拦截器中记录访问日志

课件的拦截器版本还在登录认证通过后记录访问日志：`g.user = user_info` 之后调用 `LogService.addAccessLog()`。`common/libs/LogService.py` 实现如下（依赖 `AppAccessLog` 模型，可同样用 flask-sqlacodegen 生成）：

```python
from web.models.AppAccessLog import AppAccessLog
from flask import g, request
import json
from datetime import datetime
from application import db


class LogService:
    @staticmethod
    def addAccessLog():
        """添加访问日志，g对象中user中可以获取到用户的uid"""
        target = AppAccessLog()
        if 'user' in g and g.user:
            target.uid = g.user.uid

        target.referer_url = request.referrer
        target.target_url = request.url
        target.query_params = json.dumps(request.values.to_dict())
        target.ua = request.headers.get("User-Agent")[:255]

        target.created_time = datetime.now()
        db.session.add(target)
        db.session.commit()
        return True
```

> 说明：课件这一版实现与正文略有命名差异——加密串方法叫 `genUserCode`（仅拼接 `uid` 与 `login_name` 做 md5），当前用户存入 `g.user`。功能等价，正文按 PDF 的 `genAuthCode` / `g.current_user` 写法整理。

## 13.7 个人信息维护

### 13.7.1 显示当前用户信息：g 对象与 ops_render

拦截器已把登录用户存入 `g.current_user`，为了让每个模板都能直接拿到用户信息，封装一个渲染函数。在 `common/libs` 下创建 `render_helper.py`：

```python
from flask import render_template, g


def ops_render(template, context={}):
    """
    :param template:
    :param context: 字典类型数据
    :return:
    """
    if "current_user" in g:
        context["userinfo"] = g.current_user
    return render_template(template, **context)
```

之后返回首页、用户信息编辑页、重置密码页的视图统一改用 `ops_render()`：

```python
# web/views/index.py
@route_index.route("/")
def index():
    return ops_render("index/index.html")

# web/views/user/User.py
@route_user.route("/edit")
def edit():
    return ops_render("user/edit.html")

@route_user.route("/reset-pwd")
def resetPwd():
    return ops_render("user/reset_pwd.html")
```

模板中即可直接渲染用户数据，例如顶部下拉菜单显示昵称和手机号：

```html
<div class="dropdown-messages-box">
    姓名：{{ userinfo.nickname }}
</div>
<div class="dropdown-messages-box">
    手机号码：{{ userinfo.mobile }}
</div>
```

### 13.7.2 编辑个人信息

编辑页 `edit.html` 的各输入框用 `userinfo` 回填当前值（手机号为 `readonly`，姓名、邮箱可编辑）：

```html
<input type="text" name="mobile" class="form-control" placeholder="请输入手机~~" readonly="" value="{{ userinfo.mobile }}">
<input type="text" name="nickname" class="form-control" placeholder="请输入姓名~~" value="{{ userinfo.nickname }}">
<input type="text" name="email" class="form-control" placeholder="请输入邮箱~~" value="{{ userinfo.email }}">
```

页面底部引入静态资源 `edit.js` 处理保存按钮的异步提交：

```html
{% block js %}
    <script src="{{ buildStaticUrl('/js/user/edit.js') }}"></script>
{% endblock %}
```

后台 `edit()` 视图支持 POST 请求：后端再次验证输入格式，修改入库，最后重新生成 Cookie（因为 `genAuthCode` 依赖用户信息）：

```python
@route_user.route("/edit", methods=['GET', 'POST'])
def edit():
    if request.method == "POST":
        resp = {"code": 200, "msg": "操作成功", "data": {}}

        req = request.values
        nickname = req["nickname"] if "nickname" in req else ""
        email = req["email"] if "email" in req else ""

        if (not nickname) or len(nickname) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入符合规范的姓名"
            return jsonify(resp)
        if (not email) or len(email) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入符合规范的邮箱"
            return jsonify(resp)

        # 修改当前登录人姓名和邮箱（from flask import g）
        user_info = g.current_user
        user_info.nickname = nickname
        user_info.email = email
        # 提交到数据库（from application import db）
        db.session.add(user_info)
        db.session.commit()

        # 用户信息变了，重新生成cookie
        response = make_response(json.dumps(resp))
        cookie_str = UserService.genAuthCode(user_info) + "#" + str(user_info.uid)
        response.set_cookie(current_app.config.get("AUTH_COOKIE_NAME"),
                            cookie_str, max_age=7*24*60*60)
        return response

    return ops_render("user/edit.html")
```

> 如果想要允许修改手机号，把 `input` 标签的 `readonly` 去掉即可，同时 js 和后端都要补充手机号相关的校验与入库处理流程。

### 13.7.3 修改用户密码

修改密码页 `reset_pwd.html` 显示当前账号和手机号（不可改），提供原密码、新密码输入框，并引入 `reset_pwd.js`：

```html
{% block js %}
    <script src="{{ buildStaticUrl('/js/user/reset_pwd.js') }}"></script>
{% endblock %}
```

后台 `resetPwd()` 视图支持 POST：后端验证输入格式，用与登录相同的加盐机制校验原密码，更新密码入库，并生成新 Cookie：

```python
@route_user.route("/reset-pwd", methods=['GET', 'POST'])
def resetPwd():
    if request.method == "POST":
        resp = {"code": 200, "msg": "修改密码成功", "data": {}}
        req = request.values
        old_password = req["old_password"] if "old_password" in req else ""
        new_password = req["new_password"] if "new_password" in req else ""
        if (not old_password) or len(old_password) < 1:
            resp["code"] = -1
            resp["msg"] = "请输入正确的原密码"
            return jsonify(resp)
        if (not new_password) or len(new_password) < 6:
            resp["code"] = -1
            resp["msg"] = "请输入不少于6位的新密码"
            return jsonify(resp)
        if old_password == new_password:
            resp["code"] = -1
            resp["msg"] = "新旧密码一致"
            return jsonify(resp)

        user_info = g.current_user
        salt = user_info.login_salt
        gen_pwd = UserService.genPwd(old_password, salt)  # 跟注册时相同的加密机制
        if user_info.login_pwd != gen_pwd:
            resp["code"] = -1
            resp["msg"] = "原密码不对~"
            return jsonify(resp)

        user_info.login_pwd = UserService.genPwd(new_password, salt)
        # 提交到数据库
        db.session.add(user_info)
        db.session.commit()

        # 生成新的cookie
        response = make_response(json.dumps(resp))
        # 携带cookie
        cookie_str = UserService.genAuthCode(user_info) + "#" + str(user_info.uid)
        response.set_cookie(current_app.config.get("AUTH_COOKIE_NAME"),
                            cookie_str, max_age=7*24*60*60)
        return response

    return ops_render("user/reset_pwd.html")
```
