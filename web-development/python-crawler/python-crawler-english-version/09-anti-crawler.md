# 9 Anti-Crawler

Where there are crawlers, there is anti-crawler. To protect data, keep servers stable, and defend copyright, websites try hard to detect and block crawlers; crawler engineers must recognize these mechanisms and bypass them one by one. This chapter first builds the "anti-crawler vs. anti-anti-crawler" framework, then walks through proxy IPs, dynamic-page sniffing, request disguise techniques, and the Fiddler packet-capture tool.

## 9.1 Overview of Anti-Crawler Mechanisms

Common anti-crawler measures:

| Category | Specific technique |
|---|---|
| IP blocking | Ban an IP after too many requests in a short window |
| Login / captcha | Require login or a captcha to access |
| Account system | Require a registered account with permissions |
| Dynamically loaded data | Data rendered asynchronously by JS/AJAX, absent from static HTML |

## 9.2 Overview of Anti-Anti-Crawler Strategies

Corresponding countermeasures:

| Strategy | Description |
|---|---|
| Disguise as a browser | Forge request headers (User-Agent, Referer, ...) |
| Proxy IPs | Rotate the egress IP to avoid bans |
| Rate limiting | Lower request frequency, add random delays |
| Captcha recognition | OCR / decoding platforms (see chapter 10) |
| Selenium simulation | Render dynamic pages with a real browser (see chapter 8) |

## 9.3 Why Websites Fight Crawlers

- **Data security**: prevent bulk scraping and leakage of core data.
- **Server stability**: high-frequency crawling creates heavy load that hurts real users.
- **Copyright**: content is protected and may not be copied without authorization.

> **Key idea:** Anti-crawler is not "hostile" — it is a website's normal defense. Crawlers should honor robots.txt, throttle requests, and respect the target server, i.e. "crawl politely".

## 9.4 Proxy IPs

### 9.4.1 Definition and Sources

A proxy IP makes requests "on behalf of" your real IP. The request goes to a proxy server first, which forwards it to the target, so the target only sees the proxy's IP. Common free-proxy sources include Xicidaili, Kuaidaili, Quanwangdaili, and Proxyspider.

### 9.4.2 Classification by Anonymity

| Type | Target sees the real IP | Target knows a proxy is used |
|---|---|---|
| Transparent proxy | Yes | Yes |
| Anonymous proxy | No (hides the real IP) | Yes |
| Elite (high-anonymity) proxy | No | No (fully invisible) |

> **Key idea:** Anonymity order: transparent < anonymous < elite. Crawlers usually use elite proxies, because a transparent proxy still leaks your real IP.

### 9.4.3 Classification by Commercial Type

| Type | Availability | Speed | Price | Use case |
|---|---|---|---|---|
| Regular proxy | Low | Slow | Cheap | Testing, learning |
| Private proxy | Medium | Medium | Medium | Common for crawling |
| Dedicated proxy | Very high | Fast | Expensive | High-demand production |

### 9.4.4 Using a Regular Proxy with requests

```python
import requests

proxies = {
    'http': 'http://<ip>:<port>',
    'https': 'https://<ip>:<port>',
}
html = requests.get(url, proxies=proxies, headers=headers, timeout=5).text
```

> **Correction:** The free proxy `112.85.164.220:9999` in the source is long dead. Free proxies have a very short lifespan — get and test them yourself first. The code uses `<ip>:<port>` as a placeholder.

### 9.4.5 Using a Private/Dedicated Proxy with requests

Private and dedicated proxies need authentication, in the form `http://user:pass@IP:port`:

```python
proxies = {
    'http': 'http://<username>:<password>@<ip>:<port>',
    'https': 'https://<username>:<password>@<ip>:<port>',
}
html = requests.get(url, proxies=proxies, headers=headers, timeout=5).text
```

> **Note:** Proxy credentials are sensitive. Do not hard-code them into committed code; use environment variables or a config file.

### 9.4.6 Building a Proxy IP Pool

Free proxies are unstable, so maintain a "pool": scrape free proxies → test availability → save the good ones to a file → pick at random and refresh periodically.

```python
import random
import requests

def get_available_proxies():
    """Read available proxies from a file; in practice, scrape and test them first."""
    with open('proxies.txt', 'r', encoding='utf-8') as f:
        return [line.strip() for line in f if line.strip()]

def fetch(url):
    proxies_list = get_available_proxies()
    proxy = random.choice(proxies_list)          # pick one at random
    proxies = {'http': proxy, 'https': proxy}
    try:
        return requests.get(url, proxies=proxies, timeout=5).text
    except Exception:
        return fetch(url)                        # try the next one on failure
```

## 9.5 Static vs Dynamic Pages

| Aspect | Static page | Dynamic page |
|---|---|---|
| Data source | Rendered by the server into the response | Generated by JS/AJAX partial refresh |
| How to crawl | Parse HTML directly | Hit the API or use Selenium |
| Signature | Data is present in `response.text` | "Load more" buttons; data visible in Elements but absent from the response |

Signs of a dynamic page: a "Load more" button, data visible in DevTools' Elements panel but not found in the Response, and AJAX-based async loading.

## 9.6 Console Sniffing (F12)

The browser's DevTools is the key tool for reverse-engineering dynamic pages. Key panels after pressing F12:

| Panel | Purpose |
|---|---|
| Network → ALL/XHR/JS | All requests / only XHR / only JS |
| Headers → General | URL, method, status code |
| Headers → Response Headers | Response headers |
| Headers → Request Headers | Request headers (UA, Referer, Cookie) |
| Headers → Query String / Form Data | GET query params / POST form data |
| Preview / Response | Preview / raw response body |
| Sources | Breakpoint debugging of JS |
| Console | Interactive JS testing |

## 9.7 AJAX + JSON Dynamic-Page Workflow

AJAX (Asynchronous JavaScript And XML) updates part of a page asynchronously without a full reload; JSON is a lightweight cross-language data format that almost all modern APIs return.

The fixed workflow for dynamic pages:

1. Request the target URL and open the F12 Network panel.
2. Switch to XHR and observe which API requests fire.
3. Identify the real data endpoint (usually returns JSON).
4. Request that endpoint directly with requests.
5. Parse the returned JSON.
6. Persist the data.

```python
import requests
import json

# assume this is the data endpoint found in F12 (copy URL/params/headers from capture)
api = 'https://example.com/api/list'
headers = {'User-Agent': '<your-ua>'}
resp = requests.get(api, params={'page': 1}, headers=headers, timeout=5)
data = resp.json()   # most endpoints return JSON directly
with open('data.json', 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

## 9.8 Common Anti-Crawler Mechanisms and Responses

### 9.8.1 User-Agent Anti-Crawler and a UA Pool

The server uses the User-Agent to judge the request source, and blocks non-browser UAs. Add a UA before requesting; the advanced approach keeps a pool of UAs and rotates them.

```python
import random
import requests

def get_ua():
    """Randomly generate a Chrome User-Agent"""
    chrome = [
        'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36',
        '(KHTML, like Gecko) Chrome/{major}.0.0.0 Safari/537.36',
    ]
    major = random.randint(90, 120)
    return chrome[0] + ' ' + chrome[1].format(major=major)

headers = {'User-Agent': get_ua()}
resp = requests.get(url, headers=headers, timeout=5)
```

> **Key idea:** The core of a UA is `Mozilla/5.0 ... Chrome/x.x Safari/537.36`. Randomizing the Chrome major version simulates different users.

### 9.8.2 Referer Anti-Crawler

The Referer indicates the page that made the request; some servers validate it to prevent hotlinking of images/APIs. Add the correct `Referer` header:

```python
headers = {
    'User-Agent': get_ua(),
    'Referer': 'https://example.com/detail/123',   # the page the data came from
}
resp = requests.get(img_url, headers=headers, timeout=5)
```

### 9.8.3 Cookie/Session and Simulated Login

Cookies record identity on the client; Sessions record state on the server. Together they implement "session tracking" — the server recognizes you by the Session ID in the cookie. For login-gated sites, there are three ways to simulate login with cookies:

**Method 1: copy the Cookie into headers after logging in**

```python
headers = {
    'User-Agent': get_ua(),
    'Cookie': '<cookie string copied from the browser after login>',
}
resp = requests.get(url, headers=headers)
```

**Method 2: pass a `cookies` dict**

```python
cookies = {'sessionid': '<value>', 'token': '<value>'}
resp = requests.get(url, cookies=cookies, headers=headers)
```

**Method 3: `requests.session()` for session persistence (recommended)**

```python
import requests

session = requests.session()   # keeps cookies across requests automatically
session.post(
    post_url,
    data={'email': '<account>', 'password': '<password>'},
    headers=headers,
)
resp = session.get(url, headers=headers)   # carries the login cookie automatically
```

> **Key idea:** A `session` object automatically saves and sends the cookies the server returns, so after a simulated login you never manage cookies manually — this is the most common approach.

### 9.8.4 Request-Parameter Anti-Crawler

Some endpoint parameters are generated dynamically. Three common ways to obtain them:

| Method | When it applies |
|---|---|
| Parse parameters from the static HTML | Params hidden in the source (e.g. GitHub's `authenticity_token`) |
| Fetch parameters via a prior request | Params returned by a previous request |
| JS-generated parameters | Params computed by JS — use `js2py` or Selenium |

### 9.8.5 Captcha Anti-Crawler (Principle)

When the server decides you are "not human" (high frequency, no cookies, ...), it shows a captcha that must be solved to continue. Solutions include decoding platforms and machine-learning recognition — **the actual recognition is covered in chapter 10**; this chapter only treats it as one anti-crawler measure.

### 9.8.6 CSS Anti-Crawler

The source does not contain the real data; the real content is assembled via CSS displacement (custom fonts + offset properties). The trick is to analyze the offsets and restore the data:

```python
# idea: put each character back according to its CSS offset
def restore(text, offsets):
    result = [''] * len(text)
    for i, off in enumerate(offsets):
        result[i] = text[i + off]   # place it back by offset
    return ''.join(result)
```

### 9.8.7 JS-Generated-Data Anti-Crawler

Data is computed in the browser by a key JS script. The trick: locate the generating script → analyze how it produces the data → replicate the algorithm in Python (or run the JS with `js2py`, or render with Selenium).

### 9.8.8 Encoding Anti-Crawler

When a server returns a non-`utf-8` encoding, you get garbled text or errors. Try decoding with multiple encodings:

```python
resp = requests.get(url, headers=headers)
# prefer the encoding declared in the response, then try manually
for enc in ['utf-8', 'gbk', 'gb2312', 'latin-1']:
    try:
        text = resp.content.decode(enc)
        break
    except UnicodeDecodeError:
        continue
```

## 9.9 Fiddler Packet Capture

Fiddler is a local HTTP/HTTPS capture tool. It sets up a proxy on your machine (default `127.0.0.1:8888`) to intercept and record all passing traffic, which is handy for analyzing the APIs of mobile and desktop clients.

### 9.9.1 How It Works and Configuration

- **Principle**: Fiddler acts as a local proxy — apps send requests to Fiddler, Fiddler forwards them to the target server and back, recording all traffic along the way.
- **Installation**: download the installer from the official site (it has moved — search "Telerik Fiddler" for the current URL).
- **Configuration**: `Tools > Options > Connections` sets the listening port (default `8888`); for HTTPS capture, enable "Decrypt HTTPS traffic" under the `HTTPS` tab and install the certificate.

## Summary Mnemonic

- **Four anti-crawler tricks:** IP blocking, login/captcha, account system, dynamic loading.
- **Five counter-tricks:** browser disguise, proxies, rate limiting, captcha recognition, Selenium.
- **Proxy anonymity:** transparent (leaks IP) < anonymous (hides IP) < elite (invisible).
- **Proxy format:** regular `http://<ip>:<port>`; authenticated `http://<username>:<password>@<ip>:<port>`.
- **Dynamic-page workflow:** request → sniff XHR in F12 → identify endpoint → request → parse JSON → persist.
- **Three login methods:** Cookie in headers / `cookies=` argument / `requests.session()` persistence.
- **Three parameter sources:** static HTML, a prior response, JS generation.
- **Fiddler:** local proxy `127.0.0.1:8888`; enable Decrypt + install cert for HTTPS.
