# 16 JS 逆向与调试绕过

很多网站不再直接返回明文数据，而是把请求参数加密、把响应体加密，再用 JS 在浏览器里加解密。所谓"逆向"，就是在看不懂对方源码的情况下，通过抓包、断点、阅读混淆 JS，还原出加解密算法，然后用 Python 复刻调用，从而绕过这层防护。本章梳理逆向的通用思路、常用加密算法（MD5 / base64 / AES / SHA-256 / RC4）、sign 签名、无限 debugger 绕过，以及如何让 Python 稳定地执行 JS。

## 16.1 逆向的概念与定位思路

### 16.1.1 什么是 JS 逆向

> **核心要点：** 反反爬 = 看懂网站加密 JS，并用 Python 复刻算法来绕过它。

浏览器里的请求是"明文可读"的，但服务器返回给爬虫的往往经过 JS 加密。逆向的目标不是攻破加密本身，而是**把浏览器自动完成的那段加解密 JS 找出来、读懂、再让 Python 也能执行同样的逻辑**。

### 16.1.2 逆向定位思路

1. 打开开发者工具（F12）的 Network 面板，刷新页面。
2. 找到真正返回数据的 XHR / Fetch 请求（而不是页面本身）。
3. 观察请求参数与响应体：哪些是明文（页码、关键词），哪些是乱码。
4. 对乱码参数，用"键名"在 Sources 里全局搜索，定位生成它的 JS。
5. 在可疑位置打断点，刷新页面，逐步跟踪变量，还原算法。

## 16.2 加密参数的识别

判断一个参数是否需要逆向，先看它"像不像加密"：

| 特征 | 说明 |
|---|---|
| 明文参数 | 页码 `page`、关键词 `kw`、分类 `cid`，值可读、固定 |
| 加密参数 | 长串乱码，或每次请求都变化（掺了时间戳、随机数） |
| 常见键名 | `sign`、`token`、`_signature`、`encrypt`、`encode` |

> **核心要点：** 键名是线索。看到 `sign` / `_signature` 基本可断定是签名，看到 `encrypt` / `encode` 多半是加密，看到 `ts` / `timestamp` / `nonce` 是时间戳与随机数。

变化的那部分（时间戳、随机数）说明加密过程里有"动态输入"，这正是断点调试时重点观察的变量。

## 16.3 逆向的三大方案

拿到一个加密参数后，有三种落地方式：

| 方案 | 做法 | 优缺点 |
|---|---|---|
| ① Python 还原逻辑 | 用 `hashlib`、`pycryptodome` 在 Python 里重写算法 | 无需 Node，跨平台，但费时且算法复杂时易出错 |
| ② 扣 JS 代码 | 把加密函数从原站 JS 里"抠"出来，用 `execjs` 调用 | 最快最稳，但依赖 Node 环境 |
| ③ 第三方模块 | 用网上现成的逆向库/模块 | 省事，但可能失效或不可控 |

> **核心要点：** 三者的统一套路是——**定位加密参数 → 按键名搜 JS 文件 → 断点调试找算法 → 复刻或抠出**。方案①②只是最后"落地"环节的不同选择。

## 16.4 Node.js 环境与 crypto-js

方案②（扣 JS）需要在本地能运行 JS，这依赖 Node.js。常用的前端加密库是 `crypto-js`：

```bash
npm install -g crypto-js
```

安装后写一个 `pwd.js`：

```js
// pwd.js：MD5 加密（供 Python 用 execjs 调用）
var crypto = require('crypto-js');
function f1(mima) {
  return crypto.MD5(mima).toString();
}
```

> **注意：** `require('crypto-js')` 需要从能解析到该包的位置运行；全局安装（`-g`）便于在任意目录用 `node pwd.js` 测试，也可以 `npm install crypto-js` 装到当前目录。

## 16.5 Python 执行 JS：PyExecJS

`PyExecJS` 是 Python 调用 JS 的桥接库，它背后其实启动了一个本地 JS 运行时（默认优先 Node.js）。

```bash
pip install PyExecJS
```

### 16.5.1 基本调用

```python
import execjs

# 内联 JS
ctx = execjs.compile("function f(){return 111}")
print(ctx.call('f'))           # 111

# 从 .js 文件读取后调用
js = open('pwd.js', encoding='utf-8').read()
res = execjs.compile(js).call('f1', '123456')
print(res)                     # e10adc3949ba59abbe56e057f20f883e
```

`compile(js)` 得到上下文，`call(函数名, 参数...)` 调用 JS 函数并返回结果。

> **注意：** `PyExecJS` 已停止维护，跨环境（尤其新版本 Node）可能找不到运行时。备选方案见 16.14。

### 16.5.2 指定本地 Node 运行时

当默认运行时缺失或版本不匹配时，可以手动指定 Node 可执行文件路径：

```python
import execjs
from execjs import _runner_sources as runner_sources

rt = execjs.ExternalRuntime(
    name="Node.js (local)", command='', encoding='UTF-8',
    runner_source=runner_sources.Node)
rt._binary_cache = [r'C:\Program Files\nodejs\node.exe']   # node.exe 实际路径
rt._available = True
execjs.register('local_node', rt)
nodejs = execjs.get('local_node')

# 之后可用 nodejs.eval(js) 或 nodejs.compile(js).call('f', ...)
print(nodejs.eval("1 + 1"))   # 2
```

> **勘误：** 这段代码依赖 `ExternalRuntime` 的私有属性 `_binary_cache` / `_available`，属于未公开的 hack，跨版本极易失效。更稳妥的做法是直接用 `subprocess` 调用 `node` 命令，或换用 `py_mini_racer` / `js2py` 等仍在维护的库。

## 16.6 常用加密算法速览

逆向里最常见的算法就是 MD5、base64、AES，以及稍少见的 SHA-256、RC4。先掌握"JS 怎么写、Python 怎么写"的对照，才能一眼认出扣下来的 JS 在干什么。

| 算法 | JS（crypto-js） | Python |
|---|---|---|
| MD5 | `crypto.MD5(s).toString()` | `hashlib.md5(s.encode()).hexdigest()` |
| SHA-256 | `crypto.SHA256(s).toString()` | `hashlib.sha256(s.encode()).hexdigest()` |
| base64 | `crypto.enc.Base64.stringify(...)`（或浏览器 `btoa`） | `base64.b64encode(...)` |
| AES | `crypto.AES.encrypt` / `crypto.AES.decrypt` | `pycryptodome` 的 `AES` |

## 16.7 MD5 加密：JS 与 Python 对照

MD5 是不可逆的摘要算法，常用于密码与签名。

```js
// JS 侧（crypto-js）
var crypto = require('crypto-js');
function f1(mima) {
  return crypto.MD5(mima).toString();
}
```

```python
# Python 侧
import hashlib

s = hashlib.md5()
s.update('123456'.encode())
print(s.hexdigest())          # e10adc3949ba59abbe56e057f20f883e
```

> **勘误：** 源课件注释里 `var crypot = require('crypto-js')` 把 `crypto` 拼成了 `crypot`，正确写法是 `crypto`。

微信公众号登录即典型应用：把密码 MD5 后 POST 到登录接口，并生成 `fingerprint = md5(UA + 8 位随机整数)`。

```python
import hashlib, random

def get_fingerprint(ua):
    rand = str(random.randint(0, 99999999)).zfill(8)
    return hashlib.md5((ua + rand).encode()).hexdigest()
```

> **勘误：** 源课件把 `fingerprint` 硬编码成 `'6f30a0770ecc9964c3b9927f773cc45a'`，并未调用同文件里已写好的 `get_fingerprint()`；正确做法是每次用 `md5(UA + 随机8位)` 动态生成。

## 16.8 base64 编码与 btoa

base64 是"可逆编码"，常用来给参数做个不让人一眼看穿的壳。浏览器里用 `btoa()`，Python 里用 `base64` 模块。

> **勘误：** `btoa` 是**浏览器 API**，Node 环境没有这个函数（Node 里可用 `Buffer.from(s).toString('base64')` 或自行实现）。这也正是源课件里 `demo.py` 改用 Python 重写这段逻辑的原因。

Virustotal 的 `x-vt-anti-abuse-header` 就是 `btoa(随机数 - 固定串 - 时间戳)`：

```python
import base64, random, time

rand = (1 + random.random() % 50000) * 10**10
raw = f"{rand}-<固定串>-{int(time.time())}"
b64 = base64.b64encode(raw.encode()).decode('utf-8')
headers = {'x-vt-anti-abuse-header': b64}
```

> **勘误：** 源课件 `rand = (1 + random.random() % 50000) + 10**10` 与 JS `(1 + Math.random() % 5e4) * 1e10` 不等价（丢了乘法、优先级错），应为 `(1 + random.random() % 50000) * 10**10`。
>
> **勘误：** `base64.b64encode(...)` 返回 `bytes`，直接塞进 headers 会带 `b'...'`，应先 `.decode('utf-8')`。

## 16.9 AES 加解密（crypto-js）

AES 是分组对称加密，需要 `key`、`iv`、模式（常用 CBC）与填充（常用 Pkcs7）。逆向时经常遇到"请求参数加密"与"响应密文解密"两种用法。

### 16.9.1 AES 解密响应密文

服务端把响应加密成密文，前端 JS 解密后再渲染。扣出解密函数：

```js
// get_response.js：解密响应密文并解析成 JSON
var crypto = require('crypto-js');

function b(t) {
  var e = crypto.enc.Utf8.parse('<32字节密钥>');     // key（脱敏）
    , n = crypto.enc.Utf8.parse('<16字节IV>');       // iv（脱敏）
    , a = crypto.AES.decrypt(t, e, {
        iv: n, mode: crypto.mode.CBC, padding: crypto.pad.Pkcs7
      });
  return a.toString(crypto.enc.Utf8);
}

function get_response(mi) {
  return JSON.parse(b(mi));
}
```

> **核心要点：** `enc.Utf8.parse` 把字符串转成 WordArray，`enc.Base64.stringify` / `enc.Utf8.parse` 负责编码转换，`toString(crypto.enc.Utf8)` 把解密结果还原为可读文本。key/iv 长度决定 AES-128 / 192 / 256。

### 16.9.2 AES 加密生成请求参数

反向操作：把时间戳用 AES 加密后作为请求头，服务端再解密校验：

```js
function getResCode() {
  var c = crypto.AES.encrypt(
    crypto.enc.Utf8.parse(String(Math.floor(new Date().getTime() / 1000))),
    crypto.enc.Utf8.parse('1234567887654321'),        // 示例 key（16 字节）
    { iv: crypto.enc.Utf8.parse('1234567887654321'),  // 示例 iv
      mode: crypto.mode.CBC, padding: crypto.pad.Pkcs7 });
  return crypto.enc.Base64.stringify(c.ciphertext);   // Accept-EncKey
}
```

> **核心要点：** 加密结果取 `c.ciphertext`（去掉 WordArray 的元信息）再 base64，作为 `Accept-EncKey` 请求头。

## 16.10 SHA-256 与 RC4 结构骨架

- **SHA-256** 与 MD5 同为摘要算法，但更安全，`hashlib.sha256(b'...').hexdigest()` 即可。
- **RC4** 是流式对称加密，核心是一个 256 字节 S 盒的置换（KSA 初始化 + PRGA 加密）。在 ob 混淆里，RC4 常用来解密字符串数组（详见第 17 章）。

```python
def rc4(key: bytes, data: bytes) -> bytes:
    S = list(range(256))
    j = 0
    for i in range(256):                 # KSA：用 key 打乱 S 盒
        j = (j + S[i] + key[i % len(key)]) % 256
        S[i], S[j] = S[j], S[i]
    i = j = 0
    out = []
    for ch in data:                      # PRGA：逐字节异或
        i = (i + 1) % 256
        j = (j + S[i]) % 256
        S[i], S[j] = S[j], S[i]
        out.append(ch ^ S[(S[i] + S[j]) % 256])
    return bytes(out)
```

## 16.11 参数签名 sign 逆向

很多接口要求把参数排序、拼接、加盐后再 MD5，作为 `sign`（或 `portal-sign`）请求头，防止参数被篡改。典型算法：

```js
function l(t, e) {                       // 忽略大小写比较 key
  var a = t.toString().toUpperCase(), b = e.toString().toUpperCase();
  return a > b ? 1 : a == b ? 0 : -1;
}
function u(t) {                          // 排序后拼接 key=value
  var ks = Object.keys(t).sort(l), n = "";
  for (var i = 0; i < ks.length; i++) n += ks[i] + t[ks[i]];
  return n;
}
function d(t) {                          // sign = MD5(盐 + 拼接串) 小写
  var n = "<固定盐>" + u(t);
  return crypto.MD5(n).toString().toLocaleLowerCase();
}
```

用 Python 复刻（注意 `sort` 用 `key=str.upper` 达到忽略大小写排序）：

```python
import hashlib

def sign(params: dict) -> str:
    salt = "<固定盐>"
    joined = ''.join(k + str(params[k])
                     for k in sorted(params, key=str.upper))
    return hashlib.md5((salt + joined).encode()).hexdigest()
```

> **核心要点：** 签名三步——**排序、拼接、加盐 MD5**。盐是固定串（源课件为某真实站点盐，此处脱敏为 `<固定盐>`），排序规则必须与前端完全一致，否则签名对不上。

## 16.12 综合案例：加密请求与密文解密

把前面的片段串起来：先算 `sign` 与 `Accept-EncKey`，发起请求，再解密响应里的 `Data` 密文。

```python
import execjs, requests

# 抠出的算法：加密请求头 + 解密响应
js = open('get_response.js', encoding='utf-8').read()
ctx = execjs.compile(js)

params = {'page': 1, 'keyword': '<关键词>'}
headers = {
    'User-Agent': '<UA>',
    'portal-sign': sign(params),                 # 用 Python 复刻的 sign
    'Accept-EncKey': ctx.call('getResCode'),     # 用 JS 生成的加密头
}

resp = requests.get('<接口地址>', params=params, headers=headers).json()
plain = ctx.call('get_response', resp['Data'])   # 解密响应密文
print(plain)
```

> **核心要点：** 逆向是"混合"的：能复刻的（sign）用 Python，复杂或易变的（AES）扣 JS 交给 `execjs`，二者配合完成一次完整请求。

## 16.13 无限 debugger 的原理与绕过

### 16.13.1 原理

网站会在页面 JS 里塞入 `debugger` 关键字，配合定时器或死循环，让打开开发者工具的爬虫/研究者不断断点卡死：

```js
// 反调试代码（示意）
setInterval(function () { debugger; }, 100);
// 或
while (true) { debugger; }
```

只要 DevTools 处于断点监听状态，`debugger` 就会触发暂停，形成"无限断点"。

### 16.13.2 绕过四法

| 方法 | 操作 |
|---|---|
| ① 全局禁用断点 | 点击 DevTools 的 "Deactivate breakpoints"（或 Ctrl+F8） |
| ② Never pause here | 在 `debugger` 那行右键 → "Never pause here" |
| ③ 条件断点写 `false` | 右键该行 → "Add conditional breakpoint"，填 `false` |
| ④ Fiddler 改写响应 | 用代理把响应 JS 里的 `debugger` 替换成空串后再返回 |

> **注意：** 方法①~③ 是调试时的临时手段；方法④ 是绕过反调试的"釜底抽薪"，但会改变页面逻辑，仅用于研究。

## 16.14 PyExecJS 的局限与替代方案

当 `PyExecJS` 的默认运行时不可用，又不想碰私有 API 时，可以直接用 `subprocess` 调 `node`：

```python
import subprocess

def call_js(js_path: str, func: str, arg: str) -> str:
    # 需在 js_path 末尾追加一句 console.log(func(arg))
    cmd = ['node', '-e',
           f"const f=require('{js_path}');console.log(f.{func}('{arg}'))"]
    return subprocess.check_output(cmd, text=True).strip()
```

备选库对比：

| 方案 | 说明 |
|---|---|
| `subprocess` + `node` | 最可控，跨版本稳定，但每次调用有进程开销 |
| `py_mini_racer` | 内嵌 V8，无需外部 Node，维护较活跃 |
| `js2py` | 纯 Python 实现，无需 Node，但性能与兼容性有限 |

**记忆口诀**

- **定位三步：** 找接口 → 辨明文/加密 → 按签名键名搜 JS。
- **落地三选：** Python 复刻 / 扣 JS 用 execjs / 第三方模块。
- **算法四件套：** MD5、base64、AES(CBC/Pkcs7)、SHA-256/RC4。
- **签名套路：** 排序 + 拼接 + 加盐 + MD5。
- **debugger 四绕过：** 禁用断点 / Never pause here / 条件断点 false / Fiddler 改写。
