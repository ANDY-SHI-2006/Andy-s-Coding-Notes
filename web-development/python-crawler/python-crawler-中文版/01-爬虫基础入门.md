# 1 爬虫基础入门

爬虫是自动化获取网页数据的核心技术。本章先建立对爬虫的整体认知——它是什么、分几类、怎么工作，再掌握浏览器抓包工具，为后续章节打好地基。

## 1.1 什么是网络爬虫

**网络爬虫**（Web Crawler），又称网页蜘蛛（Spider）、网络机器人（Web Robot）或网页追逐者，是一种**按照一定规则自动抓取万维网信息的程序或脚本**。

| 别名 | 说明 |
|------|------|
| 网络爬虫 / 网页蜘蛛 | 最常用叫法 |
| 网络机器人 | 强调「自动」属性 |
| 网页追逐者 | 强调「抓取」动作 |

它的本质是一段程序：向目标网站发出请求，拿到返回的网页内容，再按规则把需要的数据提取出来。

## 1.2 爬虫与搜索引擎

搜索引擎（如百度、Google）本身就是超大规模的爬虫。以**百度蜘蛛（Baiduspider）**为例，它做三件事：

| 步骤 | 说明 |
|------|------|
| 爬取 | 不断抓取互联网上的网页 |
| 收录 | 把抓到的网页存进索引库 |
| 排序 | 用户搜索时按算法给结果排序 |

> **核心要点：** 搜索引擎会「爬取 → 收录 → 排序」。哪些网页能被爬取、去重、优先收录，都由爬虫算法决定。

网站排名与「访问权重（pv，即页面浏览量）」相关：访问量大、内容优质的网页更容易被收录并排到前面。这个概念只需了解即可，不需要深入算法细节。

## 1.3 数据从哪来

做数据工作，数据有四种常见来源：

| 来源 | 例子 | 特点 |
|------|------|------|
| 第三方购买 | 企查查等商业数据服务 | 花钱，省力 |
| 免费下载 | 国家统计局公开数据 | 免费但范围固定 |
| 爬虫爬取 | 自己写程序抓取 | 灵活，效率最高 |
| 人工收集 | 手动复制粘贴 | 慢，易出错 |

> **核心要点：** 四种来源里，**爬虫爬取的效率最高**——一次写好脚本，可以反复、批量、自动地获取数据。

## 1.4 爬虫与黑客

爬虫和黑客在技术上有相似之处（都要研究请求、抓包、绕过限制），但**行为和目的完全不同**。

| 维度 | 爬虫 | 黑客 |
|------|------|------|
| 目标 | 采集公开数据 | 入侵、破坏、窃取 |
| 合法性 | 合法合规的采集 | 违法行为 |
| 破坏性 | 无 | 有 |

> **勘误：** 原课件用「爬虫 = 男朋友、黑客 = 强奸犯」这类不恰当比喻来类比，容易误导。建议改用上表的中性对比：**技术相似，但爬虫是合法采集公开数据，黑客是非法入侵破坏**，二者本质是目的不同。

## 1.5 大数据、应用前景与能抓什么

**大数据与爬虫**：抓取的数据量越大，与大数据的关联就越紧密——爬虫是大数据的重要数据来源之一。

爬虫的常见应用场景：

| 场景 | 例子 |
|------|------|
| 人脸识别 | 建立人脸图库供模型训练 |
| 市场分析 | 抓商品价格、评价做竞品分析 |
| 市场监控 | 监控价格波动、库存变化 |
| 商机发现 | 抓招聘、招标信息找机会 |
| 金融股票 | 抓取行情、财报做分析 |

爬虫能抓到的数据，本质是「能请求到就能获取」：

| 数据类型 | 例子 |
|----------|------|
| 网页文本 | 新闻、商品标题、评论 |
| 图片 | 商品图、表情包 |
| 视频 / 音频 | 短视频、音乐 |
| 其他 | 各类接口返回的 JSON 数据 |

> **核心要点：** 「万物皆可爬，可视即可爬」——只要浏览器能看到的公开数据，理论上都能用爬虫获取。

## 1.6 爬虫的分类

爬虫按用途通常分为四类：

| 分类 | 说明 | 典型代表 |
|------|------|----------|
| 通用爬虫 | 抓取全网网页 | 搜索引擎（百度蜘蛛） |
| 聚焦爬虫 | 只抓特定主题 / 特定网站 | 本课程学习的重点 |
| 增量式爬虫 | 只抓变化或新增的内容 | 定时更新新闻 |
| 深层爬虫 | 抓表单提交后才能看到的深层页面 | 需要登录/搜索的页面 |

> **勘误：** 原课件出现口径不一致——有的材料写「3 类（通用/聚焦/增量）」，有的写「4 类」。统一采用 **4 类**（通用 / 聚焦 / 增量式 / 深层），深层爬虫作为补充了解项。

### 1.6.1 表层页面 vs 深层页面

| 页面类型 | 说明 |
|----------|------|
| 表层页面 | 通过静态链接可以直接到达的页面 |
| 深层页面 | 需要提交关键词（表单、搜索）才能获取的页面 |

深层页面的数量**远多于**表层页面——大量内容「藏在」搜索框和表单之后。

## 1.7 通用爬虫与聚焦爬虫的原理

### 1.7.1 通用爬虫原理

通用爬虫（搜索引擎）的完整流程分四步：

| 步骤 | 内容 |
|------|------|
| 1. 抓取网页 | URL 队列 → 解析 DNS → 下载并存储页面 |
| 2. 数据存储 | 把抓到的原始页面存起来 |
| 3. 预处理 | 提取文字、中文分词、消噪、建索引、计算链接关系、处理特殊文件 |
| 4. 提供检索 | 用户搜索时返回结果并排序 |

### 1.7.2 聚焦爬虫原理

聚焦爬虫是本课程的核心。它的流程可以概括为四步：

```
start_url 发请求 → 获取响应 → 解析 → 保存数据
```

如果解析时发现了新的目标 URL，就把它加入队列，重复上述过程：

```python
# 聚焦爬虫通用骨架（伪代码）
def crawl(start_url):
    url_queue = [start_url]                     # 待抓 URL 队列
    seen = set()                                 # 去重集合
    while url_queue:
        url = url_queue.pop(0)                   # 取一个 URL
        if url in seen:
            continue
        seen.add(url)
        resp = requests.get(url, headers=HEADERS)  # 1. 发起请求
        html = resp.text                           # 2. 获取响应内容
        items, new_urls = parse(html)              # 3. 解析：提取数据 + 发现新链接
        save(items)                                # 4. 保存数据
        url_queue.extend(new_urls)                 # 新链接入队，继续循环
```

> **核心要点：** 聚焦爬虫四步——**发请求 → 得响应 → 解析 → 保存**，这是贯穿全课程的主线。

## 1.8 robots 协议

**robots 协议**（Robots Exclusion Protocol，网络爬虫排除标准）是网站用来告知爬虫「哪些页面可以抓、哪些不可以抓」的约定，一般写在站点根目录的 `robots.txt` 文件里。

| 属性 | 说明 |
|------|------|
| 性质 | 君子协定，仅道德层面约束 |
| 约束力 | 没有法律强制力，但应遵守 |
| 作用 | 指明允许/禁止抓取的范围 |

> **注意：** robots 协议靠自觉遵守，不代表「写了就不能抓」。但作为开发者，应尊重网站的意愿，避免给服务器造成压力。

## 1.9 爬虫的基本流程

把聚焦爬虫展开，就是四步主线（对应课件第 10 页）：

| 步骤 | 动作 | 对应工具 |
|------|------|----------|
| 1. 发起请求 | 向目标 URL 发送 HTTP 请求 | `requests` |
| 2. 获取响应 | 拿到服务器返回的内容 | `response` |
| 3. 解析内容 | 从响应中提取想要的数据 | 正则 / BS4 / XPath |
| 4. 保存数据 | 把结果持久化 | 文件 / 数据库 |

### 1.9.1 Request 的组成

一次 HTTP 请求（Request）由四部分组成：

| 组成 | 说明 | 例子 |
|------|------|------|
| 请求方式 | HTTP 方法 | GET、POST、HEAD、PUT、DELETE、OPTIONS |
| 请求头 | 附加信息 | User-Agent、Host、Cookies |
| 请求 URL | 目标地址 | `https://www.baidu.com` |
| 请求体 | 提交的数据 | 表单数据（POST 时） |

### 1.9.2 Response 的组成

服务器返回的响应（Response）由三部分组成：

| 组成 | 说明 | 例子 |
|------|------|------|
| 响应状态 | 状态码 | 200、301、404、502 |
| 响应头 | 元信息 | 内容类型、长度、服务器、Set-Cookie |
| 响应体 | 实际内容 | HTML 文本、图片二进制 |

> **核心要点：** 请求四件套 = 方式 + 头 + URL + 体；响应三件套 = 状态 + 头 + 体。

## 1.10 解析与保存数据的方式

拿到响应后，解析数据（第 3 步）有多种方式：

| 解析方式 | 适用场景 |
|----------|----------|
| 正则表达式 | 简单、精确的文本匹配 |
| BeautifulSoup | 结构化的 HTML/XML 解析（易上手） |
| XPath | 按路径定位节点，配合 lxml |
| PyQuery | 类 jQuery 的语法 |
| JSON 解析 | 处理接口返回的 JSON |
| 直接处理 | 内容简单时直接字符串处理 |

保存数据（第 4 步）的方式：

| 保存方式 | 例子 |
|----------|------|
| 文本文件 | 纯文本、JSON、XML |
| 关系型数据库 | MySQL、Oracle、SQL Server |
| 非关系型数据库 | MongoDB、Redis |
| 二进制文件 | 图片、视频、音频 |

## 1.11 Chrome 抓包工具基础

抓包（分析网络请求）是爬虫的基本功。Chrome 开发者工具（F12）里的 **Network** 面板就是最常用的抓包工具。

### 1.11.1 新建隐身窗口

分析一个网站时，建议先开**隐身窗口**（无痕模式）：首次请求不携带 cookie，能尽量还原「代码第一次请求网站」的结果，避免已有登录态干扰分析。

### 1.11.2 Preserve log（保留日志）

页面跳转后，跳转前的请求会被清掉。勾选 **Preserve log** 后，跳转前的请求 URL 会被保留下来，方便回看。

### 1.11.3 使用 filter 过滤

一个页面可能发起几十上百个请求。在 filter 输入框里输入部分 URL 关键字，就能过滤出想要的请求。

### 1.11.4 观察特定请求类型

Network 面板顶部可以按类型筛选：

| 类型 | 含义 |
|------|------|
| **XHR** | 多为 ajax 异步请求（数据接口常用） |
| **JS** | JavaScript 脚本 |
| **CSS** | 样式表 |
| **All** | 全部类型 |

不确定该看哪种时，选 **All**，从前往后一个个看。

### 1.11.5 抓包分析一个请求

点击某条请求，可以看到详细信息：

| 部分 | 内容 |
|------|------|
| 第一个包 | 就是访问该 URL 的响应 |
| Headers | 请求头 + 响应头（反爬时补齐缺失信息） |
| Response | 响应内容，可能是源码或 JSON |

> **核心要点：** 反爬场景下，先抓包对比「浏览器发的请求头」和「你代码发的请求头」，缺什么补什么。

### 1.11.6 寻找登录接口

抓包找登录接口有三种思路：

| 思路 | 做法 |
|------|------|
| 看 form 表单 | 找 `action` 对应的 URL，提交键 = input 的 `name` 值 |
| 直接抓包 | 登录时抓请求，看登录 URL（参数可能含 `uniqueTimestamp`、`rkey`、加密的 `password`） |
| 参考手机版 | 手机版接口参数更少，分析起来更简单 |

> **注意：** 登录参数里的密码多为加密后的值，需要做 JS 逆向才能还原（见第 16 章）。

**记忆口诀**

- **爬虫定义** = "按规则自动抓取万维网信息的程序/脚本。"
- **四步主线** = "发请求 → 得响应 → 解析 → 保存。"
- **四大分类** = "通用、聚焦、增量、深层。"
- **请求四件套 / 响应三件套** = "方式头 URL 体 / 状态头体。"
- **抓包** = "隐身窗口 + Preserve log + filter，缺头补头。"
