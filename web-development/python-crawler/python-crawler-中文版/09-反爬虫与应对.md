# 9 反爬虫与应对

有爬虫就有反爬虫。网站为了保护数据、维护稳定、守住版权，会想尽办法识别并拦截爬虫；爬虫工程师则需要识别这些机制并逐一绕过。本章先建立"反爬—反反爬"的整体框架，再逐一讲解代理 IP、动态页面抓包、各类请求伪装与 Fiddler 抓包工具。

## 9.1 反爬机制总览

网站常用的反爬手段：

| 类别 | 具体手段 |
|---|---|
| 封 IP | 同一 IP 短时间内大量请求，直接封禁 |
| 登录/验证码 | 要求登录或输入验证码才能访问 |
| 账号体制 | 必须注册账号并绑定权限 |
| 动态加载数据 | 数据由 JS/AJAX 异步渲染，静态 HTML 里没有 |

## 9.2 反反爬策略总览

对应的破解思路：

| 策略 | 说明 |
|---|---|
| 伪装浏览器 | 伪造请求头（User-Agent、Referer 等），模拟真实浏览器 |
| 代理 IP | 更换出口 IP，规避封禁 |
| 限频 | 降低请求频率，加随机延时 |
| 验证码识别 | OCR / 打码平台（详见第 10 章） |
| Selenium 模拟 | 用真实浏览器渲染动态页面（详见第 8 章） |

## 9.3 网站反制爬虫的原因

- **数据安全**：防止核心数据被批量抓取、泄露。
- **服务器稳定**：高频爬取会造成大量负载，影响正常用户。
- **版权**：内容受版权保护，禁止未授权复制。

> **核心要点：** 反爬不是"敌对"，而是网站的正常防护手段。爬虫应遵守 robots 协议、控制频率、尊重对方服务器，做到"礼貌爬取"。

## 9.4 代理 IP

### 9.4.1 定义与获取

代理 IP 就是"代替你的真实 IP 去请求网络"。请求先发给代理服务器，由代理转发给目标网站，目标网站看到的只是代理的 IP。常见免费代理获取站：西刺代理、快代理、全网代理、代理精灵。

### 9.4.2 按匿名度分类

| 类型 | 服务端看到真实 IP | 服务端知道用了代理 |
|---|---|---|
| 透明代理 | 是 | 是 |
| 匿名代理 | 否（隐藏真实 IP） | 是 |
| 高匿代理 | 否 | 否（完全看不出） |

> **核心要点：** 匿名度排序：透明 < 匿名 < 高匿。爬虫一般用高匿代理，因为透明代理会暴露真实 IP，失去意义。

### 9.4.3 按商用类型分类

| 类型 | 可用率 | 速度 | 价格 | 适用 |
|---|---|---|---|---|
| 普通代理 | 低 | 慢 | 便宜 | 测试、学习 |
| 私密代理 | 适中 | 适中 | 适中 | 爬虫常用 |
| 独享代理 | 极高 | 快 | 贵 | 高要求生产场景 |

### 9.4.4 requests 使用普通代理

```python
import requests

proxies = {
    'http': 'http://<ip>:<端口>',
    'https': 'https://<ip>:<端口>',
}
html = requests.get(url, proxies=proxies, headers=headers, timeout=5).text
```

> **勘误：** 源课件示例里的免费代理 `112.85.164.220:9999` 早已失效。免费代理生命周期很短，需自行从代理站获取并测试后再用，代码中统一用 `<ip>:<端口>` 占位。

### 9.4.5 requests 使用私密/独享代理

私密和独享代理需要认证，格式为 `http://用户名:密码@IP:端口`：

```python
proxies = {
    'http': 'http://<用户名>:<密码>@<ip>:<端口>',
    'https': 'https://<用户名>:<密码>@<ip>:<端口>',
}
html = requests.get(url, proxies=proxies, headers=headers, timeout=5).text
```

> **注意：** 代理凭据属于敏感信息，不要硬编码到代码并提交到仓库，建议用环境变量或配置文件管理。

### 9.4.6 代理 IP 池

免费代理不稳定，需要维护一个"池"：抓取免费代理 → 测试可用性 → 可用者存文件 → 随机选用并定期更新。

```python
import random
import requests

def get_available_proxies():
    """从文件读取可用代理，实际项目需先抓取并测试后写入"""
    with open('proxies.txt', 'r', encoding='utf-8') as f:
        return [line.strip() for line in f if line.strip()]

def fetch(url):
    proxies_list = get_available_proxies()
    proxy = random.choice(proxies_list)          # 随机选用一个
    proxies = {'http': proxy, 'https': proxy}
    try:
        return requests.get(url, proxies=proxies, timeout=5).text
    except Exception:
        return fetch(url)                        # 失败换下一个
```

## 9.5 静态页面 vs 动态页面

| 对比 | 静态页面 | 动态页面 |
|---|---|---|
| 数据来源 | 服务器直接渲染在 response | JS/AJAX 局部刷新生成 |
| 抓取方式 | 直接解析 HTML | 需抓接口或用 Selenium |
| 特征 | `response.text` 里就有数据 | 页面"加载更多"，elements 有数据但 response 查不到 |

判断动态页面的特征：页面上有"加载更多"按钮、开发者工具 Elements 面板里能看到数据但 Response 里搜不到、数据经 AJAX 异步加载。

## 9.6 控制台抓包（F12）

浏览器开发者工具是动态页面抓包的利器。打开 F12 后的关键面板：

| 面板 | 作用 |
|---|---|
| Network → ALL/XHR/JS | 查看所有请求 / 只看 XHR / 只看 JS |
| Headers → General | 请求 URL、方法、状态码 |
| Headers → Response Headers | 响应头 |
| Headers → Request Headers | 请求头（含 UA、Referer、Cookie） |
| Headers → Query String / Form Data | GET 查询参数 / POST 表单数据 |
| Preview / Response | 预览 / 原始响应内容 |
| Sources | 断点调试 JS |
| Console | 交互式测试 JS |

## 9.7 AJAX 与 JSON 动态抓取套路

AJAX（Asynchronous JavaScript And XML）让页面异步局部更新、不重载整页；JSON 是跨语言轻量数据交换格式，现代接口几乎都用 JSON 返回。

动态页面抓取的固定套路：

1. 请求目标 URL，打开 F12 的 Network。
2. 切到 XHR，观察发起了哪些接口请求。
3. 确定真正的数据接口（往往返回 JSON）。
4. 用 requests 直接请求该接口。
5. 解析返回的 JSON。
6. 持久化保存。

```python
import requests
import json

# 假设 F12 抓到的数据接口（URL、参数、headers 均从抓包中复制）
api = 'https://example.com/api/list'
headers = {'User-Agent': '<你的UA>'}
resp = requests.get(api, params={'page': 1}, headers=headers, timeout=5)
data = resp.json()   # 多数接口直接返回 JSON
with open('data.json', 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

## 9.8 常见反爬机制及处理方式

### 9.8.1 User-Agent 反爬与 UA 池

服务器通过 User-Agent 判断请求来源，非浏览器 UA 会被拦截。请求前加 UA 即可伪装；进阶做法是维护一个 UA 池随机切换。

```python
import random
import requests

def get_ua():
    """随机生成一个 Chrome 的 User-Agent"""
    chrome = [
        'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36',
        '(KHTML, like Gecko) Chrome/{major}.0.0.0 Safari/537.36',
    ]
    major = random.randint(90, 120)
    return chrome[0] + ' ' + chrome[1].format(major=major)

headers = {'User-Agent': get_ua()}
resp = requests.get(url, headers=headers, timeout=5)
```

> **核心要点：** UA 的核心是 `Mozilla/5.0 ... Chrome/x.x Safari/537.36`，用 `random` 随机 Chrome 大版本号即可模拟不同用户。

### 9.8.2 Referer 反爬

Referer 表示请求来源页面，有些服务器会校验它，防止图片/接口被盗链。爬虫需在请求头中带上正确的 `Referer`：

```python
headers = {
    'User-Agent': get_ua(),
    'Referer': 'https://example.com/detail/123',   # 数据来源页
}
resp = requests.get(img_url, headers=headers, timeout=5)
```

### 9.8.3 Cookie/Session 机制与模拟登录

Cookie 在客户端记录身份信息，Session 在服务器端记录状态，两者配合实现"会话跟踪"——服务器靠 Cookie 里的 Session ID 认出"你是谁"。需要登录的网站，用 Cookie 模拟登录有三种方法：

**方法一：登录后手动取 Cookie 放进 headers**

```python
headers = {
    'User-Agent': get_ua(),
    'Cookie': '<登录后从浏览器复制的 Cookie 字符串>',
}
resp = requests.get(url, headers=headers)
```

**方法二：`cookies` 参数传字典**

```python
cookies = {'sessionid': '<值>', 'token': '<值>'}
resp = requests.get(url, cookies=cookies, headers=headers)
```

**方法三：`requests.session()` 会话保持（推荐）**

```python
import requests

session = requests.session()   # 自动在多次请求间保持 Cookie
session.post(
    post_url,
    data={'email': '<账号>', 'password': '<密码>'},
    headers=headers,
)
resp = session.get(url, headers=headers)   # 自动携带登录后的 Cookie
```

> **核心要点：** `session` 对象会在同一次会话内自动保存并携带服务端返回的 Cookie，模拟登录后无需手动管理，是最常用做法。

### 9.8.4 请求参数反爬

有些接口的参数是动态生成的，常见三种获取方式：

| 方式 | 适用场景 |
|---|---|
| 从 HTML 静态文件解析参数 | 参数藏在源码里（如 github 登录页的 `authenticity_token`） |
| 发请求获取参数 | 参数由上一个请求返回 |
| JS 生成参数 | 参数由 JS 动态计算，需 `js2py` 执行或 Selenium 渲染 |

### 9.8.5 验证码反爬（原理）

当服务器判定你是"非人类"（高频请求、无 Cookie 等），会弹出验证码强制校验，只有输入正确才能继续访问。解决方式有打码平台、机器学习识别等——**具体识别实现在第 10 章**，本章只讲它是反爬手段之一。

### 9.8.6 CSS 反爬

源码里放的不是真实数据，真实内容用 CSS 位移（如自定义字体 + 位移属性）拼凑。破解思路：分析 CSS 中的偏移量，按位移还原真实数据：

```python
# 思路示例：把每个字符按 CSS 偏移量还原
def restore(text, offsets):
    result = [''] * len(text)
    for i, off in enumerate(offsets):
        result[i] = text[i + off]   # 按偏移放回正确位置
    return ''.join(result)
```

### 9.8.7 JS 动态生成数据反爬

数据由关键 JS 在浏览器端计算生成。破解思路：定位生成数据的 JS 脚本 → 分析其生成流程 → 在 Python 中模拟同样的算法（或用 `js2py` 执行 JS、用 Selenium 渲染）。

### 9.8.8 编码格式反爬

服务器返回非 `utf-8` 编码时会出现乱码或报错。按源码实际编码多格式尝试解码：

```python
resp = requests.get(url, headers=headers)
# 优先用 response 声明的编码，不行再手动尝试
for enc in ['utf-8', 'gbk', 'gb2312', 'latin-1']:
    try:
        text = resp.content.decode(enc)
        break
    except UnicodeDecodeError:
        continue
```

## 9.9 抓包工具 Fiddler

Fiddler 是一款本地 HTTP/HTTPS 抓包工具，通过在本机架设代理（默认 `127.0.0.1:8888`）拦截并记录经过的所有请求，方便分析移动端、客户端程序的接口。

### 9.9.1 工作原理与配置

- **原理**：Fiddler 作为本地代理，应用把请求发给 Fiddler，Fiddler 转发给目标服务器，再原路返回，从而记录下全部流量。
- **安装**：从官网下载安装包（官网已迁移，搜索 "Telerik Fiddler" 获取最新地址）。
- **配置**：`Tools > Options > Connections` 设置监听端口（默认 `8888`）；抓 HTTPS 还需在 `HTTPS` 页签勾选 Decrypt HTTPS traffic 并安装证书。

## 记忆口诀

- **反爬四大招：** 封 IP、登录/验证码、账号体制、动态加载。
- **反反爬五招：** 伪装浏览器、代理 IP、限频、验证码识别、Selenium。
- **代理匿名度：** 透明（暴露真实 IP）< 匿名（隐藏 IP）< 高匿（无痕）。
- **代理格式：** 普通 `http://<ip>:<端口>`；认证 `http://<用户名>:<密码>@<ip>:<端口>`。
- **动态页面套路：** 请求 → F12 抓 XHR → 定接口 → 发请求 → 解析 JSON → 持久化。
- **模拟登录三法：** Cookie 放 headers / `cookies=` 参数 / `requests.session()` 会话保持。
- **参数反爬三源：** 静态 HTML 解析 / 上一个请求返回 / JS 生成。
- **Fiddler：** 本地代理 `127.0.0.1:8888`，抓 HTTPS 需开 Decrypt 并装证书。
