# 14 异常处理

**异常**（exception）是打断程序正常运行流程的事件。常见的例子包括除以零、打开不存在的文件，或向函数传入非法值。如果异常未被处理，程序会打印错误信息并停止运行。

**异常处理**让你能够捕获这些事件、决定如何应对，从而让程序继续运行或优雅地失败。主要工具是 `try/except` 代码块：`try` 中的代码会被监控是否出错，`except` 块则定义如何响应特定的错误。

良好的异常处理将正常逻辑与错误处理分离开来，使代码更健壮、更易于调试。

## 14.1 常见异常

| 异常 | 原因 |
|-----------|-------|
| `SyntaxError` | Python 语法非法 |
| `NameError` | 变量未定义 |
| `TypeError` | 对不兼容的类型执行操作 |
| `ValueError` | 操作的值非法 |
| `IndexError` | 列表索引越界 |
| `KeyError` | 字典键不存在 |
| `ZeroDivisionError` | 除以零 |
| `FileNotFoundError` | 文件不存在 |
| `AttributeError` | 属性不存在 |

```python
# ValueError — invalid literal
int("abc")

# IndexError — index out of range
[1, 2, 3][10]

# KeyError — key not found
{"a": 1}["b"]

# TypeError — can't add str and int
"1" + 2
```

上面每一行都会单独抛出对应的异常——请逐行尝试。

## 14.2 异常层次结构

Python 的异常构成一个类层次结构。捕获父类异常会同时捕获其所有子类异常。

```
BaseException
 ├── SystemExit
 ├── KeyboardInterrupt
 └── Exception
      ├── ArithmeticError
      │    └── ZeroDivisionError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── TypeError
      ├── ValueError
      ├── AttributeError
      └── OSError
           └── FileNotFoundError
```

**最佳实践：** 尽可能捕获最具体的异常。

## 14.3 异常处理语法

| 语法 | 用途 |
|--------|---------|
| `try` | 可能抛出异常的代码 |
| `except` | 处理特定异常 |
| `except Exception as e` | 捕获异常并获取详细信息 |
| `else` | 没有异常时执行 |
| `finally` | 总是执行（清理工作） |

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
except Exception as e:
    print(f"Error: {e}")
else:
    print(f"Result: {result}")  # Only if no exception
finally:
    print("Cleanup code")       # Always runs

# Catch multiple exceptions
try:
    value = int(input("Enter number: "))
except (ValueError, TypeError):
    print("Invalid input")
```

### 14.3.1 嵌套 `try/except`

`try` 块可以嵌套。内层的 `except` 处理内层块中的错误；如果它没有捕获该异常，异常会传播到外层的 `except`。

```python
try:
    print("Outer try")
    try:
        result = 10 / 0
    except ZeroDivisionError:
        print("Inner: caught division by zero")
    # Inner block handled the error, outer continues normally
    print("Outer continues")
except Exception:
    print("Outer: caught something")

# Output:
# Outer try
# Inner: caught division by zero
# Outer continues
```

**使用场景：** 内层块处理可预期的局部错误；外层块处理意料之外的、范围更大的故障。

### 14.3.2 执行流程

```
try:
    # Code runs first
    risky_operation()
    # If no exception → else block runs
except SomeError:
    # Runs only if SomeError is raised
    handle_error()
else:
    # Runs only if NO exception in try
    success_handler()
finally:
    # ALWAYS runs (cleanup)
    cleanup()
```

**执行顺序保证：**
1. `try` 块执行
2. 如果有异常 → 匹配的 `except` 执行
3. 如果没有异常 → `else` 执行
4. `finally` 总是最后执行

### 14.3.3 `finally` 的使用场景

无论是否发生错误都必须执行的清理工作，应放在 `finally` 中。

**手动关闭资源：**

```python
f = open("data.txt", "r", encoding="utf-8")
try:
    content = f.read()
    process(content)
except FileNotFoundError:
    print("File not found")
finally:
    f.close()           # Always runs
```

**重置状态：**

```python
is_busy = False

def perform_task():
    global is_busy
    is_busy = True
    try:
        # do work that might fail
        risky_operation()
    finally:
        is_busy = False   # Always reset the flag
```

对于大多数文件和资源的清理，更推荐使用 `with`，因为它会自动生成等价的 `try/finally` 块。

### 14.3.4 `except` 块的顺序

Python **从上到下**检查 `except` 块，**只运行第一个匹配的块**。具体的异常必须放在更宽泛的异常之前，否则宽泛的异常会遮蔽它们，导致具体异常的块永远不会执行：

```python
# ❌ Bad — Exception matches everything, ZeroDivisionError never reached
try:
    result = 10 / 0
except Exception:
    print("Caught something")
except ZeroDivisionError:
    print("Cannot divide by zero")   # Dead code — never runs

# ✅ Good — specific first, general last
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
except Exception:
    print("Caught something")
```

这直接源于 14.2 节中的层次结构：父类会匹配其所有子类。

## 14.4 最佳实践

### 14.4.1 要具体

```python
# Bad - catches everything including SystemExit and KeyboardInterrupt
try:
    risky_operation()
except:                     # Bare except - dangerous!
    pass

# Good - catch expected exceptions only
try:
    risky_operation()
except ValueError as e:
    print(f"Invalid value: {e}")
except FileNotFoundError:
    print("File missing")
```

### 14.4.2 不要盲目吞掉异常

```python
# Bad - hides bugs
try:
    process_data()
except:
    pass                    # Bug goes unnoticed!

# Good - log or handle meaningfully
import logging

try:
    process_data()
except ValueError as e:
    logging.error(f"Data error: {e}")
    raise                   # Re-raise if caller should know
```

关于配置 `logging` 和捕获完整回溯信息，参见 [14.9 日志记录异常与回溯信息](#149-日志记录异常与回溯信息)。

### 14.4.3 EAFP 与 LBYL

处理可能失败的操作有两种风格：

- **LBYL**（Look Before You Leap，三思而后行）：在行动之前用 `if` 检查前置条件。
- **EAFP**（Easier to Ask Forgiveness than Permission，请求原谅比请求许可更容易）：直接尝试，失败了就处理异常。

```python
# LBYL — check first
from pathlib import Path

p = Path("data.txt")
if p.exists():
    content = p.read_text(encoding="utf-8")

# EAFP — try first, handle failure
try:
    content = Path("data.txt").read_text(encoding="utf-8")
except FileNotFoundError:
    content = ""
```

Python 的惯用写法通常更推崇 **EAFP**：

- 在 `if` 检查和实际行动之间，情况可能发生变化（另一个进程删除了文件）——这就是**竞态条件**（race condition）。EAFP 不存在这样的空档。
- 顺利执行的路径读起来是一条直线，而不是被埋在层层 `if` 守卫之中。

当检查的开销很小、失败很常见，或没有合适的异常可用时，LBYL 依然适用。

## 14.5 `raise`

| 特性 | 说明 |
|---------|-------------|
| `raise Exception()` | 抛出指定异常 |
| `raise` | 重新抛出当前异常 |
| 自定义消息 | `raise ValueError("message")` |

```python
def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("Insufficient funds")
    if amount <= 0:
        raise ValueError("Amount must be positive")
    return balance - amount

# Custom exception
class ValidationError(Exception):
    pass

raise ValidationError("Age cannot be negative")
```

自定义异常就是一个继承自 `Exception` 的类。携带额外上下文属性的完整示例见下文 14.5.1 节。

### 14.5.1 实例：带上下文的自定义异常

带有描述性消息的自定义异常能让调试轻松得多。继承自 `Exception`（或更具体的内置异常），并将错误详情传给 `super().__init__()`。

```python
class FutureYearError(Exception):
    """Raised when a year from the future is provided."""
    def __init__(self, year, current_year):
        message = f"Year {year} does not exist yet (current year is {current_year})"
        super().__init__(message)
        self.year = year
        self.current_year = current_year

def calculate_age(birth_year, current_year=2025):
    if birth_year > current_year:
        raise FutureYearError(birth_year, current_year)
    if birth_year < 1900:
        raise ValueError("Birth year seems unrealistic")
    return current_year - birth_year

# Normal case
print(calculate_age(2000))   # 25

# Custom exception with rich context
try:
    print(calculate_age(2030))
except FutureYearError as e:
    print(f"Error: {e}")
    print(f"Provided year: {e.year}")
    print(f"Current year: {e.current_year}")
# Error: Year 2030 does not exist yet (current year is 2025)
# Provided year: 2030
# Current year: 2025
```

### 14.5.2 异常链

`raise ... from ...` 将原始异常作为原因（cause）附加到新异常上，从而保留完整的回溯信息（traceback）。

```python
try:
    int("not_a_number")
except ValueError as e:
    raise RuntimeError("Conversion failed") from e
```

### 14.5.3 抑制异常上下文

当你捕获一个异常并抛出另一个异常时，Python 会将原始异常保留为**原因**（cause）或**上下文**（context）。这通常很有用，但有时你希望隐藏原始错误，以免让用户困惑。

使用 `raise ... from None` 来抑制上下文。

```python
try:
    int("not_a_number")
except ValueError:
    raise RuntimeError("Invalid configuration value") from None
```

不使用 `from None` 时，回溯信息会同时显示 `ValueError` 和 `RuntimeError`；使用 `from None` 后，只会显示 `RuntimeError`。请谨慎使用——隐藏原始错误会让调试变得更困难。

## 14.6 `assert`

| 特性 | 说明 |
|---------|-------------|
| 用途 | 调试检查（本不应发生的情况） |
| 语法 | `assert condition, "message"` |
| 效果 | 条件为 False 时抛出 `AssertionError` |
| 禁用方式 | 使用 `python -O`（优化模式） |

```python
def divide(a, b):
    assert b != 0, "Divisor cannot be zero"     # Debug check
    return a / b

# Use for internal logic validation
class Stack:
    def __init__(self):
        self.items = []

    def push(self, item):
        self.items.append(item)

    def pop(self):
        assert len(self.items) > 0, "Stack is empty"  # Should not happen if used correctly
        return self.items.pop()

s = Stack()
s.push(1)
print(s.pop())   # 1
# s.pop()        # AssertionError: Stack is empty
```

**断言（Assertion）与异常（Exception）的区别：**
- **断言**：内部 bug 检查，可以被禁用
- **异常**：可预期的错误情况，始终需要处理

## 14.7 上下文管理器

`with` 语句确保即使发生异常，清理代码也会执行。

```python
# File context manager (auto-closes)
with open("file.txt") as f:
    content = f.read()
```

### 14.7.1 自定义上下文管理器

实现 `__enter__` 和 `__exit__` 方法。

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        elapsed = time.time() - self.start
        print(f"Elapsed: {elapsed:.2f}s")

with Timer():
    # Code to time
    sum(range(1000000))
```

### 14.7.2 `contextlib.contextmanager`

使用生成器编写上下文管理器的更简单方式。

```python
from contextlib import contextmanager

@contextmanager
def managed_resource(name):
    print(f"Acquiring {name}")
    yield name
    print(f"Releasing {name}")

with managed_resource("db_connection") as res:
    print(f"Using {res}")
```

## 14.8 `warnings` 模块

在不中断程序执行的情况下发出非致命的警告。

```python
import warnings

# Issue a warning
warnings.warn("This feature is deprecated", DeprecationWarning)

# Filter warnings
warnings.filterwarnings("ignore", category=DeprecationWarning)
```

## 14.9 日志记录异常与回溯信息

当长时间运行的程序中发生异常时，只打印一条简单的消息往往不够。`logging` 和 `traceback` 模块可以帮助记录完整的错误信息，便于日后诊断问题。

### 14.9.1 记录异常日志

在 `except` 块中使用 `logging.exception()`，会自动附带回溯信息。

```python
import logging

logging.basicConfig(level=logging.ERROR)

try:
    result = 10 / 0
except ZeroDivisionError:
    logging.exception("Division failed")
```

### 14.9.2 将回溯信息捕获为字符串

使用 `traceback.format_exc()` 捕获完整的回溯信息，用于错误报告、测试或自定义错误消息。

```python
import traceback

try:
    result = 10 / 0
except ZeroDivisionError:
    tb = traceback.format_exc()
    print("An error occurred. Details:")
    print(tb)
```

**最佳实践：** 在生产代码中，应使用 `logging.exception()` 或 `logging.error(..., exc_info=True)` 记录异常，而不是直接使用 `print()`。这样能保留调试所需的完整上下文。

更深入的内容见 [28 logging 日志](28-logging日志.md)。

## 14.10 快速参考

**`try/except` 语法**

| 代码块 | 何时运行 |
|-------|-----------|
| `try` | 总是运行——被监控的代码 |
| `except X as e` | 抛出了异常 `X`（或其子类）时 |
| `else` | `try` 中没有抛出异常时 |
| `finally` | 总是最后运行——清理工作 |

**抛出与检查**

| 工具 | 用途 |
|------|---------|
| `raise X("msg")` | 发出一个可预期的错误信号 |
| `raise` | 重新抛出当前异常 |
| `raise X(...) from e` | 异常链：保留原始原因 |
| `raise X(...) from None` | 隐藏原始原因（谨慎使用） |
| `assert cond, "msg"` | 仅用于内部 bug 检查——会被 `python -O` 禁用 |
| `with` / 上下文管理器 | 保证清理（文件、锁、计时器） |

**黄金法则**

- 尽可能捕获最具体的异常；绝不使用裸 `except:`。
- `except` 块按从具体到宽泛的顺序排列——第一个匹配的生效。
- 不要静默吞掉异常；要么记录日志（`logging.exception()`），要么重新抛出。
- 可预期的错误用 `raise`，"本不应发生"的情况用 `assert`。
- 在 Python 惯用写法中，优先使用 EAFP（先 `try`）而不是 LBYL（先 `if` 检查）。
- 关于文件错误的专门内容，参见 [10.7.2 常见文件错误](10-文件操作.md#1072-常见文件错误)。
