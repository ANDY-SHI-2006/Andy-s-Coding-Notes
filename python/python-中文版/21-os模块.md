# 21 os 模块

os 模块是 Python 与操作系统交互的标准接口。它提供了跨平台的文件路径处理、目录管理、环境变量读取、进程信息查询等功能。只要是需要「与文件系统或操作系统打交道」的任务，os 模块通常都是首选。

```python
import os
```

**注意：** os 模块会自动适配当前操作系统，但路径分隔符、换行符等细节因平台而异。Windows 用 `\`，Linux/macOS 用 `/`。本章示例均使用跨平台写法，可在任意系统上运行。

## 21.1 路径操作

路径操作集中在 `os.path` 子模块中。这些函数只做**字符串层面的路径处理**，不要求路径真实存在。

### 21.1.1 拼接路径：os.path.join

永远不要手工用 `+` 或 `/` 拼接路径——os.path.join 会根据当前系统自动选择正确的分隔符。

```python
import os

# Cross-platform path joining
path = os.path.join("data", "images", "photo.jpg")
print(path)     # data/images/photo.jpg (Linux/macOS)
                # data\images\photo.jpg (Windows)
```

**注意：** 如果某个参数是绝对路径，join 会丢弃之前的所有部分：

```python
import os

os.path.join("data", "/etc", "config.ini")
# '/etc/config.ini' (Linux/macOS), '/etc\config.ini' (Windows)
```

### 21.1.2 判断路径：exists / isfile / isdir

| 函数 | 返回 True 的条件 |
|------------------|--------------------------|
| `os.path.exists(p)` | 路径存在（文件或目录均可） |
| `os.path.isfile(p)` | 路径存在且是文件 |
| `os.path.isdir(p)` | 路径存在且是目录 |

```python
import os

print(os.path.exists("python/python-中文版"))   # True
print(os.path.isfile("python/python-中文版"))   # False
print(os.path.isdir("python/python-中文版"))    # True
```

这三个函数是最常用的「防御性检查」：在读写文件之前先确认路径状态，避免抛出异常（异常处理的完整讨论见第 14 章）。

### 21.1.3 拆分路径：basename / dirname / splitext

| 函数 | 作用 | 示例返回值 |
|-----------------------|-----------------------|---------------------------|
| `os.path.basename(p)` | 取最后一段（文件名） | `'photo.jpg'` |
| `os.path.dirname(p)` | 去掉最后一段（目录部分） | `'data/images'` |
| `os.path.splitext(p)` | 拆成 `(主体, 扩展名)` | `('photo', '.jpg')` |

```python
import os

path = os.path.join("data", "images", "photo.jpg")

print(os.path.basename(path))   # photo.jpg
print(os.path.dirname(path))    # data/images (Linux/macOS)

name, ext = os.path.splitext("report.tar.gz")
print(name)                     # report.tar
print(ext)                      # .gz
```

**注意：** splitext 只识别**最后一个**后缀。`'report.tar.gz'` 拆出来是 `('report.tar', '.gz')`，而不是 `('report', '.tar.gz')`。

### 21.1.4 绝对路径：os.path.abspath

相对路径是相对于当前工作目录的（见 21.5 节的 getcwd）。abspath 把它转换成绝对路径：

```python
import os

abs_path = os.path.abspath("21-os模块.md")
print(os.path.isabs(abs_path))  # True
print(abs_path)                 # e.g. /home/user/project/21-os模块.md
```

abspath 不做任何存在性检查，纯粹是字符串运算。配套的 `os.path.isabs()` 可以判断一个路径是否已经是绝对路径。

## 21.2 目录与文件操作

### 21.2.1 列出目录内容：os.listdir

listdir 返回目录下所有条目（文件 + 子目录）的**名字列表**，不递归、不包含 `.` 和 `..`：

```python
import os

entries = os.listdir(".")
for name in sorted(entries):
    print(name)
```

**注意：** listdir 返回的是**相对名字**，不是完整路径。要判断条目类型，必须先 join 回父目录：

```python
import os

parent = "."
for name in os.listdir(parent):
    full = os.path.join(parent, name)       # Rebuild full path
    kind = "dir" if os.path.isdir(full) else "file"
    print(f"{kind}: {name}")
```

### 21.2.2 创建目录：mkdir 与 makedirs

| 函数 | 行为 | 父目录不存在时 |
|------------------|------------------------------------|----------------------|
| `os.mkdir(p)` | 创建**单级**目录 | 抛出 FileNotFoundError |
| `os.makedirs(p)` | 递归创建**多级**目录 | 自动创建中间目录 |

```python
import os

os.makedirs("demo/a/b", exist_ok=True)  # Create nested directories
```

两者的共同点是：目标目录**已存在**时会抛出 FileExistsError。加 `exist_ok=True` 可以让已存在的情况静默通过（makedirs 支持，Python 3.2+）。

### 21.2.3 删除与重命名

| 函数 | 作用 |
|------------------|----------------------------------|
| `os.remove(p)` | 删除**文件** |
| `os.rmdir(p)` | 删除**空目录** |
| `os.rename(src, dst)` | 重命名/移动文件或目录 |

```python
import os

# Create, rename, then remove a file
with open("demo/tmp.txt", "w") as f:
    f.write("hello")

os.rename("demo/tmp.txt", "demo/renamed.txt")
print(os.path.exists("demo/tmp.txt"))       # False
print(os.path.exists("demo/renamed.txt"))   # True

os.remove("demo/renamed.txt")               # Delete file
```

**注意：**
- os.remove 只能删文件，对目录调用会抛出错误（Linux/macOS 上是 IsADirectoryError，Windows 上是 PermissionError）。
- os.rmdir 只能删**空目录**。要连同内容一起删除非空目录，需要 `shutil.rmtree()`（shutil 是另一个标准库模块）。
- os.rename 在目标已存在时行为因平台而异（Windows 上会抛出 FileExistsError，POSIX 上会静默覆盖）。跨平台原子替换建议用 `os.replace()`。

```python
import os

# Cleanup the demo directories (must be empty, remove deepest first)
os.rmdir("demo/a/b")
os.rmdir("demo/a")
os.rmdir("demo")
```

## 21.3 os.walk 遍历目录树

listdir 只看一层，而 os.walk 会**递归**遍历整棵目录树。它是一个生成器（生成器的概念见 11.3 节），惰性地产出结果，内存开销很小。

### 21.3.1 基本用法

os.walk 每次产出一个三元组 `(dirpath, dirnames, filenames)`：

| 元素 | 含义 |
|-------------|-----------------------------------|
| `dirpath` | 当前目录的路径字符串 |
| `dirnames` | 当前目录下的**子目录名**列表 |
| `filenames` | 当前目录下的**文件名**列表 |

```python
import os

for dirpath, dirnames, filenames in os.walk("docs"):
    for name in filenames:
        print(os.path.join(dirpath, name))
```

### 21.3.2 topdown 参数

默认 `topdown=True`：先访问父目录，再进入子目录。此时可以**修改 dirnames 列表**来剪枝——从列表中删除的名字不会被继续遍历：

```python
import os

for dirpath, dirnames, filenames in os.walk(".", topdown=True):
    # Skip hidden directories and virtualenvs
    dirnames[:] = [d for d in dirnames
                   if not d.startswith(".") and d != "venv"]
    for name in filenames:
        print(os.path.join(dirpath, name))
```

**注意：** 必须用 `dirnames[:] = ...` 做**就地修改**。写成 `dirnames = [...]` 只是重新绑定了局部变量，对 walk 的遍历毫无影响——这是 os.walk 最常见的易错点。

`topdown=False` 时自下而上（先子目录后父目录），适合「先清空内容再删目录」之类的场景。

### 21.3.3 实战：按类型统计并收集文件

```python
import os
from collections import Counter

def collect_by_ext(root, exts):
    """Collect files matching given extensions, case-insensitive."""
    matched = []
    stats = Counter()
    for dirpath, dirnames, filenames in os.walk(root, topdown=True):
        dirnames[:] = [d for d in dirnames if not d.startswith(".")]
        for name in filenames:
            ext = os.path.splitext(name)[1].lower()
            stats[ext] += 1
            if ext in exts:
                matched.append(os.path.join(dirpath, name))
    return matched, stats

md_files, stats = collect_by_ext(".", {".md"})
print(f"Found {len(md_files)} Markdown files")
print("Top 3 extensions:", stats.most_common(3))
```

这个模式非常实用：遍历时用 splitext 统一转小写再比对，避免 `photo.JPG` 和 `photo.jpg` 被当成两种类型（字符串方法见第 2 章，Counter 见第 4 章）。

## 21.4 环境变量

环境变量（environment variable）是操作系统级别的键值对，常用于向程序传递配置——比如数据库地址、API 密钥、运行模式等，避免把这些信息硬编码进代码。

### 21.4.1 os.environ

os.environ 是一个类似字典的映射对象（映射类型见第 4 章），反映当前进程的环境变量：

```python
import os

# Read
home = os.environ.get("HOME") or os.environ.get("USERPROFILE")
print(home)

# Write (affects only this process and its children)
os.environ["APP_MODE"] = "debug"
print(os.environ["APP_MODE"])       # debug
```

**注意：** 通过 os.environ 修改环境变量只对**当前进程及其子进程**生效，进程退出后即失效，不会永久写入操作系统。

### 21.4.2 os.getenv 与默认值

os.getenv 是更安全的读取方式：变量不存在时返回默认值而不是抛出 KeyError：

```python
import os

mode = os.getenv("APP_MODE", "production")  # Default fallback
print(mode)                                 # production

debug = os.getenv("APP_DEBUG")              # None if missing
print(debug)                                # None
```

对比两种写法的差别：

```python
import os

os.environ["MISSING_VAR"]       # Raises KeyError
os.getenv("MISSING_VAR")        # Returns None
os.getenv("MISSING_VAR", "x")   # Returns "x"
```

### 21.4.3 常见用途

```python
import os

# Typical configuration pattern
DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///local.db")
DEBUG = os.getenv("DEBUG", "false").lower() == "true"
MAX_WORKERS = int(os.getenv("MAX_WORKERS", "4"))

print(DATABASE_URL, DEBUG, MAX_WORKERS)
```

**注意：** 环境变量**永远是字符串**。`os.getenv("DEBUG", "false")` 拿到的是字符串 `'false'`，而不是布尔值 False。要转成 int/bool 必须自己转换——`"false".lower() == "true"` 这类写法就是为此准备的。

## 21.5 进程与系统信息

### 21.5.1 当前工作目录：getcwd

当前工作目录（current working directory, cwd）是所有**相对路径**的基准：

```python
import os

cwd = os.getcwd()
print(cwd)      # e.g. /home/user/project
```

**注意：** 脚本在哪个目录被启动，cwd 就是哪里——它与脚本文件本身所在的位置**无关**。用 `python scripts/tool.py` 在项目根目录运行时，脚本里的相对路径 `data/x.txt` 指向的是项目根目录下的 `data`，而不是 `scripts/data`。想定位脚本自身位置，用 `os.path.dirname(os.path.abspath(__file__))`。

### 21.5.2 进程 ID：getpid

```python
import os

print(os.getpid())      # Current process ID, e.g. 12845
print(os.getppid())     # Parent process ID
```

常用于生成临时文件名、日志标识等场景。

### 21.5.3 操作系统类型：os.name

| os.name 值 | 平台 |
|-------------|---------------------------|
| `'posix'` | Linux、macOS 等 Unix 系统 |
| `'nt'` | Windows |

```python
import os

print(os.name)      # 'posix' on Linux/macOS, 'nt' on Windows
```

需要更细粒度的判断时（比如区分 Linux 和 macOS），用 `sys.platform`（`'linux'`、`'darwin'`、`'win32'`）：

```python
import sys

print(sys.platform)     # 'linux', 'darwin', or 'win32'
```

### 21.5.4 执行系统命令：os.system 及其局限

os.system 把字符串交给系统 shell 执行，返回**退出状态码**（0 通常表示成功）：

```python
import os

code = os.system("echo hello from shell")
print("exit code:", code)       # 0
```

它的局限很多：

- **拿不到命令输出**——输出直接打印到终端，程序无法捕获。
- **返回值只是状态码**，不是输出文本。
- **有注入风险**——拼接用户输入进命令字符串非常危险。
- **跨平台差异大**——同一命令在 Windows 和 Linux 上可能完全不同。

需要捕获输出时，应使用 subprocess 模块：

```python
import subprocess

result = subprocess.run(["echo", "hello"],
                        capture_output=True, text=True)
print(result.stdout.strip())    # hello
print(result.returncode)        # 0
```

结论：os.system 只适合「随手调一下、不关心输出」的临时场景；正式代码一律用 subprocess。

## 21.6 os 与 pathlib 对比

从 Python 3.4 起，标准库提供了面向对象的路径库 pathlib。它并不是要取代 os，而是提供了另一种编程风格。pathlib 在第 10 章文件操作中已有介绍，这里做一个系统对比。

### 21.6.1 风格对照

| 操作 | os / os.path | pathlib |
|------------------------|--------------------------------------|--------------------------------------|
| 拼接路径 | `os.path.join(d, "a.txt")` | `d / "a.txt"` |
| 文件名 | `os.path.basename(p)` | `p.name` |
| 父目录 | `os.path.dirname(p)` | `p.parent` |
| 扩展名 | `os.path.splitext(p)[1]` | `p.suffix` |
| 绝对路径 | `os.path.abspath(p)` | `p.resolve()` |
| 是否存在 | `os.path.exists(p)` | `p.exists()` |
| 是否文件 | `os.path.isfile(p)` | `p.is_file()` |
| 是否目录 | `os.path.isdir(p)` | `p.is_dir()` |
| 创建目录 | `os.makedirs(p, exist_ok=True)` | `p.mkdir(parents=True, exist_ok=True)` |
| 列出目录 | `os.listdir(p)` | `list(p.iterdir())` |
| 递归找文件 | `os.walk` + 手动过滤 | `p.rglob("*.md")` |
| 当前目录 | `os.getcwd()` | `Path.cwd()` |

```python
from pathlib import Path

p = Path("data") / "images" / "photo.jpg"
print(p.name)           # photo.jpg
print(p.suffix)         # .jpg
print(p.parent)         # data/images
print(Path.cwd())       # Current working directory
```

### 21.6.2 实战对照：递归收集 Markdown 文件

同一个任务，两种写法：

```python
import os
from pathlib import Path

# os.walk style
md_os = []
for dirpath, _, filenames in os.walk("."):
    md_os += [os.path.join(dirpath, f) for f in filenames
              if f.endswith(".md")]

# pathlib style
md_pl = list(Path(".").rglob("*.md"))

print(len(md_os), len(md_pl))
```

### 21.6.3 何时用哪个

| 场景 | 推荐 |
|----------------------------------------|-------------------|
| 现代代码的路径处理（拼接、拆分、读写） | **pathlib**，可读性更好 |
| 环境变量、进程信息、执行命令 | **os**（pathlib 不管这些） |
| os.walk 的目录剪枝等精细遍历控制 | **os.walk** |
| 维护老代码、与只接受字符串的旧 API 对接 | **os.path** |
| 删除非空目录（shutil.rmtree 等） | 配合 os/shutil 使用 |

**注意：** os 模块的函数普遍接受字符串路径，多数也接受 Path 对象（返回值类型跟随传入类型）；反过来，pathlib 的方法只接受 Path。混用时可用 `str(p)` 或 `Path(s)` 显式转换，避免类型混乱。

实际建议：新项目优先 pathlib 处理路径，环境变量、进程与系统相关功能仍用 os——两者是互补关系，不是二选一。

## 本章小结

- `os.path` 负责路径字符串处理：join 拼接、basename/dirname/splitext 拆分、exists/isfile/isdir 判断、abspath 转绝对路径。
- 目录与文件操作：listdir 列单层、makedirs 递归建目录、remove 删文件、rmdir 删空目录、rename 重命名。
- `os.walk` 递归遍历目录树；topdown 模式下用 `dirnames[:] = ...` 就地剪枝。
- 环境变量用 `os.getenv(key, default)` 读取，注意返回值永远是字符串。
- getcwd 返回相对路径的基准目录；os.name / sys.platform 判断平台；os.system 功能受限，正式代码用 subprocess。
- pathlib 提供面向对象的路径 API，与 os 互补：路径处理优先 pathlib，系统功能仍用 os。
