# 13 闭包与装饰器

## 13.1 一等函数

Python 中的函数是一等对象（first-class object）：它们可以像其他任何值一样被赋值、传递、返回和存储。

### 13.1.1 赋值给变量

函数名只是一个引用。你可以把它赋值给另一个变量。

```python
def greet():
    print("Hello")

my_func = greet
my_func()                   # 调用 greet()
```

### 13.1.2 作为参数传递

函数可以传递给其他函数，从而实现灵活的行为。

```python
def apply(func, value):
    return func(value)

apply(len, "hello")         # 5
apply(str.upper, "abc")     # "ABC"
```

### 13.1.3 从函数中返回

函数可以创建并返回其他函数。这是闭包与装饰器的基础。

```python
def multiplier(n):
    def inner(x):
        return x * n
    return inner

triple = multiplier(3)        # 返回内部函数
triple(10)                  # 30
```

### 13.1.4 存储在容器中

函数可以存储在列表、字典和其他数据结构中。

```python
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

operations = {
    "+": add,
    "-": subtract,
}

operations["+"](5, 3)       # 8
operations["-"](5, 3)       # 2
```

## 13.2 闭包

### 13.2.1 定义

**闭包（closure）：** 一个引用了其外层作用域中变量、并由外层函数返回的嵌套函数。

| 条件 | 说明 |
|-----------|-------------|
| 1. 嵌套函数 | 函数定义在另一个函数内部 |
| 2. 变量引用 | 内层函数使用外层函数的变量 |
| 3. 返回内层函数 | 外层函数返回内层函数 |

```python
def counter():
    count = 0               # 外层变量（被保留）
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

c1 = counter()              # 每次调用创建新的闭包
c1()                        # 1
c1()                        # 2 (记住了状态)

c2 = counter()              # 独立的闭包
c2()                        # 1
```

### 13.2.2 带状态的工厂函数

闭包让你可以创建携带私有状态的函数。每次调用工厂函数都会产生一个独立的闭包。

```python
def make_multiplier(n):
    def multiply(x):
        return x * n        # n 从外层作用域捕获
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

double(5)   # 10
triple(5)   # 15
```

### 13.2.3 陷阱：延迟绑定

当闭包在循环中被创建时，它们捕获的是**变量名**，而不是创建那一刻的值。所有闭包最终看到的都是最终值。

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)   # 所有闭包引用同一个 i

funcs[0]()   # 2 (不是 0)
funcs[1]()   # 2
funcs[2]()   # 2
```

**修复方法：** 把当前值绑定为默认参数，默认参数在定义时就会被求值。

```python
funcs = []
for i in range(3):
    funcs.append(lambda x=i: x)   # x 捕获 i 的当前值

funcs[0]()   # 0
funcs[1]()   # 1
funcs[2]()   # 2
```

## 13.3 装饰器基础

**装饰器（decorator）：** 一个包装另一个函数、在不修改原函数的前提下扩展其行为的函数。

### 13.3.1 为什么需要装饰器？（演进过程）

假设你需要为多个函数测量执行时间。不用装饰器的话，你有三种不理想的方案：

#### 13.3.1.1 问题：重复代码

最直接的方式是给每个函数都加上计时代码。这违反了 DRY 原则。

```python
import time

def login():
    start = time.time()
    print("Login logic")
    time.sleep(1)
    print(f"Time: {time.time() - start:.2f}s")

def register():
    start = time.time()
    print("Register logic")
    time.sleep(1)
    print(f"Time: {time.time() - start:.2f}s")
```

#### 13.3.1.2 第一步：提取辅助函数

把公共的计时代码移到辅助函数中。这样好一些，但现在你必须调用 `measure(func)` 而不是 `func()`。

```python
def measure(func):
    start = time.time()
    func()
    print(f"Time: {time.time() - start:.2f}s")

measure(login)      # 可行，但改变了函数的调用方式
```

#### 13.3.1.3 第二步：返回包装函数

利用闭包返回一个新函数：它看起来和原函数一样，但在其前后加上了计时逻辑。

```python
def timer(func):
    def wrapper():
        start = time.time()
        func()
        print(f"Time: {time.time() - start:.2f}s")
    return wrapper

login = timer(login)    # 用包装后的版本替换 login
login()                 # 看起来像普通调用，但多了计时
```

#### 13.3.1.4 第三步：使用 `@` 语法

`@` 语法只是 `login = timer(login)` 的一种更简洁的写法。

```python
@timer
def login():
    print("Login logic")
    time.sleep(1)

login()                 # 与第 2 步行为完全相同
```

#### 13.3.1.5 核心优势

装饰器在不修改原函数源代码、也不改变其调用方式的前提下增加功能。

### 13.3.2 装饰器 1.0（基础模板）

```python
def decorator(func):
    def wrapper():
        # 之前：扩展功能
        print("Before function call")
        func()              # 调用原函数
        # 之后：扩展功能
        print("After function call")
    return wrapper

# 手动装饰
def greet():
    print("Hello")

greet = decorator(greet)
greet()

# 语法糖
@decorator
def greet():
    print("Hello")
```

**注意：** 如果包装函数（wrapper）不调用 `func()`，原函数就永远不会执行。有时这是有意为之（例如阻止访问），但通常是一个 bug。

### 13.3.3 装饰器 2.0（支持参数）

```python
import time

def timer(func):
    def wrapper(*args, **kwargs):   # 接受任意参数
        start = time.time()
        result = func(*args, **kwargs)  # 把参数传给原函数
        print(f"Time: {time.time() - start:.2f}s")
        return result
    return wrapper

@timer
def slow_function(n):
    time.sleep(n)
    return "Done"

slow_function(1)            # 测量并打印执行时间
```

### 13.3.4 装饰器最终版（保留返回值）

```python
# 通用装饰器模板
def decorator(func):
    def wrapper(*args, **kwargs):
        # 前处理
        result = func(*args, **kwargs)  # 执行原函数
        # 后处理
        return result                   # 保留返回值
    return wrapper

# 实际例子：登录检查
def require_login(func):
    def wrapper(user, *args, **kwargs):
        if not user.get("logged_in"):
            return "Please login first"
        return func(user, *args, **kwargs)
    return wrapper

@require_login
def view_profile(user):
    return user["profile"]
```

### 13.3.5 用 `functools.wraps` 保留元数据

当你编写装饰器时，包装函数会覆盖原函数的元数据，例如 `__name__` 和 `__doc__`。在包装函数上使用 `@functools.wraps(func)` 可以把这些属性复制回来。

详细说明和示例见 [17.2 使用 `@functools.wraps` 保留元数据](17-functools.md#172-使用-functoolswraps-保留元数据)。

## 13.4 高级装饰器模式

### 13.4.1 装饰器叠加

一个函数可以应用多个装饰器。它们自下而上执行。

```python
@decorator_b
@decorator_a
def my_function():
    pass

# 等价于：
# my_function = decorator_b(decorator_a(my_function))
```

**当多个装饰器转换同一个对象时，顺序很重要。** 离函数最近的装饰器最先执行。例如，要创建一个抽象属性，必须把 `@property` 写在 `@abstractmethod` 上方，因为 `@abstractmethod` 需要包装由 `@property` 返回的 property 对象。

```python
from abc import ABC, abstractmethod

class Vehicle(ABC):
    @property
    @abstractmethod
    def wheels(self):
        pass

class Bicycle(Vehicle):
    @property
    def wheels(self):
        return 2

print(Bicycle().wheels)   # 2
```

如果颠倒顺序（`@abstractmethod` 在 `@property` 上方），那么当 `@abstractmethod` 执行时，该方法还是一个普通函数，最终得到的对象就不是一个 property。

### 13.4.2 带参数的装饰器

带参数的装饰器（parametric decorator）是指自身接受参数的装饰器。因为 `@decorator(arg)` 在函数定义之前就会被执行，所以它必须返回另一个装饰器，再由这个装饰器去包装函数。这就需要额外增加一层工厂。

#### 13.4.2.1 为什么需要带参数的装饰器？

有时你希望装饰器本身是可配置的。例如，你可能想在一处让函数重复执行 3 次，在另一处重复执行 5 次。没有参数的话，你就得为每种情况各写一个装饰器。

#### 13.4.2.2 工厂模式

带参数的装饰器有三层嵌套：

```python
def repeat(times):              # 第一层：接收装饰器参数
    def decorator(func):        # 第二层：接收被包装的函数
        def wrapper(*args, **kwargs):   # 第三层：函数被调用时执行
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator
```

#### 13.4.2.3 示例：重复执行一个函数

```python
@repeat(3)
def greet(name):
    print(f"Hello, {name}!")

greet("Alice")   # 打印 3 次
```

#### 13.4.2.4 处理返回值

这个简单的 `repeat` 实现只返回最后一次调用的结果。对于打印这类只产生副作用的场景没问题，但更早的结果会被丢弃。

```python
import random

@repeat(3)
def roll():
    return random.randint(1, 6)

result = roll()
# result 只保留第 3 次投掷；前两次被丢弃
```

如果需要保留每一次结果，可以在包装函数内用列表收集：

```python
def repeat_all(times):
    def decorator(func):
        def wrapper(*args, **kwargs):
            results = []
            for _ in range(times):
                results.append(func(*args, **kwargs))
            return results
        return wrapper
    return decorator

@repeat_all(3)
def roll():
    return random.randint(1, 6)

print(roll())   # e.g., [4, 1, 6]
```

### 13.4.3 类装饰器

#### 13.4.3.1 什么是类装饰器？

正如函数装饰器接收并返回函数，类装饰器接收并返回类。语法完全相同：

```python
@my_decorator
class MyClass:
    pass

# 等价于：
# MyClass = my_decorator(MyClass)
```

当你想修改类的创建行为、在多个类之间统一强制实施某些规则，或在实例之间共享状态时，类装饰器很有用。

#### 13.4.3.2 示例：单例模式

单例（singleton）确保一个类只有一个实例。装饰器把实例保存在闭包中，后续调用时返回同一个实例。

```python
def singleton(cls):
    instance = {}
    def wrapper(*args, **kwargs):
        if cls not in instance:
            instance[cls] = cls(*args, **kwargs)
        return instance[cls]
    return wrapper

@singleton
class Database:
    def __init__(self):
        print("Connecting...")

db1 = Database()
db2 = Database()
print(db1 is db2)   # True — 同一个实例
```

#### 13.4.3.3 示例：自动注册

类装饰器还可以自动注册类。这一模式在插件系统、命令分发器和工厂注册表中很常见。

```python
registry = {}

def register(cls):
    registry[cls.__name__] = cls
    return cls

@register
class Dog:
    def speak(self):
        return "Woof"

@register
class Cat:
    def speak(self):
        return "Meow"

print(registry)
# {'Dog': <class 'Dog'>, 'Cat': <class 'Cat'>}

animal = registry["Dog"]()
print(animal.speak())   # Woof
```

## 13.5 常见的内置装饰器

### 13.5.1 `@property`

`@property` 把方法变成类似属性的访问器，这样你就可以用点号语法读写它，同时在幕后仍然执行自定义逻辑。

#### 13.5.1.1 为什么使用 `@property`？

如果直接暴露属性，任何人都可以赋给它非法的值：

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

c = Circle(5)
c.radius = -10      # 不报错，但圆不能有负半径
```

你可以添加 getter 和 setter 方法，但这样访问值显得别扭：

```python
print(c.get_radius())   # 不如 c.radius 自然
c.set_radius(10)        # 不如 c.radius = 10 自然
```

`@property` 同时解决了这两个问题：它让你使用简单的点号语法，同时在幕后执行校验或计算。

#### 13.5.1.2 Getter

getter 让你像访问普通属性一样访问一个计算得到或受保护的属性。

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

c = Circle(5)
print(c.radius)     # 5 (调用 getter)
```

#### 13.5.1.3 Setter

使用 `@attr.setter`，在属性被赋值时执行校验或副作用逻辑。

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError("Radius cannot be negative")
        self._radius = value

c = Circle(5)
c.radius = 10       # 调用 setter
print(c.radius)     # 10
```

#### 13.5.1.4 Deleter

使用 `@attr.deleter`，在用 `del` 删除属性时执行清理代码。

```python
class Person:
    def __init__(self, name):
        self._name = name

    @property
    def name(self):
        return self._name

    @name.deleter
    def name(self):
        print("Deleting name...")
        del self._name

p = Person("Alice")
del p.name          # 调用 deleter
```

#### 13.5.1.5 为什么 setter 需要先定义 getter

如果没有先用 `@property` 定义对应的 getter，就无法定义 `@attr.setter`。Python 需要先知道该 property 存在，才能给它挂上 setter 或 deleter。

```python
class BankAccount:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance

    # 正确：balance.setter 跟在 balance.property 之后
    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("Balance cannot be negative")
        self._balance = value

    # 没有先写 @property 会出错：
    # @pin.setter      # AttributeError: 'function' object has no attribute 'setter'
    # def pin(self, value):
    #     self._pin = value
```

**最佳实践：** `@property` getter、`@<name>.setter` 和 `@<name>.deleter` 使用相同的方法名。这样该 property 的行为就像一个真正的属性。

### 13.5.2 `@classmethod`

`@classmethod`（类方法）接收类本身作为第一个参数（`cls`），而不是实例。它常用于创建替代构造函数或工厂方法。

#### 13.5.2.1 为什么使用 `@classmethod`？

有时你需要不止一种方式来创建对象。与其重载 `__init__`，不如用类方法作为工厂。

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_birth_year(cls, name, year):
        """Create a Person from a birth year."""
        return cls(name, 2026 - year)

p = Person.from_birth_year("Alice", 1990)
print(p.name, p.age)   # Alice 36
```

#### 13.5.2.2 继承方面的优势

使用 `cls(...)` 而不是硬编码类名，可以让子类化正常工作。

```python
class Employee(Person):
    pass

e = Employee.from_birth_year("Bob", 1995)
print(type(e))   # <class '__main__.Employee'>
```

如果 `from_birth_year` 使用的是 `Person(...)` 而不是 `cls(...)`，那么 `e` 会是 `Person`，而不是 `Employee`。

### 13.5.3 `@staticmethod`

`@staticmethod`（静态方法）不接收 `self` 或 `cls`。它只是一个放在类命名空间中的普通函数，通常用于与该类相关的工具逻辑。

#### 13.5.3.1 为什么使用 `@staticmethod`？

你完全可以把同样的逻辑写成模块级函数，但把它放在类内表明该函数属于这个类的领域，也让相关代码集中在一起。

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @staticmethod
    def is_adult(age):
        """Check if an age qualifies as an adult."""
        return age >= 18

print(Person.is_adult(20))   # True
print(Person.is_adult(16))   # False
```

#### 13.5.3.2 `@staticmethod` 与模块级函数对比

两者都可行，但静态方法让归属关系更明确：

```python
# 模块级函数
def is_adult(age):
    return age >= 18

# 静态方法：明确隶属于 Person
class Person:
    @staticmethod
    def is_adult(age):
        return age >= 18
```

#### 13.5.3.3 它不仅仅是一个声明

`@staticmethod` 实际上改变了 Python 调用该方法的方式。没有它，调用 `Person.is_adult(20)` 会失败，因为 Python 会尝试把类作为第一个参数传入。

### 13.5.4 `@dataclass`

`@dataclass`（来自 `dataclasses` 模块）为主要用于存储数据的类自动生成 `__init__`、`__repr__`、`__eq__` 等样板方法。

#### 13.5.4.1 为什么使用 `@dataclass`？

没有它，一个简单的数据容器需要写大量重复代码：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
```

使用 `@dataclass`，同样的类变成：

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p1 = Point(1, 2)
p2 = Point(1, 2)

print(p1)        # Point(x=1, y=2)
print(p1 == p2)  # True
```

#### 13.5.4.2 常用选项

| 选项 | 效果 |
|--------|--------|
| `frozen=True` | 实例创建后变为不可变 |
| `order=True` | 生成比较方法（`<`、`<=`、`>`、`>=`） |
| `default=...` | 为字段提供默认值 |
| `field(...)` | 对单个字段进行细粒度控制 |

```python
from dataclasses import dataclass, field

@dataclass(order=True, frozen=True)
class Item:
    name: str
    price: float = 0.0
    tags: list = field(default_factory=list)

items = [Item("Apple", 1.5), Item("Banana", 0.5)]
print(sorted(items))   # 先按名称排序，再按价格
```

**何时使用：** 对于简单的数据容器，使用 `@dataclass`，而不是手写 `__init__`、`__repr__` 和 `__eq__`。

### 13.5.5 `@abstractmethod`

`@abstractmethod`（来自 `abc` 模块）把一个方法标记为必须由子类实现。它主要用于设计类层次结构和接口。

包含至少一个抽象方法的类不能被实例化。子类必须重写所有抽象方法后才能被创建为对象。

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def speak(self):
        pass

class Dog(Animal):
    def speak(self):
        return "Woof"

# animal = Animal()   # TypeError: Can't instantiate abstract class
dog = Dog()
print(dog.speak())    # Woof
```

更多细节和完整的 ABC 工作流程，见 [12.9 抽象基类](12-面向对象编程.md#129-抽象基类)。

## 13.6 实战示例

### 13.6.1 登录检查装饰器

一个常见的实际应用场景：根据登录状态限制函数执行。

```python
def require_login(func):
    """Decorator that checks if user is logged in before executing."""
    def wrapper(is_logged_in, *args, **kwargs):
        if not is_logged_in:
            print("❌ Access denied. Please log in first.")
            return
        return func(is_logged_in, *args, **kwargs)
    return wrapper

@require_login
def view_dashboard(is_logged_in):
    print("📊 Showing dashboard...")

@require_login
def transfer_money(is_logged_in, amount):
    print(f"💰 Transferring ${amount}...")

# Not logged in
view_dashboard(False)       # ❌ Access denied. Please log in first.
transfer_money(False, 100)  # ❌ Access denied. Please log in first.

# Logged in
view_dashboard(True)        # 📊 Showing dashboard...
transfer_money(True, 100)   # 💰 Transferring $100...
```

**关键模式：** 装饰器拦截调用，检查条件，然后要么阻止执行，要么继续调用原函数。这一模式在 Web 框架（Flask、Django）中被广泛用于身份认证和授权。

### 13.6.2 日志装饰器

日志装饰器记录函数调用——对调试和监控很有用。

```python
def log_call(func):
    """Log function name, arguments, and return value."""
    def wrapper(*args, **kwargs):
        print(f"[CALL] {func.__name__} args={args} kwargs={kwargs}")
        result = func(*args, **kwargs)
        print(f"[RETURN] {func.__name__} → {result}")
        return result
    return wrapper

@log_call
def add(a, b):
    return a + b

@log_call
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

add(3, 5)
# [CALL] add args=(3, 5) kwargs={}
# [RETURN] add → 8

greet("Alice", greeting="Hi")
# [CALL] greet args=('Alice',) kwargs={'greeting': 'Hi'}
# [RETURN] greet → Hi, Alice!
```

**实际开发提示：** 在生产环境中，用 Python 的 `logging` 模块这类正式的日志框架替换 `print()`。
